# 门控的退出码口径（`tools/` · 0/1/2/3）

> **一句话**：读 `rc` 之前，先问 **「这个脚本的 `rc` 是判词吗」** —— 本目录有三种角色，**只有"门"的 `rc` 才有意义**。
>
> **为什么有这份文档**：本会话反复在治同一族病 —— **退出码与判词脱钩**（`engineering-lead` `#173` 点名）；另有 **`grep 类名当验收`** 这种"代理量"。这张表把口径固定下来，**免得"看到 `rc=0` 就当通过"**。

---

## 一、先分清角色（★ 读 `rc` 前必看）

| 角色 | `rc` 是判词吗 | 含义 |
|---|---|---|
| **门**（gate） | ✅ **是** | `rc` = 结论。见 §二四码 |
| **报表 / 诊断工具** | ❌ **不是，恒 0** | 只打印数字 / 落盘。**"有没有问题"要看人读表** ⇒ **`rc=0` 不表示通过** |
| **构建 / 服务 / 助手** | ❌ 不是 | `rc` 只报"跑没跑成"，不报"好不好" |

> ★ **本目录目前有两个"名叫 audit、实为报表"的脚本：`ailayout`（`audit:ai`）与 `aidiagnose`（`audit:ai-diag`）** —— 它们**从不设退出码**（源码里没有任何 `process.exit` / `process.exitCode` 作用于结论）⇒ **恒 0**。`npm run audit:ai` 成功**不代表 AI 没问题**，只代表**表打出来了**。

## 二、四码约定

| 码 | 含义 | 落地方式 |
|---|---|---|
| **0** | 全过 | 所有门 |
| **1** | 有 FAIL（**量到了，结论"不过"**） | 所有门 |
| **2** | **前置不满足**（无 Chrome / 构建缺被测对象 / 服务没起）—— **不吐模块解析栈** | 统一入口 `_dist.mjs` 的 `requireFile()`；各门也可自带分支 |
| **3** | **读数不可信**（跑的过程中**被测对象变了**）⇒ **本次结论作废**，**与 1 区分** | 目前仅 `contactaudit`（`#173`） |

> ★ **2 vs 1**：`2` = "这次**没量到**"（环境/前置）；`1` = "**量到了，不过**"（结论）。**把 2 混进 1，会让"环境坏"看起来像"代码坏"。**
> ★ **3 vs 1**：`3` = "量到了，但**量错了对象**" ⇒ **既不该报过、也不该报不过**，**必须重跑**。例：`contactaudit` 跑的中途 `dist` 指纹变了（`94beeb2` / `185ad5b`）。

## 四、三条通用纪律

1. **前置不满足一律 `2`** —— 走 `_dist.mjs` 的 **`requireFile()`**（缺文件即 `2` + 一句"先 `npm run build`"），**不要让它以模块解析栈崩在 `1`**。★ 现状（**2026-11-13 按 npm 脚本重数**；此前"17 道 / 10 走 requireFile"是 2026-10-13 的旧口径，当时按文件数、且门数远少于今天，**别再用那个数**）：**66 道门**里 **54 道 import 了 `_dist.mjs`**，其中 **47 道真的调了 `requireFile()`**；**7 道接了但没调**（`audit:hover` / `audit:touch` / `audit:atlas` / `audit:crest` / `audit:contact` / `audit:scenario` / `audit:androidsync`）；**12 道完全不接**（`audit:score` / `probe:uip0` / `probe:mapshadow` / `probe:terrainedge` / `probe:reachdots` / `probe:pathdots` / `probe:pathday` / `probe:pathflow` / `probe:longlist` / `probe:dayflow` / `probe:objectives` / `probe:hexgeom`）—— 这 12 道是纯 Node 或"自带服务 + 浏览器"，前置靠各自 `exit(2)` / 页面加载超时兜住，**"自带分支是否覆盖全部前置"仍是未核项**（不是已认定的缺陷）。另：**`iaaccept.mjs` 不接 `_dist.mjs` 的服务/指纹胶水**（自带 `--dist=` + `exit(2)`，且默认连外部 5173 ⇒ 见 §五）；2026-11-05 起只为 `READ_SAVE_EXPR` 常量 import 了它。⚠️ **2026-11-19 复核（城景五版批）：§三表实际逐行登记 56 行门** —— **52 行有 npm 脚本**（逐条跑 **255 s，全 rc=0**）+ **4 行标注"无 npm script"**（`grimscontact` / `showcasegate` / `verify-static-map` / `iaaccept`，直接 `node tools/*.mjs`，同样全 0；`iaaccept` 前置见 §五）。⚠️ 批量回归**别用 `npm run` 遍历全表**：那 4 行会以 `npm run "（无 npm script…）"` 报 rc=1，看着像 4 道红门，其实一条都没量到。上面的 66 / 54 / 47 是 2026-11-13 按 npm 脚本重数的**历史口径**，多出来的 16 道是表外 probe/audit（其中 `tp8:blindtest` 是过期素材工具、rc=1，不是门）。批量回归以 §三表这 56 行为判词，别把两个口径混着报。

3. **新增门时自查两句**：**「它会不会红？」「它会不会绿？」** —— 只能红的是**墙**，只能绿的是**假绿**。
   ★ 已被点过名的失效形态：`恒真计数` · `样本自带被测标记` · `空跑即绿` · **`算出失败却 exit 0`** · **`声明了纪律但没实现`** · **`grep 代理量`** · **`计数=0 未带阳性对照`** · **`0 == 0 静默空`** · **`正则被拒被读成无匹配`** · **`毫秒数当布尔用（0 = falsy）`**。
   - ★ 最后一条是 **2026-10-13 `showcasegate` G 组实测**到的：`waitInGame()` 返回的是**毫秒数**，判据写成 `const started = await waitInGame(evaluate)` ⇒ "第一次轮询就命中"= `0` ⇒ falsy ⇒ **假红**。同一份门里 E 组写的是 `waited !== null`（对），G 组漏了 —— **同一条判据两处写法不一致**，而机器快/缓存热时才会触发，冷机永远绿。⇒ **规矩：凡"等待函数返回时长/计数"的，判据必须是 `!== null` / `> 0`，不许直接把返回值塞进 `PASS()`。**
