## 0. 摘要（先给结论）

| | **图一《教学场》** | **图二《对决场》** |
|---|---|---|
| 教什么 | **操作**：移动 / 拾取 / 打第一仗 / 建第一座建筑 | **策略**：发育 vs 进攻；英雄死活的后果 |
| 配置 | 小型 24×24 · 旷野 · **0 对手** · 轻松 | 中型 32×32 · **同心环** · **1 对手** · 普通 |
| 时长目标 | **≤10 分钟**（约 5–7 天） | 20–30 分钟（约 12–18 天） |
| 胜负 | **无胜负**（练习场，看 §2.4 的 3 条清单） | 攻城 / 灭对手英雄 |
| 需要的覆盖项 | 5 项（全是"生成器参数"，**不碰 AI**） | **1 项 AI 行为**（`aiIntent:'rush'`）+ 1 项中线门控 |
| 选定的固定 seed | `247944`（备选 `93604` / `24151`） | `170774`（备选 `139906` / `124472`） |
| 为什么选它 | **1 天可达圈内资源最富**（10 堆资源 + 6 宝箱）+ 木石矿保底 2 座（选法见 §2.5） | 3 项综合最优：主城间距大（2.1 天）+ 门口强怪 **= 0** + 1 天圈内 7 堆资源 |

**两条最重要的设计决定**（理由与代价都在正文）：

1. **不做逐格手绘地图。** 用"固定 `config` + 生成后覆盖项"表达意图。代价：地形细节随种子（不可控但同种子可复现）；收益：零编辑器成本、与程序生成不分叉。
2. **图二的"对手会主动打你"必须靠新增 `aiIntent:'rush'` 实现。**
   实测证据：中型旷野图 **8/8 个种子里，AI 在 21 天内从未进入玩家视野**（`/tmp/contactmeasure.mjs`，跑真实 `endDay`）。
   不解决这条，图二的核心承诺（教"发育 vs 进攻"）**不成立**。**降级方案见 §3.6。**

## 1. 载体：「场景（scenario）」= 固定配置 + 生成后覆盖项

### 1.1 为什么是这个载体

本作没有地图编辑器，`createGame({ size, seed, layout, opponents, difficulty })` 程序生成，**同种子必然同图**。
所以"一张设计好的图"在本作的等价物是：**把一个 config 固定下来，并开放少量"生成后盖章"的钩子**。

> **我明确不建议"逐格手写地图"**（需要地图编辑器 + 全量校验，成本以周计，且会让程序生成与手绘两套逻辑长期并存）。
> **本规格里两张图的全部设计意图，都能用 §1.2 的 8 个覆盖项表达。** 如果工程实现时发现某项表达不了，**请只报那一项**，我再改设计，而不是加编辑器。

### 1.2 `ScenarioDef`（建议新增 `src/core/data/scenarios.ts`）

```ts
/** 试玩场景：固定 config + 生成后覆盖项。 */
interface ScenarioDef {
  id: string; name: string; sub: string;
  config: { size: MapSize; layout: MapLayout; seed: number; opponents: number; difficulty: Difficulty };

  /** ── 生成期覆盖（在现有生成流程内改参数，不是新流程） ── */
  gen?: {
    neutralTowns?: number;          // 覆盖 `neutralCount`（图一 = 0）
    vaults?: number;                // 覆盖 `vaultCount`（图一 = 0）
    chokepointGuards?: boolean;     // 是否执行"隘口守卫"循环（图一 = false）
    monsterCount?: number;          // 覆盖 `max(6, round(18k))`
    monsterTierBand?: { weakMax: number; midMax: number }; // 覆盖 9k / 18k（图一 = 全弱）
  };

  /** ── 生成后盖章（独立 rng，见 §1.3 红线） ── */
  stamp?: {
    midGuard?: { tier: 'mid' | 'strong'; reward: { kind: 'gold'; amount: [number, number] } }; // 图二
  };

  /** ── AI 行为（图二） ── */
  aiIntent?: 'normal' | 'rush';

  /** ── 目标清单：只读 GameState 判定（图一） ── */
  objectives?: { id: string; text: string; check: string }[];
}
```

### 1.3 给工程的改动清单（按"必须/可选"分级）

| # | 位置（符号锚点） | 改动 | 级别 |
|---|---|---|---|
| 1 | 新增 `src/core/data/scenarios.ts` | `SCENARIOS: ScenarioDef[]`（两张图）+ 类型 | 必须 |
| 2 | `StartScreen.ts` 的 `sizeRow` / `layoutRow` 之上 | 加一行「**试玩场景**」（3 个选项：教学场 / 对决场 / 自由对局），选场景时**锁定并置灰** 尺寸/布局/对手/难度/种子几行，并显示场景说明 | 必须 |
| 3 | `generator.ts · createGame()` → `buildGame()` | 读 `cfg.scenario?.gen`，分别覆盖 `neutralCount` / `vaultCount` / 隘口守卫循环 / `monsterCount` / `weakMax`+`midMax` | 必须 |
| 4 | `generator.ts · buildGame()` 末尾 | 执行 `stamp.midGuard`：在**两家主城连线的中点 6 格内**、按**现有隘口评分**取最优空格，放 1 只 `monsterArmy(rng2, tier, diff.monsterMul)` + 奖励 | 必须（图二） |
| 5 | `ai.ts · pickTarget()` | `aiIntent === 'rush'` 且 **尚未见过任何玩家资产**（`!hasSeenAnyAssetOf(...)`：英雄/城/矿任一处）时，把**朝玩家方向、`aiMarch` 真会走且路径不穿战斗格的最远路点**（`waypoint`，`kind:'loot'`）作为一个**候选**加入候选表 —— **不覆盖其它候选、不绕过 `seen()`** | 必须（图二） |
| 6 | `persistence.ts` | `config` 里多一个可选 `scenario?: string`（**存档结构只多一个可选字段，`VERSION` 不动**，与 difficulty 那次同一判断） | 必须 |
| 7 | UI：教学清单（图一 `objectives`） | 3 行只读勾选（读 `state` 即可，见 §2.4）。**UX 规格归 ux-ia** | 可选（图一很好用，但不阻塞） |

> ### 📌 与"我的初稿"的差异（**均已采纳实现**，2026-09-21 复核）
> 1. **第 5 项（`rush` 目标）—— 实现迭代过两次**：
>    - 初稿：我写「朝主城方向的**最短路下一格**」⇒ **不可用**（`aiMarch` 一次性用掉当天移动力；只给"下一格"就变成一天挪 1 格）。
>    - 一版：以**玩家主城远点**为目标 ⇒ **会永久卡死**（`aiMarch` 的 repath **忽略物件**，会撞上一只打不过的野怪后停住；实测 seed `1000` 卡在 (27,12)、被 (27,11) 的怪挡住，**第 5 天停到第 21 天**）。
>    - **现行**：取**朝玩家方向、`aiMarch` 真会走、且路径不穿战斗格的最远路点**（`waypoint`）⇒ **既保持推进速度，又不会卡死**。
>    - 权重 `RUSH_BIAS` 随实测调过 **210 → 450 → 600**（**`#119` 定稿 = 600**，理由见 §3.5）。
> 2. **第 4 项（中线门控搜索半径）**：我原写「中点 **6 格**内」；实现 `mid ± 8`（16×16 搜索框）+ 评分扣 `-(|dx|+|dy|)` 偏离 ⇒ **最优格仍落在中点附近，效果等价**。
>
> **均按 D-49（代码/决策优先于规格）改本表。** 复核同时确认实现兑现了批准时挂的条件：① `hasSeenAnyAssetOf` 覆盖**英雄 / 城 / 矿**三处 = 规格说的"任何玩家资产"；② 它只是**候选**（沿用同一评分），**不覆盖**其它候选；③ 盖章用**独立 rng**（`mulberry32(seed ^ 0x9e3779b9)`），不扰动主 `rng`；④ 找不到合适格**宁缺勿错**（不退化到随机点，同 §6.2 风险③）。

> ### ⚠️ 红线（与 `monsterArmy` 的 `monsterMul` 是同一条纪律）
> **覆盖项必须"不改变已有 `rng` 的调用次数与顺序"。**
> 自由改动参数（#3）天然满足；**只有 `stamp.midGuard`（#4）会新增一次生成** ⇒ **必须用独立 rng 流**（`mulberry32(seed ^ 0x9e3779b9)` 之类），**绝不能接着用主 `rng`**。
> 否则：同种子生成的地形/城镇/野怪会整体错位 —— 玩家拿旧种子复现不出同一张图，"同种子同图"这条对玩家的承诺就破了。

### 1.4 复杂度与风险

| 项 | 评估 |
|---|---|
| 纯工程量 | #1–#4、#6：**均为小改动**（都是"读一个可选配置，分支跳过/覆盖"）；#5 需要在 `pickTarget` 加一个候选分支，**是本清单里唯一有行为风险的一项** |
| 对既有玩法的影响 | 默认无 `scenario` 时**所有分支都不走** ⇒ 自由对局与今天**逐字节一致**（与 difficulty 重设计同一原则：**零改动回滚底线**） |
| 验证成本 | 每张图跑 8 seeds（§4），并重跑 `audit:layout` / `audit:mines` / `audit:ai` 确认未回归 |

## 2. 图一《教学场》

**口号**：*"先学会走路，再学会挨打。"*（无对手 —— 这一版只教操作，不教对抗）

### 2.1 配置

| 项 | 取值 | 理由 |
|---|---|---|
| 尺寸 | **小型 24×24** | 教学只要"3–4 场必赢的仗 + 两条拾取路线"。**一天能横穿全图**（1800 ÷ 100~150 ≈ 12–18 格）在教学中是**优点**：不会迷路、不会资源枯竭、10 分钟走得完 |
| 布局 | **旷野 wild** | 特殊地形（护城河/海峡）是"第二个要学的东西"，教学图不该同时教两件事 |
| 对手 | **0** | 教学期不允许"被别人打"。**这正是难度系统重设计（D-20）的价值：`opponents: 0` 时难度依然生效**（走 `playerStartMul` 等 4 根玩家侧杠杆） |
| 难度 | **轻松 easy** | 开局 3000/12/12 ⇒ **D1 就能建成兵营（2500 金 / 10 矿）**，教学图给正反馈越早越好 |
| seed | **247944**（备选 `93604`、`24151`） | 见 §2.5 的筛法 |
| 时长 | **≤10 分钟**（5–7 天） | 用户对图一的明确要求 |

### 2.2 覆盖项（5 项，全部为生成器参数，**不碰 AI**）

| 覆盖 | 值 | 为什么必须 |
|---|---|---|
| `neutralTowns` | **0** | 当前生成器**保底 2 座**中立城（`Math.max(2, …)`）。教学图不要"抢城"这个变量 |
| `vaults` | **0** | 宝库是"高风险高回报"，属**图二**的教学内容；且**它连带产生 3 只强档隘口守卫**（见下条） |
| `chokepointGuards` | **false** | 实测：小图/中图上**强档野怪 unavoidable 地贴近主城**（小图 1.5 天圈内 4–13 只），根因是隘口守卫那条"守卫必须比目标更靠近主城"的规则 ⇒ 教学图必须关掉它 |
| `monsterTierBand` | `{ weakMax: 1e9, midMax: 1e9 }` | 全图**只有弱怪**（野狼 20–28）。教学期不出现"打不过"的仗 |
| `monsterCount` | **5** | 当前公式 `max(6, 18k)`，小图 k≈0.56 → 约 10 只。**降到 5 只**给教学留呼吸空间（2200 格以上才有一只怪） |

**预期结果**：选定种子 `247944` 在覆盖前，玩家主城 1.5 天可达圈内有 **11 只怪**（含中/强档）；五条覆盖项生效后 ⇒ **全图只剩 5 只弱怪**，其中落在家门口的约 **2–3 只**。（怪数由 `monsterCount` 覆盖项决定，不由种子决定 —— 见 §2.5 的更正。）

### 2.3 地形布局意图（**非逐格**）

```
   24×24 旷野 · 固定 seed · 示意（仅教学动线，不代表真实坐标）
   ┌────────────────────────────┐
   │   Ⓜ木   ·   Ⓜ石              │  Ⓜ = 锯木场/采石场（3~7 格，无守卫，
   │      ╲   ╱                  │      generator 已保底 —— E1/E3 不许动）
   │   ┌── @P ──┐    ⚔狼①        │  @P = 玩家主城（含 tavern/dwell1/dwell2）
   │   │  （西侧）│      ⚔狼②     │  ⚔ = 野狼（覆盖后全图脆弱；带金/木石战利品）
   │   └──┬──────┘        ⚔狼③    │  💰 = 资源堆 / 💎 = 宝箱（拾取教学）
   │      │          💰  💰  💎   │
   │   💰 │  💎   💰              │  三条"出门路线"，每条 1 只狼 + 2~3 堆资源
   │      │       💰  💎  💰      │  → 玩家任选一条都不会空手而归
   └────────────────────────────┘
```

**意图**：从主城向外伸出**三条"教学走廊"**，每条给"1 场必赢的仗 + 2~3 堆资源"。
不需要"必经之路"（教学图不需要门控），**需要的是"每条路都有正反馈"**。

### 2.4 一局流程（逐阶段）· 目标 ≤10 分钟

| 阶段 | 玩家动作 | 出现的新概念 | 为什么这样排 |
|---|---|---|---|
| **① 第 1 天·出门** | 点地图走 3–5 格，迷雾揭开 | 点击移动 / 寻路 / 迷雾 | 第一个动作必须是"**立刻有反应**"的，不能先读文字 |
| **② 第 1 天·捡** | 走到资源堆上自动拾取（💰 500–1500 金） | 拾取 / 资源种类 | 零风险正反馈 |
| **③ 第 1–2 天·第一仗** | 打野狼（20–28 只，弱档） | 战斗界面 / **战前预览** / 远程先射 | 弱档是"稳赢小亏"，教会"打仗要掉兵"但不挫败 |
| **④ 第 2 天·回城** | 回主城，建**兵营（2500 金 / 10 矿）** | 建造树 / 招募 | 轻松档 3000 金正好够（`difficulty-spec §5` 的锚点），**当天就有成就感** |
| **⑤ 第 3–4 天** | 再清 1–2 只狼、占锯木场/采石场 | 占矿 / 每日产出 | "资源会持续来"这个概念 |
| **⑥ 第 5–7 天·收尾** | 招募一队新兵走出门 → 三堆资源 + 三只狼打完 | 编队 / 回头补 | 循环闭合：**打 → 捡 → 建 → 更强 → 再打** |

**3 条"学会了吗"清单**（`objectives`，**全部读现有 `state`，零新系统**）：

| # | 文案 | 判定（**精确表达式，已核源码**） |
|---|---|---|
| ① | 「你已经会走路了」 | `state.players.p1.revealed.reduce((n,v)=>n+(v===1?1:0),0) >= 140` |
| ② | 「你打赢了第一仗」 | `(state.heroes['hero1']?.exp ?? 0) > 0` |
| ③ | 「你有自己的矿了」 | `ownedMines(state, 'p1').length >= 2`（**复用 `town.ts` 已有的导出函数**，别在 UI 里再写一遍 filter） |

三条全勾 ⇒ 弹一句「**你学会了。下一张图有人会来打你。**」并给"去对决场"的按钮。

> **③ 阈值 2 已锁定（2026-09-21 实测 · ux-ia 交接）**：图一 seed `247944` 从英雄起点算，**最近的矿是锯木场（cost 480）与采石场（cost 640）**，都 ≤ 0.32 天（英雄 **2070 移动点/天**）⇒ 2 座矿**第 1 天就够得着**；且**开局 `ownedMines(p1)=0`**（实测）⇒ 判据**既可达、又能被"还没做"的状态 falsify**（不是开局即真的假守卫，同 ① 的坑）。取 **2** 是因为它正好对应 §2.4 阶段⑤「占锯木场/采石场」的动作数；**取 3 会逼玩家多跑一趟，破 ≤10 分钟预算。**

> ### ⚠️ ① 的阈值必须写 140，不能写 60 —— 两处踩坑记录（2026-09-21，实测）
> **坑 1：`revealed.length` 不是"已揭开格数"。** `revealed` 是 `number[]`，**长度恒等于地图总格数**（小型 24×24 = **576**）。
> ⇒ 用 `.length >= 60` 判定，**第 1 帧就成立**（576 ≥ 60），玩家一步没走就"学会走路"了。
> **坑 2：即使改成"数 `===1` 的格数"，阈值 60 也已经被开局自带视野吃掉了。** 实测开局揭雾格数：
>
> | 种子 | 开局已揭开 | 占全图 |
> |---|---|---|
> | `247944`（图一选用） | **82** | 14.2% |
> | `93604` | 73 | 12.7% |
> | `24151` | 66 | 11.5% |
> | `1000` | 83 | 14.4% |
>
> （原因：`createGame` 末尾对主城揭 4 格半径 + 英雄揭 `HERO_SIGHT = 5` 半径，两个圆并集就有 66~83 格。）
> ⇒ **阈值必须显著高于开局值**：取 **140**（约为全图 24%，即在开局基础上再走揭 ~58 格 ≈ 3~4 步）—— 既能被 3~4 步达成，又不可能"开局即完成"。
> **本条的教训与项目其它教训同形**：*判据必须能被"还没做"的状态 falsify*；一个开局就为真的判据是**假守卫**。

> ### ⚠️ 两条实现约束（由 ux-ia 复核提出，采纳）
> 1. **必须"锁存"（latch）**：三条一旦达成即**保持为真**，不是每帧实时重算。
>    理由：② 依赖 `state.heroes['hero1']`，而**英雄阵亡后该键会消失** ⇒ 不锁存的话清单会**倒退**（3/3 掉回 2/3）。
>    教学场是"全弱怪 + 0 对手"，英雄阵亡概率极低，但**锁存才是正确形态**（这也解释了为什么它属于"目标"而不是"读数"）。
> 2. **设备画质档的尺寸上限**：`MAP_SIZES` 与 `quality.maxMapSize` 是两套数（24/32 vs 32/40/48）。
>    本方案两张图是 **24 与 32**，在**三档画质全部 ≤ cap** ⇒ 两卡都可选。
>    **红线**：将来若把某个场景改成 `large/huge`，**该卡必须在低画质档禁用** —— 否则 `clampMapSize` 会**静默改尺寸**，破掉"固定 config"的承诺（玩家会以为在玩教学场，实际拿到的是别的尺寸的图）。

### 2.5 选种子的筛法（可复跑）


> #### ⚠️ 作废判据 = **被测对象自己的指纹**，**不是** `git status`（2026-09-21 主理人裁定）

| **A3** | **覆盖项没有改变已有 `rng` 序列** | 只在"关掉/改参数 + 独立 rng 盖章"范围内 ⇒ 用 A2 即可反证 |
| **A4** | 图一的 6 条 V1–V6、图二的接触日对照组 | §2.6 / §3.5 |
| **A5** | 未回归：`audit:layout`（48 局全过）、`audit:mines`、`audit:ai`、`smoke` 556-0 | 已有门控 |
| **A6** | 存档：旧档（`VERSION = 7`）仍能 `loadGame()`；新档多一个可选 `scenario` 字段不涨版本 | 手工构造旧档 |

## 5. 与既有文档的关系（**不装作没写过**）

`design/gdd/maps.md`（我此前写的示例图文档）里已有两张图：《启程》（中型教学图，**1 个对手**）与《四族会猎》（巨型同心环 4 方）。
**本次的两张"试玩场"与它们不是一回事，关系如下：**

| | `gdd/maps.md`《启程》/《四族会猎》 | **本次《教学场》/《对决场》** |
|---|---|---|
| 目的 | **发布级示例图**（可攻略、可分享、完整剧本） | **试玩场**（只验证"可玩性到底上不上得来"） |
| 依赖 | **需要"地图脚本/事件系统"**（§0 的 `ScriptRunner` + toast，工程量以周计） | **不需要任何事件系统** —— 只用生成器覆盖项 |
| 教学图对手 | 1 个 | **0 个**（先只教操作） |
| 时长 | 25–40 分钟 / 60–90 分钟 | 10 分钟 / 20–30 分钟 |

**⇒ 建议的推进顺序（我的判断，供你拍板）**：
**先做本次两张试玩场（零新系统、一周内能上人试玩，直接回答用户"可玩性上不上得来"），
再决定要不要投入事件系统去做《启程》《四族会猎》。**
理由是用户此刻要的是"**哪怕只在这两个地图上让可玩性上来**" —— 那是**验证**，不是**出品**。
`gdd/maps.md` 的 §0（事件系统）与 §3.3（`MapDef` schema）**建议维持原样、暂不实现**；其中"固定 seed + 覆盖项"这一层已被本文吸收。

## 6. 已知取舍、风险与"我改动了什么说法"

### 6.1 我主动推翻的两处既有说法

| 谁 | 原说法 | 现结论 | 依据 |
|---|---|---|---|
| `difficulty-spec.md §6`（我的文档） | 「中型图…**探索期约 7–10 天后接触**」 | **错**：几何上界 **1.7 天**（同心环 3.0）；且实测 AI 常在 21 天内根本不接近 | `/tmp/measure3.mjs`、`/tmp/contactmeasure.mjs`（D-49：代码优先于规格）。**§6 已更正** |
| `gdd/maps.md §1.1`（我的文档） | 图一《启程》用**中型 + 1 对手**做教学 | **试玩阶段建议改为小型 + 0 对手**：中型图上"对手不来"（实测），而"教操作"不需要对手 | §3.5 实测 + 用户对图一的明确要求（"无对手、教操作"） |

### 6.2 风险

| 风险 | 等级 | 处置 |
|---|---|---|
| `aiIntent:'rush'` 让 AI 变得"作弊感"（它知道你大概在哪个方向） | **中** | 只在"**尚未见过任何玩家资产**"之前生效，且**目标本身仍要过 `seen()`**；文案上把对手写成"**来侦察/来找你**"（剧本化 AI 在 HOMM3 campaign 里是标准做法）。**主理人已批准（2026-09-21，见 §3.5 裁定块）**；**用户侧口径**在试玩中核 —— 引 `design/ux/playtest-feedback.md` 的条目号，别引转述 |
| 覆盖项太多 ⇒ 场景与自由对局分叉成两套体验 | 中 | 只有 5+1 项，且**全是"减法/参数"**，不引入新机制；A1 兜底（自由对局零变化） |
| 选中线守卫位置依赖"隘口评分"在 ring 布局上的表现 | 低 | ring 是"护城河 + 渡口"，走廊格密度高 ⇒ 评分应有效；**实测若找不到合适格，退化为"连线中点上最窄的一格"** |
| 图一 10 分钟可能偏长（六个阶段） | 中 | 若实测 >12 分钟：`monsterCount` 5→4、`objectives` ③ 的矿数 2→1 |
| **个别种子地形隔断**（**历史，已消解**）：`RUSH_BIAS=450` 下 seed `1000` / `39585` 不接触（6-of-8） | 低 | **已由 #119（450→600）消解**：**600 复跑实测 8/8 全接触**（`39585` = 第 **4** 天）。⇒ 该例外**不再成立**，此条只作历史保留。*（对照组的 7/8 不接触是**预期**行为，不是缺陷。）* |
