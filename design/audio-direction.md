## 1. 音乐基调

### 方向 A · 庄重芯片进行曲（Straight Solemn Chiptune）
HOMM3 味道的小调合成进行曲：慢速 4/4、低音三角波持续音（drone）、方波"铜管"和弦、庄严的旋律线。
- 优点：最贴合"骑士外壳"，合成器音色与程序化像素美术同源。
- 风险：**太直**，完全没有承载"荒诞内里"，等于放弃了任务的半边要求。

### 方向 B · 庄重仪式 + 死面孔的荒诞装饰音（**推荐**）
一段**真正庄重**的合成仪式主题（低音持续音 + 缓慢方波和声 + 行进感旋律），但每隔约 40 秒被一个**极其克制、毫无反应的荒诞小动机**刺穿——比如一声像橡皮鸭自报家门的短促滑音"哔哇"、或一只鸡的"咯"被渲染成半音下滑的 blip。音乐**对荒诞动机既不惊讶也不接话**，继续庄严前行。
- 为什么匹配调性：这**精确镜像**了喜剧布景层的设计原则——`cartoon-style.md §6.1.1` 说"在一个认真的世界里放几件明显不属于它、且没有任何人负责的小东西，笑点来自世界假装没看见"。方向 B 把这条原则**直接写进音乐结构**：严肃的谱面 + 世界拒不回应的荒诞入侵。喜剧是**结构性的**，不是喧闹的。
- 可行性：荒诞"错音"动机在合成器里比在录制音乐里**更容易**做（一个 detune 的方波 + 音高滑移即可），反而成为程序化路线的加分项。

### 方向 C · 酒馆民谣戏仿（Tavern Pastiche）
欢快大调、鲁特琴式拨奏 + 滑稽配器。
- 风险：太"搞笑"，摧毁庄重外壳，读起来是**恶搞**而非"假装没看见"，与 §6.1.1 第 1 条"直才是笑点的支点"相悖。

**推荐：方向 B。** 它是唯一同时满足"撑住庄重外壳"和"用结构性反差承载荒诞"的路线，且最契合项目"程序化像素 + 零资产"的本体。

## 2. 曲目清单

所有曲目用同一套 WebAudio 音序引擎生成；循环点必须**小节对齐、无缝**；均受静音与生命周期挂起约束。

| # | 曲目 | 场景 | 时长 / 循环 | 要求 |
|---|---|---|---|---|
| 1 | `menu` 主菜单 | 标题/主菜单 | ~2:30 无缝循环 | **方向 B 的最佳载体**：庄严进行曲 + 每 ~40 s 一个死面孔荒诞动机。优先级 #1（见 §5） |
| 2 | `map` 冒险地图 | 大地图巡航 | ~2:30 无缝循环 | 比 menu 弱一档强度，给环境音层留 headroom；接 `lightLayer` 昼夜：夜间版降亮色、加冷色和声 |
| 3 | `town` 城镇/城堡 | 城镇面板 | ~1:30 无缝循环 | 更温暖、更"家常"；荒诞动机（晾衣绳母题）出现更频繁 |
| 4 | `battle` 战斗 | 战斗场 | ~1:30 无缝循环 | 提速至 110–130 BPM、驱动感；荒诞动机变成"战斗啾鸣" |
| 5 | `win` 胜利 | 战斗胜利 | ~0:20  sting + ~0:45 收尾循环 | 复用 `sfx.win` 动机并展开（C-E-G 上行） |
| 6 | `lose` 失败 | 撤退/战败 | ~0:25 sting | 复用 `sfx.lose` 动机，更慢、更"泄气"（下滑音） |
| 7 | `day` 新的一天（可选） | 回合更替 | 短 sting | 复用 `sfx.day` 即可，不必新做 |
| 8 | `event` 事件提示（可选） | 对话/任务弹窗 | 短 sting | 后续增补，不在首期 |

> 注：`win`/`lose`/`day` 直接复用现有 `sfx.ts` 的动机，零新增成本，且与 UI 反馈一致。

## 3. 环境音层（Ambience）

连续铺底、低增益、在 BGM 之下 **duck**（自动让位）。按相机下地形/当前画面分层叠加，全部由确定性噪声+振荡器合成（零文件）。

| 层 | 合成方式 | 触发/范围 |
|---|---|---|
| 森林 `forest` | 带通噪声风声 + 偶发确定性鸟鸣（由时间种子决定，非随机） | 森林地形格在视野内 |
| 水边 `water` | 棕/粉噪声低通 = 潮声，缓慢 LFO 调幅 | 海岸/河岸格在视野内 |
| 城镇 `town` | 低频滤波噪声"人声嗡鸣" + 稀疏确定性叮当（炊具声、**大鹅 honk！**） | 城镇/城堡 footprint 附近 |
| 地下 `underground` | ~50–60 Hz 正弦低频隆隆 + 偶发水滴（短噪声 ping） | 地下地形 |

**与现有 UI 音效不打架的原则**：
- 环境音是"床"（持续、低增益、慢变化），UI 音效是"点"（瞬态、高增益、抢注意力）。两者频域与动态域天然错开。
- 通过**独立总线 + 独立增益**（见 §4）实现：环境音总线增益 ~0.10，远低于 sfx 的 0.18，且提供**独立的环境音开关**（静音环境音的玩家仍应保留 UI 点击声）。

## 4. 技术实现策略（最关键）

### 4.1 路线结论：**继续程序化（WebAudio 合成），不引入音频文件（首期）**

**核心理由（按权重排序）**：

1. **保住项目唯一真优势**。本作 APK ~4.8 MB、web ~0.5 MB，对比商业手游 100 MB–2 GB，靠的就是"零外部资产、运行时全程序化"。引入音频文件会直接击穿这条护城河——见 §4.3 的体积测算，6 段 BGM 文件化将把包体翻 2–3 倍。
2. **地基已就绪**。音频上下文、手势解锁、静音、`suspendAudio/resumeAudio` 后台挂起**已全部实现并接线**（§0），程序化路线只需在其上叠加音序引擎，改动最小、风险最低。
3. **音色与本体契合**。合成器声天然匹配"程序化像素 + 荒诞反差"的美术；方向 B 的"错音"荒诞动机在合成器里比录制音乐里更好做。
4. **离线即正义**。无文件 = 无加载 = 天然满足 Capacitor 离线可玩，强化 App Store 4.2（"非网页内容形态"）防御。

### 4.2 程序化能做到"像样的旋律"吗？——诚实评估

**能，但有明确边界。**

- **能做到**：可辨识的旋律、和声进行、对位（counterpoint）、力度起伏（ADSR）、无缝循环、以及方向 B 关键的"庄严谱面 + 荒诞入侵"结构——这些全部靠振荡器 + 包络 + 前瞻调度器（lookahead scheduler）即可实现。
- **做不到 / 有代价**：
  - **音色是"合成器"而非真实乐器**（正弦/三角/方波/锯齿 + 滤波噪声）。你不会得到弦乐群或真实铜管，得到的是 chiptune / Fairlight 味道的声底。对像素游戏**可接受且协调**，但不是电影感管弦乐。
  - **混音/母带是业余级**。没有真实作曲/混音师打磨，动态平衡、空间感、频段干净度会明显弱于一份专业音频文件。
  - **无连奏/真实演奏法**（legato、颤音弓法等）。
  - **实时 CPU 成本**：多振荡器 + 滤波 + 包络，复杂编排下每帧有一定合成开销；但音乐/环境音远低于渲染层（光照三连 ~8.9 Mpx/帧，§M-03），量级可忽略。

**结论**：程序化给出的不是"电影原声"，而是"有性格、能记住、且荒诞得恰到好处的小调合成谱"——对一个反差幽默的像素策略游戏，这**恰好够用且风格自洽**。不要为了"听起来像管弦乐"而误判为不可行；也不要为了省事说"完全可以取代真实配乐"。

### 4.3 若未来引入文件（仅作后续可选方案，非首期）

| 维度 | 评估 |
|---|---|
| 体积预算 | 压缩 OGG ~1 MB/分钟。6 段 BGM（menu 2.5 + map 2.5 + town 1.5 + battle 1.5 ≈ 8 min）≈ **8 MB 原始**，会比当前 APK（4.8 MB）**翻 ~2–3 倍**，直接毁掉"sub-15 MB 商店下载"卖点。**首期不可接受。** |
| 格式 | Android/WebView：OGG/Vorbis 优（更小）；iOS WebView 对 OGG 支持不稳 → 需 **AAC/.m4a 或 MP3 兜底双份**。这是文件化最大的隐性成本。 |
| 离线/预加载 | 必须随 Capacitor 包内（SW 在原生壳不生效，见 `mobile-platform.md §2.8`）；菜单曲预载，其余惰性加载。增加"加载态"复杂度。 |
| 建议形态 | 仅作为**后续可选的"HD 音乐包"**（独立下载、不进基础 APK），且只替换 hero 时刻：**menu + victory 两段 ≈ 3–4 MB**。基础游戏永远零音频文件。 |

### 4.4 程序化路线的工程骨架（供下一步实现参考）

```
AudioContext (已存在, 手势后懒创建)
  └─ master gain (0.18, 已存在, 受 homm.mute 控制)
       ├─ sfxBus   (0.18)  ← 现有 10 种 UI 音效，绝不改动
       ├─ musicBus (~0.14) ← 新增 MusicEngine
       └─ ambBus   (~0.10) ← 新增 AmbienceEngine (可独立开关)
```

- **复用同一 `AudioContext` 与同一套 `suspendAudio/resumeAudio`**：MusicEngine / AmbienceEngine 不自建上下文，从 `sfx.ts` 取 ctx 与总线（新增 `getCtx()` / `getBus('music'|'amb')` 导出）。
- **前瞻调度器**（Web Audio "A Tale of Two Clocks" 模式）：用 `ctx.currentTime` 排程音符，**不**用 wall-clock；挂起时停止排程，恢复时从 `ctx.currentTime` 续排，**消除后台漂移爆音**。
- **静音语义**：`homm.mute` 仍静全部；新增 `homm.music` / `homm.amb` 两个 localStorage 开关，分别控 musicBus / ambBus 增益（沿用现有模式，不改总开关逻辑）。

## 5. 优先级：如果只能先做一件事

**先做 `menu` 主菜单主题（方向 B 的完整实现）。**

理由（按决策权重）：
1. **建立调性承诺的最强单一触点**：玩家进游戏前 10 秒听到的"庄严进行曲 + 死面孔荒诞动机"，是把"庄重外壳 + 荒诞内里"这个命题**立住**效率最高的地方——比任何地图布景都更早教育用户"这游戏是认真的，但它在跟你眨眼睛"。
2. **风险最低、可见度最高**：一段循环、零玩法耦合，端到端验证"合成器音序引擎"是否成立，且**直接回答 §4.2 的悬念**——程序化到底能不能撑住调性？做完 menu 就知道了，再决定要不要铺满 track list。
3. **复用同一引擎**：map/town/battle/win/lose 只是换谱面与参数，引擎一次建好全员受益。

## 6. 与现有 `sfx.ts` 共存（不推翻、只衔接）

| 原则 | 做法 |
|---|---|
| **不动现有 10 种 UI 音效** | `sfx.click()…sfx.error()` 函数与调用点**一律不改**；它们继续走 `sfxBus`，行为不变。 |
| **共享上下文与生命周期** | 新增 `MusicEngine` / `AmbienceEngine` 复用 `sfx.ts` 的 `AudioContext`，通过新增导出的 `getCtx()` / `getBus()` 取得；统一受 `suspendAudio/resumeAudio` 管控（已接线 lifecycle）。 |
| **分层增益** | 在现有 `master`（0.18）下新增 `musicBus`/`ambBus` 子总线（§4.4）。`sfx.ts` 现有 `master`/`setMuted` 逻辑保持；新增音乐/环境音独立音量与开关，沿用 `localStorage` 模式。 |
| **复用动机** | `win`/`lose`/`day` 直接调用/展开现有 `sfx.win/lose/day` 动机，避免重复定义、保证 UI 与过场一致。 |
| **最小改动面** | 仅向 `sfx.ts` 增加 2–3 个导出（`getCtx`、`getBus`、`maybeSetMusicMuted`），**不修改**任何既有的 `tone/noise/sfx` 实现。 |

## 7. 移动端硬约束的落实清单

| 约束 | 落实 |
|---|---|
| 手机扬声器 | 旋律留中音区、避免低频泥浆；musicBus 增益 ~0.14 < sfx 0.18，保证 UI 反馈始终清晰可辨；音乐/环境音提供**独立于 SFX** 的音量/开关。 |
| 横屏 | 音频与朝向无关；但首次发声的手势解锁在横屏 tap 上天然成立（沿用现有 `ac()` 逻辑）。 |
| 用户可能静音 | 尊重 `homm.mute`；音乐/环境音独立开关，避免"静音玩家连点击声也丢了"的反直觉。 |
| 后台暂停 | 直接复用 `lifecycle.ts` 已接线的 `suspendAudio/resumeAudio`；MusicEngine 调度器监听挂起/恢复，**不在 suspended 上下文排程**，恢复后从 `ctx.currentTime` 续排，防爆音（与 `mobile-platform.md §5.4` 同源考量）。 |
| 完全离线 | 程序化 = 零资产加载 = 离线天然成立，强化 App Store 4.2 防御。 |

## 8. 可执行的下一步（非泛泛方向）

**Phase 0 任务（单文件、低风险、端到端验证方向 B）：**

1. **`src/audio/buses.ts`**（新建，~30 行）：从 `sfx.ts` 导出 `getCtx()` / `getBus('music'|'amb')`，建立 `master → {sfxBus, musicBus, ambBus}` 子总线；新增 `homm.music` / `homm.amb` 开关。
2. **`src/audio/music-engine.ts`**（新建）：前瞻调度器（lookahead，"Two Clocks" 模式），`playMenuTheme()` 播放一段**硬编码的方向 B 旋律**（音符以 `[freq, startBeat, dur]` + ADSR 包络表示）无缝循环；`suspend()/resume()` 钩子接 `suspendAudio/resumeAudio`。
3. **只交付 menu 一段**；map/town/battle/win/lose 先留 stub（同引擎、换谱面即可）。
4. **真机验证**：在 Android 内测 APK 上听 menu 主题，确认 (a) 调性是否立住、(b) 程序化音色是否可接受、(c) 后台挂起/恢复无爆音、(d) 静音/独立开关生效。

Phase 0 完成后，再据实测决定是否：铺满 track list（Phase 1）、加环境音层（Phase 2）、或评估"HD 音乐包"文件化（§4.3，仅限 menu+victory）。
