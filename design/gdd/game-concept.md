## 1. 两大支柱

| 支柱 | 一句话 | 它否决什么 | 意图层投影 |
|---|---|---|---|
| **探索** | **「用腿换信息」** —— 每一格行军都要换回点什么（视野 / 资源 / 对手位置） | 否决「面板、弹窗、提示条可以挡住地图」 | I1 / I2 |
| **经营** | **「用信息换兵力」** —— 每一次回城都要把看到的东西变成能带出门的东西 | 否决「经营入口可以埋在探索的从属区块里」 | **I6「回城把事办了」** |

**两条支柱句同构**（互为输入输出：探索产出信息，经营把信息变成兵力）。这不是修辞——**措辞同构是"并列"不制造主次的保证**：若一条写成战略句、另一条写成功能句，文档读起来就自动分了主次。

### 1.1 D-32 并列原则

**探索与经营并列，各为一等公民，二者都是「主场景」。**

- 地图是探索的一等面，城镇是经营的一等面。
- 两个面按**同一套纪律**办："最小常驻 + 按需可达"。
- **谁都不许降级成对方的附属**（对应 `ux/in-game-ia.md` 的规则 **R9**）。
- 共用的常驻元素、共享时钟（日期）、拇指带入口组等**具体落法不写在本档**，见 `ux/in-game-ia.md` §1 / §3.0。

> 一句话选题：**地图是探索的一等面，城镇是经营的一等面——两个面谁都不许降级成对方的附属。**

## 2. ★ 支柱判定：哪两个是支柱，哪两个不是

### 2.1 判据（三条全中才算支柱）

| 判据 | 含义 |
|---|---|
| **P1 独立否决权** | 能**单独**否决一整类方案。只是"最好也考虑一下"的不算。 |
| **P2 自闭环** | 它产出 / 消费的对象**不靠别的支柱施舍**，能自己构成一段闭环。 |
| **P3 全局代价** | 改它要**重排多个系统**，而不是调一个数值。 |

### 2.2 逐候选判定

| 候选 | P1 独立否决权 | P2 自闭环 | P3 全局代价 | 判定 |
|---|---|---|---|---|
| **探索** | ✅ 否决"面板可以挡住地图"（R1/R5 由此推出） | ✅ 产出信息与资源 | ✅ 牵动地图、迷雾、路径、移动力、地图生成 | **支柱** |
| **经营** | ✅ 否决"经营入口可以埋进英雄面板末尾"（R9 / 入口 #49 由此推出） | ✅ 消费信息、产出兵力 | ✅ 牵动建筑树、招募、市场、资源与周增长 | **支柱** |
| 战斗 | ❌ 只能否决"战斗界面好不好看"——属**体验规范级**，不是全局裁决 | ❌ 参数**全部由别人给定**：带什么兵（探索产出）、招什么兵（经营产出）、在哪打（探索决定） | — | **支撑性时刻（继承者）** |
| 回合推进 / 结算（结束一天） | ❌ 它对应的意图只是 I4「推进时间」——**是动作，不是战略** | ❌ 不产出任何东西，只**兑现**已有的东西 | — | **支撑性时刻（共享时钟）** |
| 招募 / 市场 / 驻军 | ❌ **不是时刻**，是经营主面内的标签页 | — | — | **经营的下属面，不得提级** |

### 2.3 结论（直接回答）

**只有「探索」与「经营」是支柱。其余候选都不是。**

- **两大支柱成立，不是"四个平级"。** 因此 **`ux/in-game-ia.md` 不需要重排** —— 它的 §1 只登记了两个时刻，方向与本档一致。
- **战斗** = **支撑性时刻（继承者）**：它继承探索与经营的产出，自己不开一个新的战略闭环。旁证：IA 表 #42 把 `BattleScreen.ts` 判为"**按需（独立全屏）**……由遭遇触发，**不常驻**"——而支柱需要一等常驻入口，属性直接矛盾。
- **回合推进 / 结算** = **支撑性时刻（共享时钟）**：上一轮已定"日期是两方的共享时钟，**不登记在任何一方名下**"。把时钟当支柱，等于给钟表发一张选票。
- **内部一致性旁证（核心循环反过来验证了本判定）**：见 §5，核心循环的两半**正好**就是两条支柱；若战斗是支柱，循环里就该存在一条"战斗 → 下一环"的独立闭环，但它不存在（战斗是遭遇触发的**结算**，不产出循环的下一环）。

### 2.4 ⚠️ 术语冲突（需主理人处置，我未擅自改）

**仓库里"支柱"一词现在指两个层级**：

- `design/difficulty-spec.md` §2 写了「**支柱一 / 二 / 三 / 四**」——但那四条是**难度子系统的设计原则**（"难度是我这边变难"、"normal 零改动"等），**不是游戏设计支柱**，也不属于本档 §1 的两条。
- 两处撞名会导致下个读者把"难度的四条原则"当成"游戏有四大支柱"。

**建议**（属 `difficulty-spec.md` 的措辞修正，**超出本档授权，仅上报**）：
把 `difficulty-spec.md` §2 的「支柱一~四」改名为「**难度设计原则 D1–D4**」，并在其 §2 开头加一行指针指向本档。**是否执行请主理人决定。**

> 另注：我全仓 grep 不到"四个时刻"的原始出处（`design/`、`docs/`、`production/` 里只有 `ux/in-game-ia.md` 的两个时刻：探索 / 经营）。我这边唯一出现过"四条/四个"的地方就是上一条提到的 `difficulty-spec.md` §2。若主理人手上有"四个时刻"的原文，请核对第四个候选是"战斗 / 招募 / 结算"中的哪一个——**但无论它是哪一个，§2.2 的判定表已覆盖全部候选，结论不变**。

## 3. 目标玩家

| 项 | 内容 | 出处 |
|---|---|---|
| 姓名 | **阿凯** | `ux/in-game-ia.md` §1 |
| 画像 | **HoMM3 老玩家**，现在**用手机**玩 | 同上 |
| 核心要求 | **他不需要教学，他需要"别挡着我"** | 同上 |

**这条画像的推论（写进设计约束，不是写进教程）**：所有"第一次玩的人需要被解释"的东西（教学关、提示气泡、功能解锁流程）**都不是默认要做的**；反过来，"老玩家一眼就该看懂的读数"（移动力、造价、战损预估）**必须一眼可见**——他们不会去翻说明。

## 4. 平台与会话

| 项 | 内容 | 出处 / 性质 |
|---|---|---|
| 目标平台 | **横屏手机**（OPPO PMA110 / Android 16 / DPR 3 / **CSS 视口 792×360**） | `ux/in-game-ia.md` §1、§4（**实测值**） |
| 会话长度 | **≈ 8 分钟的碎片会话** | ⚠️ **这是假设，不是实测**（推导见 `ux/in-game-ia.md` 附录 A.2 / 开放问题 **Q1b**） |

**会话长度这条假设必须继续挂着"假设"标签**（Q1b 仍开放，未由用户确认）。它的**唯一用途**是给"面板开合成本"定权重：

- 若假设成立（一局 8 分钟，开合面板很多次、每次停留很短）→ "开合成本接近 0"是硬要求。
- 若真实会话远长于此（例如一坐 40 分钟）→ "面板开合成本"的权重**下降**；
  但 **"地图不被遮挡"与"经营入口不埋深"两条权重只会上升**（因为停留更久 = 结构性问题更痛）。

> 也就是说：**会话长度这条假设错不错，都不影响两条支柱的成立**——它只影响摩擦类规则的权重大小。这是把它标为假设而不标为事实的理由。

## 5. 核心循环

> **带有限的移动力出门 → 换回资源、宝物与敌情 → 回城把它变成兵与建筑 → 用更强的队伍去更远的地方 → 直到只剩你一家。**

循环的两半**就是两条支柱**：出门 = 探索（用腿换信息），回城 = 经营（用信息换兵力）。

**每一环都有代码事实支撑**（写出来是为了让实现者能对上系统，本档不写数值）：

| 环节 | 对应系统 |
|---|---|
| 带有限的移动力出门 | 英雄 `movePoints` / `BASE_MOVE_POINTS`（`core/map/generator.ts`） |
| 换回资源、宝物与敌情 | 野怪守卫奖励与矿场（`core/data/mines.ts`）、宝物（`core/data/artifacts.ts`）、迷雾（`core/map/fog.ts`） |
| 回城把它变成兵与建筑 | 建筑树与招募（`core/data/buildings.ts`）、周增长（`core/game/town.ts`） |
| 用更强的队伍去更远的地方 | 更厚的野怪分档按"距最近主城距离"排布（`core/map/generator.ts`）、中立城与对手主城 |
| 直到只剩你一家 | 出局 = 城与英雄都没了（`core/game/victory.ts` 的 `isEliminated`）；胜利 = 敌对阵营全部出局（`evaluateOutcome`） |

**循环之外的未定量（不写死，进 §6）**：一局**几天**、跨**几次会话**、单局**多长**——都还没有实测依据。
