# 示例地图关卡设计（maps.md）

> 状态：设计定稿待批 · 负责人：文策渊（设计/叙事） · 强度：Lean
> 目标：为本作提供**两张可发布示例地图**，一张教新手、一张做完整四族对抗（对标 SoC 的 example map）。
> 读取依据：`src/core/data/layouts.ts`、`mines.ts`、`src/core/map/generator.ts`、`tools/layoutmap.mjs`、`DESIGN.md` §16/§19/§20。

## 0. 前置说明：本作"示例地图"怎么落地

当前引擎**没有地图编辑器**，地图由 `createGame({ size, seed, layout, opponents, difficulty })` 程序生成——同一 `seed + config` 必然生成同一张图（`DESIGN.md` §16.1）。因此"手绘示例地图"在本作里 = **固定配置预设 + 脚本事件**：

```
示例地图 = { 固定 seed, 固定 size/layout, 固定 opponents/difficulty, 脚本事件表 }
```

- 固定 seed 保证每位玩家进场看到的是**同一张图**（可教学、可攻略、可分享）。
- 脚本事件表需要**新增一个"地图脚本"系统**（当前 `src/core/events.ts` 只是一个 UI 事件总线，**没有剧情/触发器能力**）。
- 建议落地形态：新增 `src/core/data/maps.ts`，导出一个 `MAPS: MapDef[]` 数据表（见 §3.3 的 schema）。

> **给 engineering-lead 的最小需求（经 team-lead 中转）**：
> 1. `MapDef` 数据表（预设 config + 事件表）。
> 2. 一个 `ScriptRunner`：每回合开始、玩家每步移动后，遍历该地图的 `once` 未触发事件，匹配 `when` 条件 → 执行 `effects`。
> 3. 一个 `toast` 通道：把事件文案以"角色对白框"形式弹给玩家（复用现有 log/弹窗 UI）。
> 4. 事件"固定点"物件（信使、山贼营地等）需要能按坐标放置（现有生成器只按规则撒点，需要一个"盖章"入口，§20.2 的 `applyLayout` 已是同类先例）。

## 1. 图 1《启程》—— 中型教学图

**剧本口号**：*"先学会走路，再学打架，最后才知道邻居不是好人。"*

### 1.1 配置

| 项 | 取值 | 理由 |
|---|---|---|
| 尺寸 | 中型 32×32 | 一张图 25–40 分钟走完，手机单次会话可完成 |
| 布局 | 旷野（wild） | 无特殊地形门槛，最适合"第一次玩" |
| 对手 | 1（赤焰部落 AI） | 单族对手，玩家只面对一种威胁，认知负荷最低 |
| 难度 | 轻松（easy） | AI 发育慢、出兵门槛高——**保证新手不会在第 5 天被灭** |
| seed | 固定（待工程选，要求：主城与对手主城曼哈顿距离 ≥ 14） | 教学可复现 |

### 1.3 脚本事件清单（触发器 / 效果 / 玩家看到的文案）

| # | 事件 | 触发条件 | 效果 | 玩家看到的文案 |
|---|---|---|---|---|
| ① | **迷路的信使**（引路） | 第 1 天回合开始 | 在玩家主城旁 2 格生成「信使」info 物件；揭开主城→锯木场方向 7 格半径的迷雾；弹提示 | 「指挥官！我是晨曦军团第七信使。我的地图……被一只山羊吃掉了。但我记得：**锯木场往东走三格**！」 |
| ② | **山贼同乐会**（埋伏 / 第一战） | 玩家英雄踏入隘口格（通往锯木场的唯一通道） | 生成 野狼×3 强制遭遇战；胜利后掉落 500 金 + 宝物「+1 攻之剑」 | 战前：「库房里堆着别人的年货，山贼们正在开年会——他们表示很乐意跟你'交流交流'。」<br>战后：「山贼们散会了，留下一堆没人认领的东西。看来年会开得不怎么样。」 |
| ③ | **伏兵**（第二波 / 防守课） | 第 ≥ 6 天 **且** 玩家已占领 ≥ 1 座矿场 | 在距玩家矿场 5 格处生成 野猪×4 + 野狼×3「伏兵」，3 天内向矿场移动（清掉则消失）；清掉给 800 金 | 触发时：「你的矿场飘出了烤肉味。峡谷里的野猪们表示：闻到了。」<br>清掉后：「伏兵变成了加餐。矿场安全了。」 |
| ④ | **邻居来串门**（剧情 / 难度爬升） | 第 ≥ 12 天 **或** 玩家占领第 2 座矿场 | 揭开对手主城周边迷雾；对手 AI 获得一批**明示**增援（+8 弓手 +4 枪兵）；发警告 | 「赤焰部落的侦察兵远远看了你一眼，然后回去吹了三天的牛。」 |

**设计要点**：④ 给 AI 的增援**必须明示**（弹窗写清"对手获得了一批援军"）。暗增援会摧毁新手对规则的信任——这与 `DESIGN.md`"AI 不作弊"的既有底线一致。

### 1.4 节奏表（难度曲线）

| 天数 | 玩家大致位置 | 遇到什么 | 难度 | 教学点 |
|---|---|---|---|---|
| D1–3 | 主城周边 | 事件①、拾取资源堆、踩矿 | ★☆☆ | 移动与寻路、迷雾、拾取、占领矿场（无战斗） |
| D4–6 | 隘口 | 事件②、占锯木场 | ★★☆ | 战斗界面、**远程兵先射**、伤害预估、战后奖励 |
| D7–9 | 主城 | 建兵营、招募弓手/枪兵、开市场 | ★★☆ | 建造树、招募、市场换资源 |
| D10–14 | 矿场周边 | 事件③、清伏兵 | ★★★ | 防守与巡逻意识、部队分配 |
| D15–20 | 中线 | 事件④、侦察、首次攻城 | ★★★★ | 侦察、城墙/城门/箭塔、攻城器械 |
| D20+ | 对手主城 | 攻克对手主城 → 胜利 | ★★★★ | 终局目标、胜负结算 |

**曲线形状**：一条平缓上升的折线，**没有断崖**——每次难度上台阶前，都有一个"教学事件"把新机制讲清楚。目标时长 **25–40 分钟**。

### 1.5 教学意图（这一图要让新手学会什么）

1. **怎么走** —— 点击移动、寻路、迷雾（事件①）。
2. **怎么打** —— 战术战斗、远程先手、伤害预估（事件②）。
3. **怎么发育** —— 占矿、建造、招募、市场（D1–9 全程）。
4. **怎么防** —— 世界不是静态的，会有兵来打你的矿（事件③）。
5. **怎么赢** —— 对手是敌人，攻城拿下主城即胜（事件④ → 攻城）。

### 1.6 验收标准（"这图做对了"长什么样）

- [ ] 一位**没看过攻略的新玩家**能在 40 分钟内通关，且每个教学点都在 5 分钟内被"逼"出现一次。
- [ ] 全程**不存在必败死局**：即使玩家在事件②全灭，也应有足够金币在酒馆重雇英雄翻盘（复用 `DESIGN.md` §16.5 的"城在就不算输"）。
- [ ] 事件②的野狼×3 对"20 弓手起手"应当**能赢但会掉兵**（用 `quickBattle` 验证：胜率 100%、损失 10–30%）——既教会代价，又不挫败。
- [ ] 事件③若玩家放着不管，伏兵确实会踩掉矿场（验证触发器真的在跑，不是摆设）。
- [ ] 全部文案**有笑点且不啰嗦**（单条 ≤ 2 句）。

**剧本口号**：*"四方猎手围着一座宝库转圈，谁先过河，谁先挨揍。"*

### 2.3 出生位与资源分配

| 出生区 | 方位 | 默认阵营 | 保底资源 | 争夺目标 |
|---|---|---|---|---|
| A | 西 | p1（玩家） | 锯木场 + 采石场 + 1 金矿 | 最近的内环渡口、中环中档宝库 |
| B | 北 | p2 | 同上 | 外环北渡口、中环北宝库 |
| C | 东 | p3 | 同上 | 外环东渡口、中环东宝库 |
| D | 南 | p4 | 同上 | 外环南渡口、中环南宝库 |

**对称性**：四家到中心与到"最近渡口"的距离**严格相等**（沿用 `pickHomeSpots` 的整体旋转 + 平移，`DESIGN.md` §16.2），保证没有"抽到近邻居"的不公。**随机性来自 seed 决定的湖岸与宝库具体位置**，不来自起点优势。

### 2.4 中部争夺区的设计意图

- **两道理性门槛**：外护城河 3 渡口 → 内护城河 3 渡口（**相位错开**）。玩家必须**连闯两关**才能摸到中心强宝库，把"会猎"拆成两个阶段：先抢**外渡口**（早期，决定谁先出自家片区），再抢**内渡口**（中期，决定谁能摸到稀有资源）。
- **渡口即战场**：渡口是天然走廊格，恰好是**隘口守卫**（`x`）的最佳落点（`DESIGN.md` §19.2 的"守卫摆在走廊格"规则）——所以每个关键渡口前都有一场硬仗，把"抢渡口"从竞速变成"要不要为它损兵"的决策。
- **中心强宝库是唯一的"胜负手"**：打赢它的奖励（4500–7000 金 + 3–5 稀有资源 + 50% 宝物，`mines.ts`）足以让抢到的一方在后期碾压。但强档守军（食人魔×10–14 + 骑士×8–12 + 弓手×16–24）在中期**任何单一族都打不下来**——逼出"先外交后翻脸"的动态：**谁也不想第一个去打，谁都想等别人打残了再上**。这就是"会猎"的核心张力。
- **AI 行为适配**：四方 AI 天然会去抢矿与宝库（现有 `pickTarget` 已验证会占矿 15.5 座、打掉 19/24 宝库）。本图通过**把 2 座中档宝库、4 座稀有矿放进内环、1 座强宝库放中心**，让 AI 的"向外探索"目标与地图结构对齐——AI 会自然沿渡口往中心推，而不是在自家门口转圈。

### 2.5 难度曲线与目标时长

| 阶段 | 天数 | 主要活动 | 冲突形态 |
|---|---|---|---|
| 探索发育 | D1–10 | 各家占外环保底矿、建兵营 | 无接触 |
| 抢外渡口 | D10–20 | 冲出自家片区、抢中环矿与中档宝库 | 首次遭遇战、抢矿 |
| 宝库争夺 | D20–40 | 抢内渡口、试探/残杀强宝库守军 | 四方混战、互相袭扰 |
| 决战 | D40+ | 强宝库易主后，富的一方推平其余 | 大规模攻城、终局 |

**曲线形状**：**正弦叠加式**——两次"渡口争夺"是两个波峰（D10–20、D20–40），中间有短暂喘息；D40 后由"谁吃到强宝库"决定谁陡增。目标时长 **60–90 分钟**（手机可分 2–3 次会话，进度存档）。

### 2.6 验收标准（"这图做对了"长什么样）

- [ ] 固定 seed 下，**四家主城到中心的曼哈顿距离差 ≤ 1**，到各自最近外渡口的距离差 ≤ 2（用 `tools/layoutaudit.mjs` 同款数字验收）。
- [ ] 两道理性门槛**真的存在**：外护城河在 12 个方向上大多为水、仅 3 处为渡口；内护城河同理且**相位与外环错开**（复刻 `DESIGN.md` §20.3 的同心环断言）。
- [ ] 中心高地**必有一座强档宝库**且守卫齐全（隘口守卫覆盖）。
- [ ] 四家起手资源**完全相等**（沿用 `START_ARMY` 与难度 `startMul`），无起点优势。
- [ ] 120 天 AI 长局（四方）：**至少 3 家**能走出自家片区进中环（验证渡口不是死胡同）；无一家在起手区被围死。
- [ ] 目标时长落在 60–90 分钟；若实测 < 45 分钟（速通）或 > 120 分钟（拖沓），按 §2.7 调。

### 2.7 可调旋钮（若实测偏长/偏短）

1. **渡口数量**（3 → 2 更难 / 3 → 4 更易）。
2. **中心强宝库守军规模**（决定"决胜时刻"何时到来）。
3. **中环中档宝库数量**（2 → 3，让中期争夺更分散）。
4. **地图尺寸**（48 → 40 压缩时长）。

## 3. 两张图共通

### 3.1 设计目标对照

| | 图 1《启程》 | 图 2《四族会猎》 |
|---|---|---|
| 目标玩家 | 第一次玩的人 | 已通关一次的玩家 |
| 核心体验 | 学会规则 | 四族博弈、抢渡口、夺宝库 |
| 复杂度 | 低（单威胁） | 高（四方混战 + 两阶段瓶颈） |
| 时长 | 25–40 分钟 | 60–90 分钟 |
| 主要交付 | 教学闭环 | 种族差异的可玩展示（四族同场的说服力） |

### 3.2 与种族设计的联动

- 图 2 是**四族差异的"展示窗"**：玩家在图 1（单族、轻松）学规则，在图 2 才会真正遇到"赤焰第 1 周就来抢矿""翠林越拖越厚""紫晶后期魔法碾压"——所以**图 2 的对手必须四族不重复**。
- 事件文案统一采用 `races.md` 的卡通调性（同一套"梗"语言：军团爱打卡、赤焰爱嚎、翠林爱浇水、紫晶爱爆炸）。

### 3.3 数据 Schema 建议（供工程参考）

```ts
// src/core/data/maps.ts（建议新增）
interface MapDef {
  id: string;
  name: string;            // 「启程」「四族会猎」
  sub: string;             // 卡片小字
  config: { size; layout; seed; opponents; difficulty };
  events: MapEvent[];
}
interface MapEvent {
  id: string;
  when: { day?: number; enterTile?: {x,y}; ownMines?: number };
  once: boolean;
```
