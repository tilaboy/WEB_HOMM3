## 0. 风格定位（一句话）

**「玩具箱战争」——把 HOMM3 的战争沙盘做成一桌被小孩摆歪了的彩绘木偶兵棋：粗暖描边、平涂大色块、每族一个死板的轮廓母题、每个兵种都有一处不讲道理的夸张。**

### 0.1 对 Songs of Conquest 的取舍

| SoC 有什么 | 我们**要** | 我们**不要**（成本） |
|---|---|---|
| 氛围光照（清晨暖金 / 深夜冷蓝） | ✅ 全部保留，`lightLayer.ts` 已实现，这是性价比最高的一项 | — |
| 地形整图烘焙 + 边缘 Bayer 抖动 | ✅ 保留，已经有 | — |
| 水面碎光高光带 | ✅ 保留，已经是画质亮点 | — |
| 手绘级的建筑/兵种贴图（每张都是人画几十小时） | ❌ 用「程序化色块 + 强形状语言」替代 | 写实纹理、布料褶皱、金属高光渐变 |
| 大量逐帧动画（SoC 每个兵种 8-12 帧） | ❌ 只做 **idle 浮动 + 攻击缩放** 两级程序化动画 | 逐帧手绘动画 |
| 地图上的巨型叙事地标（要塞 / 巨像） | ⚠️ 仅在 2 张 example map 上各做 1 个「英雄建筑」（AI 生成，见 asset-spec §5） | 全地图地标体系 |

**一句话取舍**：我们抄它的**光影与构图**，不抄它的**绘制密度**。卡通化的本质是「减少信息量、放大特征量」——这恰好和程序化生成的能力边界一致，所以这次方向调整**不需要推翻渲染架构**。

### 0.2 与现有两个被推翻方向的关系

| 方向 | 结局 | 我们继承了它什么 |
|---|---|---|
| Polytopia 扁平等距（DESIGN.md §十一 决策#1） | 已推翻 | 「平涂大色块」的理念被救回来了，但**换成 HOMM2 的 32px 正交方格**保留地图可读性 |
| HOMM2 像素俯视（DESIGN.md §十四） | **保留为底座**，本次只做「卡通化」而非「换风格」 | 正交方格 TILE=32、逐像素管线、画家算法、`imageSmoothingEnabled=false` 全部不动 |
| P1.4 的 16-bit SNES 弓手草稿 | ❌ **废弃重新生成** | 它的洋红抠底法可用；但它的**配色（约 40 种浑浊橄榄棕中间调）与我们的色板冲突**，见 §3.5 |

## 1. 造型语言（卡通化的可执行规则）

### 1.1 描边

| 画布尺寸 | 描边宽 | 颜色 | 理由 |
|---|---|---|---|
| 高 ≤ 64px（物件 / 兵种 / 英雄 / 城镇） | **1px** | `ink0` `#2a1a12` | — |
| 高 ≥ 65px（2×2 城堡 72×96） | **2px** | `ink0` `#2a1a12` | 大图 1px 会显得笔画太轻 |
| **战斗单位 44×56** | **1px（不要加粗）** | `ink0` | ⚠️ 见下方警告 |
| 内部结构线（甲片缝、砖缝、门框） | 1px | `ink1` `#4a3524` | 比外描边浅一档，形成主次 |

> ⚠️ **描边宽度必须按「最终屏幕像素」思考，不要按画布像素直觉加粗。**
> 相机默认 `zoom = 2`，手机 `dpr = 2~3` → **1 画布像素 = 4~6 物理像素**。
> 战斗单位放大 2 倍后，1px 描边在手机上已经是 4–6 物理像素的粗黑边。若改成 2px，屏幕上就是 8–12px 的黑框，直接把单位变成一团墨。**这是卡通化最容易踩的坑。**
>
> 例外：**只有城堡（72×96）用 2px**，因为它在地图上不参与战斗缩放，且它是画面里最大的单一主体。

### 1.2 转角规则

现管线只有 `rect / frame / hline / vline / line / ellipse / poly`，**没有圆角**——这是卡通化最缺的原语（已列入工程交接清单）。

- **有机物**（树冠、云、蘑菇、兽类躯干、村民的头）：用 `ellipse`，圆角即天然圆。
- **人造物**（建筑、车辆、盾牌、宝箱）：**禁止直角**。每栋建筑的四个外转角**至少切 1px 斜角**，大建筑（≥64px）切 2px。
  理由：32px 尺度下的纯 90° 直角会读成「程序员的矩形」（现 `town()` 的墙体就是这样，见 §8 改造清单）。
- **尖角只留给一个东西**（每族一个母题）：p1 的塔尖、p2 的屋顶兽刺、p3 的枝叶、p4 的晶体。**其他部位一律圆或切角**——尖角满图就是噪音，这是「卡通」和「低幼乱画」的分界线。

### 1.3 比例夸张规则（卡通的核心）

| 规则 | 具体数值 | 现状 → 目标 |
|---|---|---|
| **头身比** | 头高 : 全身高 = **1 : 3**（人类单位），兽类头占身体 **40%** | 现 `combatAtlas.humanoid()` 头是 `ellipse(ry=6)`=12px / 45px ≈ **1:3.7**，**要放大 1.4 倍** |
| **眼睛** | 眼宽 ≥ 头宽 **25%**；必须**两个像素以上**且能读出朝向 | 现状：`pb.set()` **1 像素黑点**（44×56 画布上），放大后是 4px 的点，读不出表情 → **必须重做** |
| **手 / 脚** | 比解剖学放大 **1.4 倍**，且用一整块色（不画指头） | 现状手脚是 3×2 的小色块，太小 |
| **道具**（武器/盾/杖/旗） | 占剪影面积 **≥ 25%**；长度夸张 **1.3–1.6 倍** | 现弓/枪基本等身，可接受但不够好笑 |
| **唯一性**：每个单位**只有一处**比例失调 | 2 处以上 → 变成噪音，不再是风格 | — |
| **基线** | 所有单位脚底**严格对齐**画布底边（`ay` 已按此设计） | 现状已正确，**继续沿用** |

> **为什么「只有一处失调」这么重要**：卡通 = 一整套写实规则 + 一个打破点。如果处处都失调，观众的「写实直觉」失去参照，搞笑感就塌成乱码。这是可执行的自检标准。

### 1.4 高光与阴影

- **阴影**：不用黑色。用**冷紫** `rgba(58, 42, 74, 0.28)`（现状是纯黑 0.22）。
  理由：卡通画面的阴影偏冷才「通透」；纯黑会在暖色地砖上留下一个脏洞。
- **高光**：**只画 1 处、只 1px 宽**，一律在**光源方向（右上）**。
  色：`hi0 #ffffff`（金属/晶体）/ `hi1 #fff3c8`（暖色材质）。
  禁止：渐变、多重高光、边缘光带（那是写实风的东西）。
- **AO 接触阴影**：物件与地面接触处，在 `outline()` **之前**画一圈 1px 的 `ink1 #4a3524`，让物件「坐」在地上而不是浮着。

## 2. 光照配合（与 `lightLayer.ts` 的对齐）

### 2.1 现状机制（必须理解）

```
MapRenderer.draw():
  画地形 → 画物件/单位 → ctx.restore()
  → applyLighting(): 全屏 multiply(rgb(tint)) → overlay 暖光 → 径向暗角
```
关键点：**光照是屏幕空间的全屏 multiply，画在所有图层之后，无法只作用于地形。** 所以单位、建筑、UI 面板外的所有像素都被一起压暗。

夜晚关键帧：`{ r:148, g:164, b:208 }` → 等效乘数 **R 0.58 / G 0.64 / B 0.82**（注释说"压到约 58%"）。

### 2.2 卡通色板在夜间的失真分析（实测推算）

把各族主色代入夜晚乘数：

| 族 | 日间主色 | 夜晚实际值 | L* 日 → 夜 |
|---|---|---|---|
| p1 晨曦 | `#3f8fe8` | `#255473` | 55 → **28** |
| p2 赤焰 | `#e04a34` | `#822f2b` | 45 → **21** |
| p3 翠林 | `#3fbe6e` | `#257a5a` | 62 → **33** |
| p4 紫晶 | `#a165e8` | `#5d538f` | 48 → **30** |

**结论（诚实版）**：
- 明度对比在 multiply 下**比例是守恒的**（乘同一个系数不影响两色的比值），所以「深底浅物」的结构不会塌。
- **真正会塌的是色相**：蓝色通道被单独留了 0.82，**所有族的色相都被拽向蓝**。p2 的暖红（hue 4°）在夜里和 p4 的暗紫在**低明度下几乎分不出**（都是深蓝紫团块）。这才是真正的风险，不是「变暗」。

### 2.3 因此必须做的调整（交工程线，见 §8）

| # | 改动 | 具体值 | 理由 |
|---|---|---|---|
| L1 | 夜晚 floor 提高 | 乘数 0.58 → **0.70** | 卡通靠明度反差，压到 58% 后大色块全进暗区，画面变"糊" |
| L2 | 夜晚降蓝饱和 | `rgb(148,164,208)` → **`rgb(178,182,205)`** | 去掉"蓝通道单独留白"的偏色，4 族色相不再塌缩 |
| L3 | **主体层单独光照** | 单位/英雄/城堡层用**较浅的 multiply**（tint 与白色按 45% 混合后再乘） | 玩家必须随时看清单位。实现建议：把单位层画进离屏 canvas，用 `alpha=0.55` 的浅 tint 二次 multiply；或接受 L1 的全局抬亮即可 |
| L4 | 暖光 overlay 不动 | 保留 | 清晨/黄昏的橘光是卡通画面最好的氛围，已实现得很好 |
| L5 | 暗角 0.22 不动 | 保留 | 卡通画面很吃暗角 |

### 2.4 色板侧的防御：明度签名 + 外形母题（双通道）

既然纯明度扛不住 4 个族，规则定为：**灰度测试下必须靠「明度台阶 + 外形母题」两条通道同时可辨**。

| 族 | 明度签名（主体墙面 L*） | 灰度下的形状签名 |
|---|---|---|
| p1 晨曦 | **90**（最亮，石灰白墙） | 垂直尖顶、高瘦、顶部有旗 |
| p2 赤焰 | **62**（暖中） | 横向宽顶、矮胖、屋顶长刺 |
| p3 翠林 | **50**（中暗，木绿） | 不规则有机轮廓、顶部不对称枝叶凸起 |
| p4 紫晶 | **36**（最暗底）+ **93**（自发光斑） | 菱形硬几何、上细中宽下垂、带 1–2 个亮光点 |

台阶差：90 / 62 / 50 / 36 → **相邻差 ≥ 12 L\***（12 是可辨阈值，3 是勉强）。p4 额外用**双峰（暗底 + 亮斑）**与 p3 拉开。

**自检方法**：截图 → 转灰度 → 缩到 25% → 让一个没看过本项目的人说出「左边那团是哪个族」。说不出就改明度，不要改色相。

## 3. 调色板规格

### 3.1 与现有 `atlas.ts` 配色的关系：**分层处理，不是全量替换**

| 层 | 资产 | 处理 |
|---|---|---|
| **环境层** | 地形砖 `g_*`、岸线 `sh_*`、小装饰 `deco_*` | ✅ **不动**（容差 ≤10%）。理由：地形已经读起来像"有笔触的像素画"，重写地形的成本极高、观感收益极低，且卡通与否的判据在**主体**身上 |
| **主体层** | 兵种 `u_*`/`cu_*`、英雄 `hero_*`、城镇 `town_*`、城堡 `castle_*`、怪物 `mon_*` | 🔄 **替换为新色板**（饱和 +15~25、明度差拉大、描边加粗） |
| **UI 层** | `mk_*`、`ic_*`、资源图标 | ⚠️ **小幅提亮 + 加粗描边**，尺寸从 16/18 统一到 24（见 asset-spec §1） |

### 3.4 色板硬约束

- 单个精灵**最多 24 色**（不含透明）。现状 `castle()` 一栋就用了约 30 种由 `shade()` 生成的颜色 → 需要收敛。
- **禁止**在色板之外用 `shade()` / `mix()` 现场造色，除非是这 5 个固定台阶：`-0.30 / -0.15 / 0 / +0.18 / +0.38`。理由：现场造色是"颜色越画越多、越画越浑"的根源，也是 AI 资产的解毒剂（见 asset-spec §5.3）。
- 每族主色的**饱和度下限 45%**、明度中位 **≥ 45%**（p4 的 wall 除外，它故意压暗）。

### 3.5 反面教材：P1.4 的 SNES 弓手草稿

`assets/ai-drafts/16_bit_SNES_style_pixel_art_ga_2026-09-17T09-19-33.png` 目测用了 **35–45 种浑浊橄榄棕中间调**，明度集中在 25–55% 的窄带里。后果：
1. 缩到 44×56 后**整体读成一坨褐色**，看不出是弓手还是农民；
2. 和现有程序化资产放在同一张图里像两个游戏；
3. 它**没有描边**（或描边是被抗锯齿糊掉的灰边）。

→ 这张图可以作为**管线测试样本**（验证抠底/降采样/钳色），但**不作为美术基准**。

## 4. 「搞笑」的可执行规则（6 条，附检查方法）

> 原则：**静态图不搞笑，动起来才搞笑** —— 这也是「程序化优于 AI」的核心理由（AI 出的是静帧，暖不了场）。

| # | 规则 | 具体做法 | 检查方法 |
|---|---|---|---|
| **H1** | **单点失调律** | 每个兵种**只有一处**比例偏离现实 ≥1.5×（大头 / 巨手 / 超长武器 / 超小身体），其余部位严格按 §1.3 的写实规则 | 遮住那一处，剩下的还像人吗？像 → 通过 |
| **H2** | **配角比主角抢眼律** | 每族 tier-5 单位必须带一个**明显过大或过小的随从/道具**（过大：扛不动的锤；过小：比头还小的坐骑） | 单位在 44×56 里最小的元素是不是道具？是 → 通过 |
| **H3** | **表情可得律** | 所有人类单位**必须有 2px 以上的可读眼睛 + 1px 嘴线**；兽类用 2px 眼白 + 1px 瞳孔（`quadruped()` 现在的 `pb.set(eye)` 是 1px，要放大） | 缩到 32px 还能看出"在笑/在凶"吗？ |
| **H4** | **色彩打架律** | 每族主色配一个**色相差 ≥120° 的撞色**（§3.3 的 `clash`），**只用在 1 处小面积**（帽子 / 披风 / 一枚徽记）。面积 >8% 就从"滑稽"变成"丑" | 撞色面积占比 ≤8%？ |
| **H5** | **动态律（程序化必做）** | ① idle：整体上下浮动 **0 / -1 / -2px**（3 帧循环，600ms，整数偏移）；② 攻击：**squash & stretch**（出击帧 1.15× 宽 / 0.85× 高，命中帧反过来）；③ 受击：整图 **+2px 右移 1 帧** | 关掉动画截图，看不出好笑 → 这正常，别加静态细节去补 |
| **H6** | **职能反差律** | 每族**最弱的 tier-1 要表现得最认真**（站最直、装备最全、表情最自信），强单位反而松松垮垮 | 把 tier-1 和 tier-5 并排，谁更"像那么回事"？应该是 tier-1 |

### 4.1 H5 的工程约束（重要，交工程线）

图集是**启动时静态烘焙**的，运行期只做 `drawImage`。所以动态搞笑必须落在渲染层：
- **idle 浮动**：用**整数 y 偏移**（`ay + 0/-1/-2`），零成本、零糊边。✅ 推荐。
- **攻击缩放**：`drawImage` 的 `dw/dh` 若用非整数会**糊**（`imageSmoothingEnabled=false` 也救不了非整数缩放的像素撕裂 → 出现 1px 差值带来的行列不均）。
  **方案 A（推荐）**：攻击时用 **1.0× 与 0.85× 两张烘焙帧**（atlas 里各存一张，成本 +1 帧/单位），render 层做整数倍切换。
  **方案 B**：只在 `zoom × dpr` 为偶整数时才缩放。
  **禁止**：运行时任意 `scale(1.15)`。

## 5. 每族的视觉识别规则（32px 可辨）

### 5.1 判定标准

> **32px 缩略测试**：把城堡缩到 32×42、兵种缩到 16px 高，贴到 3×3 网格里，旁边放同色系的另一族 —— 能在 1 秒内分出种族，才算通过。

### 5.2 p1 晨曦军团 · 「高瘦尖顶」

| 维度 | 规则 |
|---|---|
| 城市轮廓 | **垂直母题**。中央主楼最高最窄，两侧角塔细高，全部**陡三角尖顶**（屋顶角度 ≥60°），塔尖必有一根旗杆（全族唯一有旗的） |
| 建筑配色 | 石灰白墙 `#eae3d2` + 蓝瓦 `#3f8fe8`；墙面**竖条纹**（现状 `wallLite` 左 16px 的做法保留并加强） |
| 兵种剪影 | **全部向上**：武器/旗/杖竖直向上举，轮廓**高瘦**（宽高比 ≤ 0.55）；装备最整齐、盔甲最亮 |
| 32px 特征 | 尖顶 + 蓝白**竖**条；整体最亮 |
| 搞笑点 | 最严肃的一族 —— 全员站军姿、表情一本正经，道具排得整整齐齐（与 p2 的混乱形成反差） |

### 5.3 p2 赤焰部落 · 「矮胖兽刺」

| 维度 | 规则 |
|---|---|
| 城市轮廓 | **横向母题**。屋顶**宽梯形**，屋檐向外挑出，屋顶长 **2–4 根兽骨尖刺**（全族唯一有刺的）；建筑矮（高度 ≤ p1 的 75%） |
| 建筑配色 | 陶土红墙 `#c98a4e` + 红瓦 `#e04a34`；墙面**横纹**（木板/藤条），大量**不规则缺口**（像被啃过） |
| 兵种剪影 | **前倾 + 宽肩**，武器**横持**（斧 / 锤 / 大棒，横向占位 ≥30%）；轮廓矮胖（宽高比 ≥ 0.8） |
| 32px 特征 | 宽顶 + 屋顶尖刺 + 暖橙红块；整体最"毛" |
| 搞笑点 | 全员装备**不合身**：头盔太大盖住眼睛、裤子太短、武器比自己沉；表情很凶但很笨 |

### 5.4 p3 翠林守望 · 「有机不规整」

| 维度 | 规则 |
|---|---|
| 城市轮廓 | **不对称母题**。屋顶是**圆弧或叶形**，屋顶上必长出 1–2 丛**活树枝叶**（伸到轮廓之外）；建筑左右高度**故意不等**；外墙爬藤 |
| 建筑配色 | 苔木绿 `#7a7a48` + 叶绿 `#3fbe6e`；材质像**长在树上的**，底部与地面过渡要"毛"（用 `deco_*` 的草叶压住基座） |
| 兵种剪影 | 轮廓带**凸起**（头顶叶冠 / 背上的箭袋树枝 / 藤编甲）；身体**半蹲**、重心低；武器用**自然材料**（木弓 / 石斧 / 藤鞭） |
| 32px 特征 | 圆形主轮廓 + 顶部**不对称凸起** + 绿褐 |
| 搞笑点 | 最"松散"的一族：站姿歪、有单位被藤蔓绊住、动物伙伴在旁边乱入（兽类头占比最大） |

### 5.5 p4 紫晶密会 · 「悬浮晶体」

| 维度 | 规则 |
|---|---|
| 城市轮廓 | **菱形母题 + 悬浮**。主塔是**菱形晶体**（上细中宽下收），必有 **1–2 块悬浮的石块/晶体**（离主体 ≥2px 悬空，这是全族最强的识别点，因为它违反"东西要落地"的直觉） |
| 建筑配色 | 暗石紫墙 `#58526e` + 紫晶 `#a165e8`；**唯一有真实自发光**的族：`emissive #8ffff0` 用在晶体核心，并向外做 **2px 衰减光晕**（用 alpha 0.5 / 0.25 两圈） |
| 兵种剪影 | **无腿长袍**（锥形下摆，底部**不画腿**）+ **垂坠感**；轮廓上细下宽；眼睛用 `emissive` 色（发光眼） |
| 32px 特征 | 菱形 + **上下细中间宽** + 1–2 个亮光点（灰度下靠"暗底 + 亮斑"双峰区分） |
| 搞笑点 | 最"高冷"的一族，但**物理常识最崩**：法杖比人高、帽子浮在头上、袍子底下什么都没有（走过去飘） |

## 8. 给工程线的交接清单（渲染层改动）

### 8.1 `pixel.ts` 需要新增的绘制原语

| 原语 | 签名建议 | 为什么必需 |
|---|---|---|
| **圆角矩形** | `rrect(x, y, w, h, r, color, a=1)` | 卡通化最缺的原语。现有只有直角 `rect`，是"程序员矩形"的来源 |
| **粗描边** | `outline(color, alpha, width=1)`（现只支持 1px） | 城堡需要 2px。现实现靠"补一圈"，2px 需要迭代 2 次或改实现 |
| **胶囊 / 圆头线** | `cap(x0,y0,x1,y1,r,color)` | 四肢、法杖、树枝 |

| **眼睛/表情组件** | `face(pb, x, y, w, expr)`，`expr: 'smug'\|'angry'\|'dumb'\|'blank'\|'happy'` | 卡通笑点全在这里，沉淀成共享函数，避免 5 个兵种各画一遍 |

## 10. 核心问题结论预告

**卡通风格能不能继续走程序化生成？——能，而且是更优解。**

理由（详细论证见 `asset-spec.md` §5–§6）：
1. **卡通 = 减少信息量 + 放大特征**。AI 的价值在"补有机细节"，而卡通恰恰要求**丢掉**细节。方向是反的。
2. **搞笑靠动，不靠静**。AI 出静帧，`squash & stretch` / idle 浮动只能程序化做。
3. **尺寸天花板**。目标画布 32–72px，AI 的 1024² 要损失 16–32 倍信息，它最擅长的细节在这一步全被销毁。
4. **色板纪律**。AI 会带来 40 种脏中间色（P1.4 草稿就是这个病），必须靠钳色"救回来"；程序化则天生只使用色板。

**分项划分**：程序化约 **95%** 资产；AI 生成仅限 **§6 列的 3 类"英雄级"资产**（每类 ≤5–8 张）。
