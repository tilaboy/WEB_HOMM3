## ✅ 已闭：垫片 vs 真 Chrome 的**合成算子**逐像素一致（2026-09-21 · art-director）

上文「本轮没做」的第一条（垫片与真 Chrome 的**逐像素**一致性）已补。工具：`tools/shimconsistency.mjs`。

**为什么不能直接拿两张整机截图相减**：`artshot` 画的是 26×16 **合成地图**（无迷雾 / 无 UI / zoom 2），
`deviceshot` 画的是**真实游戏**（有迷雾 / UI / 相机）—— **画的是不同场景**，整图相减只会得到"场景不同"，
量不到"垫片忠不忠实"。真正能逐像素比的是**同一串绘制指令**在两套实现下的输出 —— 也就是**合成算子本身**。

**测法**：取本项目渲染代码**实际用到**的几个算子拼成一段固定指令（脚本里的 `OPS`，两套实现执行**逐字相同**的代码）：

| 算子 | 通道 max\|Δ\| | avg\|Δ\| |
|---|---|---|
| ① 不透明实色 `fillRect`（砖底色）+ ④ 整像素对齐九参 `drawImage`（含透明角） | **1** | 0.057 |
| ② `globalAlpha` 0.34 半透明覆盖（地貌层亮部那笔） | **0** | 0.000 |
| ③ `rgba()` 带 alpha 覆盖（迷雾 0.52）+ ⑤ `multiply` 叠色（夜光 tint） | **1** | 0.500 |

⇒ **全部算子在 ±1 LSB 内一致** —— ±1 是 8-bit 存储取整差，**不是结构性偏移**。
故 `a_*` / `b_*` / `c_*` 那批**垫片**对照图与数字，**可作为真实 Chrome 合成行为的代理**；
`§3.1.1` 引用的 `极差 2.37→31.79` / `相邻格平均 |ΔL*| 0.49→2.22` 也因此不再受"垫片存疑"影响。
（旁证：`d_chrome` 的逐通道 multiply 预测 `66.3×178/255=46.3` 实测 `46.4`，那 0.1 的差正是这一档取整。）

复算：`node tools/serve.mjs`（另开终端）`&& node tools/shimconsistency.mjs`。

**边界（本次没覆盖）**：测的是**合成算子**，**不是几何 / 场景**（相机、迷雾、UI 布置、DPR 上采样）。
那几项本来就由 `deviceshot.mjs` 在真 Chrome 里出图，**不经垫片** —— 两条通道互补，不是同一件事。
