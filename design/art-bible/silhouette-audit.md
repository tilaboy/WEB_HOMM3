## ★ D-73「加宽槽位」复核（art-director 裁决 · 2026-09-20）

**裁决：`PASS`（方向正确）—— 附 2 条条件（见 ② / ③）。**

### 一句话
加宽槽位是对的，而且**它没有违反任何缩放纪律**：`normalizeTier` 是在槽位内按目标高把精灵**原生 1:1** 画进去，**槽位变宽不改变精灵的像素尺寸**，只是不再把两侧硬裁。真正的问题不在「加不加宽」，而在**加多宽** —— 现在的数**只覆盖到 T4，没覆盖 T5**（②），以及盲测里的「32px」**现在有两种读法**（③）。

### 为什么方向对（三条，逐条可核）
1. **修的是真缺陷**：改前 8/48 帧被硬裁（最甚 `cu_p2_wolfrider_atk` `destW=58 > 44`）。硬裁 = 精灵两侧缺像素，**不可接受**，这不是风格偏好的问题。
2. **槽位 ≠ 缩放**（本次复核最重要的一条）：`normalizeTier` 的 `scale` 由**目标高**决定、只在槽位内绘制；加宽槽位**不改 scale、不改锚点语义**（`ax = (32−48)/2 = −8`、`ax = −w/2 = −30`）⇒ 精灵仍是**原生 1:1**。因此 **§5.4[4]（只用整数比缩放）与 §1.3（整数缩放）均未被触碰**。**不要把「槽位宽 48」误读成「放大了 1.5×」。**
3. **反面更差**：把精灵压进 32 / 44 会违反 §5.6.3 的**族宽高比**（p2 ≈1.0、p3 ≤1.1 本就要求「宽」）⇒ 等于用违反「形状通道」去救「横向裁切」。两害相权，**加宽槽位是唯一不必牺牲既有规格的出路。**

### ① 地图单位横向压格 8px/侧 —— **可接受**
- **判据不能引 HoMM3 先例。** HoMM3 里压格的是**地形物**（大树、山），它们**本来就该**打破格子边界来暗示体量；**单位**在地图上压不压格，HoMM3 没给先例（它把部队画成英雄 / 旗帜，不画自由站立的单位）。所以这条要**自立判据**，不能抄。
- **自立判据（三条须同时满足）**：
  1. **只允许横向压格，禁止纵向压格。** 横向溢出只影响同 y 行左右邻居的**遮挡顺序**；纵向溢出会**伪造高度**、破坏 y 排序的深度暗示。
  2. **必须并进既有 y 排序 pass**（`MapRenderer` 的 `draws` 数组），靠排序解决遮挡，而不是靠「后画覆盖」。
  3. **压格量必须被「最宽合规剪影」封顶**（见 ②），不允许无上界。
- **现状补充（关键）**：**地图单位帧目前没有任何消费者** —— `MapRenderer` 只 blit `hero_*`（英雄棋子）与 `mon_*`（游荡怪，取 `mon_${unitTypeId}`），**从不画 `u_*_map`**（`MapRenderer` 的对象精灵选择函数里 `wanderingMonster` 走 `mon_*`；本文件 §5 与 design-strategist 独立核实一致）。⇒ **「压格」暂时不是活问题**，它随「地图单位是否有表面」（D-50 待裁）一起生效。**有表面之前本条判 PASS；有表面之后须按上述三条复验。**

### ② 48×44 / 60×56 —— **对已画的 16 单位够用；对 B3 的 T5 不够**
口径必须从「**今天最宽的帧**」换成「**合规剪影在 T5 下最宽能到多少**」，否则 B3 会**原样复发一次同样的裁切**。

复算公式（可复现）：

```
槽位宽 ≥ ceil( T5_目标高 / 该族合规高宽比的下界 )
cu ：T5 = 100% × 56 = 56 高
map：T5 = 100% × 44 = 44 高
```

| 口径 | p2 高宽比下界 | **cu 需要宽** | **map 需要宽** |
|---|---|---|---|
| 今天已画 16 单位实测最宽（含违规 0.77） | — | **58** | **41** |
| 按审计 S2 的 p2 带下界 | 0.85 | **67** | **52** |
| 若把 p2 带收紧到 | 0.90 | **63** | **49** |
| 若把 p2 带收紧到 | 0.95 | **59** | **47** |

**读法**：
- **60 / 48 覆盖不到 T5。** 它们只对「**p2 高宽比 ≥ 0.933（cu）/ 0.917（map）**」的合规剪影才安全；而 §5.6.3 写的是 **≈1.0**，实测 p2 **已经在画 0.77**（`cu_p2_wolfrider`，§4 已记为违规）。⇒ 一个 T5 的 p2（熔岩巨魔「**锤比身体宽**」）**极可能再次溢出**。
- **不要「更贴边」。** map 取 44、cu 取 58 会**当场裁切**：cu=58 已**等于**今天最宽帧，零余量；T5 更直接溢出。**更贴边是往回走。**
- **我的建议（择一，且必须配套）**：
  - **(推荐) 加宽到 `cu 64 / map 52`**，同时把 **p2 高宽比下界写死为 ≥0.875（cu）/ ≥0.85（map）**，由 S2 断言执行（`cu_p2_wolfrider` 的 0.77 是**必改项**）。64/56 = 0.875、52/44 = 0.846，皆有余量。 ✅ **已采纳（`b43ffa8`，2026-09-20）** —— 槽位 `cu 64 / map 52` 已落地；p2 下界已写进 `cartoon-style.md §5.6.3` 与本文件 S2 断言；`cu_p2_wolfrider` 的 0.77 裁定「改形状、不开具名例外」。
  - **(备选) 维持 60 / 48**，则必须把 **p2 下界收紧到 ≥0.94（cu）/ ≥0.93（map）** —— 代价是 p2 现有宽体单位要**改形状**，比加宽槽位贵。**我不推荐。**
- **根本原因**：无论选哪个，**p2 的高宽比下界都必须写进断言**，否则「最宽帧」没有上界、槽位永远可能被突破 —— 这才是 8/48 裁切的**病根**（槽位按经验取、剪影没有宽度上界）。

### ③ 加宽会不会破坏 §5.6.5「去色 32px 盲测」的前提？—— **会，因为「32px」有两种读法**
先厘清事实：`cartoon-style.md` §5.6.5 原文是「**去色、缩到 32px 高**，排成 4×5 网格」——**「32px」是「呈现高」，不是「帧宽」**。所以：

- **D-73 改的不是「32px」**：槽位 32→48 变的是**帧宽**，盲测的 32px 是**缩放到 32px 高**。两者无关 ⇒ **单看这一点，加宽不破坏盲测。**
- **但名字会误导**：`§5.6` 标题写「32px 可辨」、`§5.6.2` 表头写「占 44×56」、`§5.6.5` 写「缩到 32px 高」—— 同一个「32px」在**格宽（1 格 = 32px）/ 帧宽（曾 32）/ 呈现高（32px 高）**三个意义上被混用。**三个测试者极可能测的不是同一件事。** 必须写死。

**我的裁定 —— 把「32px」拆成两个无歧义的盲测协议**：

| 协议 | 目的 | 源帧 | 尺寸处理 | 被测者标注 | 门槛 |
|---|---|---|---|---|---|
| **盲测-P（形状通道）** | 认**族** | map 帧 | 去色，**各自缩到 32px 高** | 这是哪个族 | ≥90% |
| **盲测-Q（体量通道）** | 认 **tier** | map 帧 | 去色，**不重缩**：原生 1:1、**底对齐**、按 **1 格 = 32px** 呈现 | 这是几级兵 | ≥90% |

- **为什么必须拆**：盲测-P 把 20 个单位**统一缩到 32px 高**，等于**用构造消掉了体量差** ⇒ 它只能测**形状通道**。要测**体量通道**（正是本次审计的病灶），**必须不重缩、底对齐**，否则「tier 体量」在测试开始前就被抹平，测试会**假通过**。
- **术语落定**：§5.6.5 的「32px」= **盲测-P 的呈现高**；**盲测-Q 用原生尺寸**。两处表头都改为显式写法，**去掉裸的「32px」**。
- **前置阻塞**：盲测-Q 要求「按游戏内**真实呈现尺寸**」，而 map 单位帧**当前无表面**（见 ①）⇒ **盲测-Q 在「地图单位是否有表面」裁定之前无法有效执行**（它测的是「玩家会看到的尺寸」，没表面就没有「玩家会看到的尺寸」）。**这条与 ② 的槽位宽、与 design-strategist 报的 `u_*_map` 无消费者，是同一个上游问题的三个面。**

### ④ 帧内居中不变量（`S3`）—— 2026-09-21 新发现（engineering-lead 探针 A）

**发现**：16 个 `u_*_map` 的剪影 **bbox 中心 = 13.5–24.5**，而 52 宽帧的像素中心 = **25.5** ⇒ **普遍偏左 5–12px**。按 `ax = (32−52)/2 = −10` 画，可见像素**只往左越界、最大 10px，右侧 0**（左右不对称）；`normalizeTier` 开/关两态都偏左。

**根因**（本档自核 `unitArt.ts` 归一化落点）：`destX0 = round(cx − destW/2)` 把缩放后的本体**锚在「本体原中心 `cx`」**，而 `cx` 来自 **32 宽时代**的绘制坐标（≈16）—— 帧加宽到 52 后**没有重新居中**。⇒ **与 R-5 同类：尺寸变更留下的静默残留**（改一处、别处不响）。

**裁定：走 (a) 重新居中；不接受 (b) 逐帧 `ax`。**
- (b)「以剪影中心逐帧定 `ax`」= **手凑 16 个数**，正是 §5.6.5 第 3 条 / D-71 明确否掉的手法，且直接违反 §8.5「`ax` 由公式导出」。
- (b) 只**掩盖**缺陷：帧本身仍不是居中构图 ⇒ **下一次加宽（或 T5）原样复发**。
- (a) 修在**共享层**：归一化的水平落点锚到**帧中心** `(pb.w − destW)/2`，一处覆盖全部 48 帧，**非手改 16 个 `drawXxx`**。

**须同时成立两件事**：
1. **横向落点改锚帧中心**（`normalizeTier`）；非归一化路径的原始 `drawXxx` 坐标同样需重居中，但**出货路径是归一化态**，故优先级低。
2. **补断言 `S3`** —— 这是**唯一能拦住下一次加宽复发**的机制。

> **`S3`（新增，硬）**：每个精灵帧**归一化后**的剪影 **bbox 水平中心 = 帧中心 `w/2`**（52 宽 ⇒ 像素中心 **25.5**），容差 **±1px**。它与 `S2`（高宽比）**正交**：`S2` 保证「剪影**不超宽**」，`S3` 保证「剪影**在帧里居中**」。**两者缺一，`ax = −w/2` 都不落在格 / hex 中心。**

**待确认（问 engineering-lead）**：**cu 帧（44 → 64）是否同病**。若原始 cu 本体中心 ≈22（44 宽时代）而帧中心 = 32，则 `ax = −w/2 = −32` 同样把战斗单位推左 ~10px。现有 `H1/H2/S1` 只测**体量**，测不出**横向居中** ⇒ 请把探针 A 扩到 cu 帧（16×`cu_*` + 16×`cu_*_atk`）。

**一个边界（不设例外）**：p2 楔形前倾 / p4 悬浮晶体等**非对称队形**不需要例外 —— `S3` 是对 **bbox**（含全部可见像素）居中，非对称是**在居中 bbox 内部**表达。只有当某单位的**接地轴**必须偏离 bbox 中心时（例如武器在单侧拖地），才需**具名**记录该偏离，而不是给一个静默的数。

## 0. 结论

**§5.6.1 定义的两条正交通道里，Tier 体量通道在当前实现中并不存在。**

20 格矩阵的**纵轴**（「这是几级兵」）在**四族全部塌掉**：

| 判定 | 结果 | 规格要求 |
|---|---|---|
| 跨族「高 tier 反而更小」的等级倒挂对 | **35 / 120 对（29%）** | **0 对** |
| 四族体量阶梯严格递增 | **0 / 4 族** | 4 / 4 |
| 每族阶梯跨度 | 19.6 / 19.6 / 8.9 / 10.7 pt | ≥ 26 pt |

最严重的一对：

> **翠林 T3 藤蔓卫士 55.4%  <  晨曦 T2 号角弩手 82.1%**（−26.8pt）
> —— 一个三级兵，比别的族的**二级兵**小掉四分之一还多。

**这不是配色问题，也不是盲测运气问题。** `cartoon-style.md §5.6.5` 第 3 条把这个失效模式**逐字预言了，并且举 p3 为例**：

> 「如果某族的形状刚好在某些 tier 上『吃掉』了体量差（**比如 p3 的矮宽 T5 比 p1 的瘦高 T4 还小**），要回去改体量，不要改形状。」

实测确认：**翠林（p3）就是那个把体量差吃掉的族** —— 它的四档体量挤在 55.4%–64.3%（跨度 8.9pt），是四族里最平的。

按 §5.6.5 的处置表，本情形落在「**70–90% → 修体量**」一档（而非「<70% → 回退换皮」）。**修法是改体量，不是改形状**（第 3 条原文）。

## 5. 根因（已确证，非推测）

`homm-web/src/render/unitArt.ts`，**2153 行，16 组 bespoke 绘制函数**：

```
function drawLampbearerMap(pb: PixBuf): void { … }
function drawLampbearerCombat(pb: PixBuf, atk: boolean): void { … }
function drawScavengerMap(pb: PixBuf): void { … }
… 共 16 单位 × 3 帧
```

```bash
$ grep -cE "tier|TIER|体量|volume|volScale" src/render/unitArt.ts
2          # 且这 2 处只是文件头注释里的「§5.6 逐 tier 剪影矩阵」字样
```

**每个单位的坐标是手写的常量，函数签名里没有任何 tier / 体量参数。**

于是：

- **Faction 通道（横轴）被实现了** —— 每单位独立画，形状确实按族分化（审计也证明 p3 的形状通道全合规）。
- **Tier 通道（纵轴）根本没有被实现** —— 每个单位画多高，是画的时候随手定的，没有任何东西约束它必须落在 §5.6.2 的那一档上。

**这正是 `asset-spec.md` §4.2 R5 / §9 里 ×4 之所以要求「全部走程序化」的原因** —— 程序化的价值在于「同一套骨架 + 参数化形状家族」能**保证** 4×5 正交成立。当前实现拿到了「程序化」这个手段，却没拿到它要保证的那个性质：**画得是程序化的，但矩阵是手凑的。**

## 6. 修法（§5.6.5 第 3 条：改体量，不要改形状）

### 6.1 第一步：把主观盲测变成机械前置 —— 先补断言

当前 `b0audit.mjs` 的 8 条断言全部关于**颜色 / 描边 / 基线**（色板归属、ΔL*、描边干净、脚底行），**没有一条关于剪影矩阵本身**。而剪影矩阵恰恰是 ×4 花 4 倍成本要买的那个东西。

必须补的断言：

- **硬（不依赖容差）**
  - `H1`：四族各自的 T1→T4 体量**严格递增**，且最小步长 ≥6pt。
  - `H2`：跨族 tier 倒挂对 **= 0**。
- **软（用自设容差，可调）**
  - `S1`：每族每 tier 落在 §5.6.2 目标 **±3pt**（原拟 ±8pt，经 `§7①` 裁定收窄 —— ±8 会让相邻档接受带**重叠**、判不出帧属哪档；落地值见 `b0audit.mjs` 的 `S1_TOL`）。
  - `S2`：§5.6.3 高宽比合规，**分两层执行** —— (a) **槽位安全下界（硬）**：比值 ≥ `槽位高 ÷ 槽位宽`，`cu = 56/64 = 0.875`、`map = 44/52 ≈ 0.846`（**低于即超宽、必被硬裁**）；(b) **族识别带（软）**：p1≥1.25 / p2∈[0.85,1.15] / p3≤1.1 / p4≥1.35。⇒ **p2 取值 = 下界 `cu ≥0.875` / `map ≥0.85`、上界 1.15**（下界取 (a)，上界取 (b)）。原 S2 只查「≈1.0」的软带、**未把下界当槽位安全约束**（D-73 病根）。
  - `S3`：**帧内居中不变量**（见本文件 **★「D-73 加宽槽位复核」④**）—— 归一化后剪影 **bbox 水平中心 = 帧中心 ±1px**（`±1` 只为吸收奇偶取整；越界即硬问题）。与 `S2` **正交**：`S2` 管「剪影不**超宽**」、`S3` 管「剪影在帧里**居中**」。**两者缺一，`ax = −w/2` 都不落在格 / hex 中心。**

> ★ **执行纪律**：这条断言必须**先跑红**（证明它测得出当前的 35 对倒挂），**再**改代码让它变绿。
> 这正是本项目已验证过的方法 —— 「先试哪一处改动能让断言变红」，只有真病根被停用才会红。

### 6.2 第二步：体量归一化，且必须插在描边 pass **之前**

不要在 16 个 `drawXxx` 里逐一手改坐标（那是复现同一个错误：**又变成手凑**）。要加一个**共享的后置步骤**：

```
绘制本体 → 【体量归一化：按 tier 目标把剪影缩放到目标高度】 → 描边 pass → 交付
```

**为什么必须在描边之前**：`b0audit.mjs` 的断言 4「描边重跑干净」实现方式是「透明像素填成 ink0，即一圈 1 次膨胀」—— 说明**描边是后置生成的一圈膨胀**。把缩放放在它之前，描边就是在**新的剪影边界上重新生成**的，仍然 1px 单线。

**若放在描边之后**，缩放会把那 1px 描边插值成灰边 / 2px 断点 ⇒ **断言 4 必红**。这一点请在实现时作为硬约束。

### 6.3 两个画布都要归一到各自的目标

- cu 帧（44×56）：§5.6.2 的表就是为它写的，直接用。
- map 帧（32×44）：**§5.6.2 没写地图画布的目标**。但盲测表用 map 帧 ⇒ 必须在 map 画布上**建立同构的阶梯**（建议按同一比例，或按 §5.6.2 的 px 目标值等比换算）。**这一条需要 art-director 确认**，见 §7。

### 6.4 顺序：先修体量，**再**做 B3（T5）

T5 = 100%（56px，允许向上溢出 4px）—— 它是整条阶梯的**锚点**。若先做 B3，T5 会照当前的（错的）基准画，阶梯定稿后必须重画。**所以 B3 暂缓。**

## 8. 与 R-1 的关系（为什么这不是「又发现一个 bug」）

`asset-spec.md` §4.2 的 **R-1** 写的正是这件事：

> ⚠️ **R-1 形状家族只在 T5 成立** → ×4 退化为「四套换色 + 额外帽子」，4 倍成本换 0 增量可读性
> **缓解**：B1 之后立刻做 20 格盲测；命中率 < 70% → 回退共用换皮，**止损在第 6.5 人日**

**R-1 的缓解措施（B1 之后的盲测）没有按期执行，一路做到了 B2 四族齐。** 本次审计补上了这一步的**机械部分**，结果指向 R-1 描述的失效：

- 形状通道（横轴）**成立** —— 四族的形状家族确实分化了，不是「换色 + 换帽子」。
- 体量通道（纵轴）**不成立** —— 纵轴塌了，20 格矩阵在纵向上退化成 4 格。

⇒ 现状是「**形状对了、体量没做**」，而不是「四套换色」。**这是可以修的**，且修法已由 §5.6.5 第 3 条给定（改体量）。**但若不做，×4 的增量可读性确实接近 0** —— 因为玩家认不出 tier，剩下能认的只有族。
