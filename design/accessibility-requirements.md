> ## 0. 一句话
> **本项目目标档 = `Standard`（L2），并额外拉入 2 项 AAA 级**（焦点外观 2.4.11、触控目标 2.5.5）—— 手机上这两项成本近乎为零、收益最大。
> **本文档是 a11y 的唯一权威基线**：任何 UI 规格（含 `in-game-ia.md`）**不得各自重申 a11y 规则**，只能**引用本文档的分级**（如「满足 L2 + 本文档 §4.1 焦点口径」）。
> **a11y 是基础要求，不是锦上添花。**

## 1. 分级定义（4 级）

| 档 | 名称 | 一句话 | 基线 |
|---|---|---|---|
| **L1** | **Basic** | 「能用」——不出现阻断性障碍 | WCAG 2.1 **A** 中与游戏相关的子集 |
| **L2** | **Standard** ✅ **本项目目标** | 「能用得舒服」——主流残障场景可**独立**完成核心循环（探索 + 经营） | WCAG 2.1 **AA** + 游戏适配（触控 / 色盲冗余 / 读屏标签 / 减少动效） |
| **L3** | **Comprehensive** | 「深度可配置」 | L2 + 选定 **AAA**（焦点外观 / 44px 目标 / 关键文本 7:1）+ 可重映射 + 字幕自定义 |
| **L4** | **Exemplary** | 「面向辅助技术深度集成」 | L3 + 全键位重映射 + 认知辅助 + 完全冗余提示 |

> **为什么要分级而不是「一档搞定」**：分级让**每份 UI 规格的验收可判定**（「这个按钮满足 L2 的 2.5.5 吗？」），也让**成本可预算**（每上一档要付什么）。没有分级的 a11y 只能变成一堆互不引用的散装规则 —— 这正是 D-39 要根治的病。

## 3. 本项目目标档与「额外拉入」的理由

| 项 | 决策 | 理由 |
|---|---|---|
| **基线** | **L2 Standard** | 覆盖 ~8% 男性红绿色盲、老年低视力、触屏误触三大主要场景，成本可控 |
| **额外 #4 焦点外观 2px** | **拉入** | 现状**已有单点缺陷**（1px，见 §4.1）；统一 `:focus-visible` 是一次改、长期受益，成本 ≈ 0 |
| **额外 #6 触控 44/48** | **拉入** | 真机实测 **p90 = 23px** 落点散布（`in-game-ia.md §5.1`）→ 40px 宽按钮横向余量仅 1px；44/48 是**可用性刚需**，非锦上添花 |
| **暂缓 #14 可重映射** | 不进 L2 | 本作触屏优先、无复杂键位；待有键盘/手柄需求再评估 |

## 4. 已发现的实项（D-39 收编 · 逐项带代码证据）

> 证据口径：`git grep` / `rg` 于 `homm-web/src/`。定位一律用**符号 / 选择器 / 关键字**（**不写行号** —— 行号是「会腐烂的坐标」，见 `production/roadmap.md` **D-52**）。

### 4.1 焦点可见性 —— 「对比达标、厚度不足」

| 项 | 内容 |
|---|---|
| **现状** | 全项目**只有一条** `:focus` 规则：`style.css` 的 `.ss-field input[type='text']:focus { outline: none; border-color: var(--gold); }`。焦点指示 = 把默认 `1px` 边框从 `--frame` 换成 `--gold`，**厚度不变（1px）**，并**移除了** outline |
| **量化** | `--gold #f0d488` vs `--frame #8a6a34` → 对比 **≈ 3.5:1**（≥ 3:1 ✅）；厚度 **1px < 2px** ❌ |
| **判据** | **2.4.7（AA）本身满足**；不满足 **2.4.11（AAA 焦点外观）**。即「**对比达标、厚度不足**」 |
| **补充事实** | 60+ 按钮**没有自定义 focus 样式** → 现靠浏览器默认 focus ring；`outline:none` **只加在输入框**、**未全局清除** → 属「**未统一**」而非「被删光」 |
| **处置** | 加全局 `:focus-visible { outline: 2px solid var(--gold); outline-offset: 2px; }`（或与既有输入框规则统一，避免两套）。**归属工程**（`style.css` 单写者 = engineering-lead），时机 = UI 重构批 |

### 4.2 既有 emoji 的读屏播报不一致

| 项 | 内容 |
|---|---|
| **现状** | `HUD.ts` 的 `muteBtn` `🔇` / `🔊`（音效）、`lightBtn` `🌗` / `☀️`（光照）。读屏（TalkBack）**播报各家不一**：有的念「静音 / 扬声器」，有的直接跳过，有的念错；`☀️` 含变体选择符 **U+FE0F**，部分平台渲染成缺字框 □ |
| **判据** | 违反 **4.1.2（名称-角色-值）**；且 emoji 全彩 / 抗锯齿 / 尺寸随 OS 变 → 违反 `cartoon-style.md §3.2 色板 / §1.1 描边 / §1.3 整数缩放`（= **G-17**） |
| **处置** | ① 换**图集精灵** `ic_sound_on/off`、`ic_light_on/off`（**已登记** `asset-spec.md §2.3.1`）；② 每个按钮补 `aria-label`（如 `aria-label="音效"`、`role="switch" aria-checked`）。时机 = UI 重构批（与 setup 搬迁同片 DOM）。**归属 = 美术出帧（已登记）+ 工程接线** |

### 4.3 图标不得为唯一语义载体（+ `aria-label`）

| 项 | 内容 |
|---|---|
| **现状** | 顶栏资源项是「**图标 + 数字**」（`HUD.ts` 资源项 `icon.src = atlas.url(\`ic_${k}\`)`），**无 `aria-label`** → 读屏只念出一个孤零零的数字。**`src/` 全目录 `aria-label` 数量 = 0**（`rg` 证据） |
| **判据** | **4.1.2 / 2.5.3** |
| **处置** | ① 「图标 + 数字」项：`aria-label="<资源名> <值>"`（如 `aria-label="金币 12"`）；② 图标按钮**必须有文字标签或 `aria-label`**；③ 拇指带已是文字标签（`in-game-ia.md §4.4 / Q10`）→ **天然达标**，仍建议补 `aria-label` 覆盖缩写（如「日志2」→ `aria-label="事件日志，2 条未读"`）。时机 = UI 重构批 |

### 4.4 触控目标（vs 实测 p90 = 23px 落点散布）

| 项 | 内容 |
|---|---|
| **现状** | 真机实测：误触 0/8，但**落点偏差 p50 = 13px / p90 = 23px**。最小 `宝物▾` = **40×32**（半宽 20px，手指落 19px 处 → 横向余量 **1px**） |
| **判据** | **2.5.8（AA，24px）** / **2.5.5（AAA，44px）**。本项目取 **≥ 44（常规）/ ≥ 48（主操作）/ ≥ 40（密集区，且相邻按钮间距足够）**（与 `in-game-ia.md §5` 一致） |
| **处置** | 尺寸批已把 `.btn.tiny` **32 → 40**（commit `028ec4a`）；其余按 IA §5。⚠️ **判定口径**：`.btn.tiny.tap::after` 用负 offset 扩**点击热区**（仅垂直向）——扩的是**热区**不是**可见尺寸**；对 2.5.5 的判定**以热区为准时 OK、以可见为准时不足**，验收时须写明用哪一种 |

### 4.5 减少动效 / 无高频闪烁

| 项 | 内容 |
|---|---|
| **现状** | **`prefers-reduced-motion` 在 `src/` 中数量 = 0**（`rg` 证据）；现有动画均为 **≤ 4 帧循环**（低闪），**无高频闪烁** |
| **判据** | **2.3.1（三次闪烁）/ 2.3.3（交互动效）**；本项目动效均为低幅（±1px 整数位移 + `squash & stretch`） |
| **处置** | 补 `@media (prefers-reduced-motion: reduce)`：关掉 idle 浮动、缩短面板过渡（**不改整数位移本身**，那是可读性手段）。**归属工程** |

### 4.6 色盲 / 灰度（色板硬约束，引自 `cartoon-style.md §7`）

| 约束 | 值 | 归属 |
|---|---|---|
| 灰度可辨 | 4 族明度台阶相邻差 **≥ 12 L\***（= §2.4 明度签名） | 美术（色板） |
| 色盲可辨 | **禁止**靠 p2 红 / p3 绿的色相差传递**唯一**信息；每族同时具备**形状母题** | 美术（§5 母题是形状） |
| 战斗队伍辨识 | 队伍色环（`cbase_*` 蓝 / 红）对红绿色盲失效 → 建议**形状区分**（我方圆环 / 敌方方环或带缺口） | 美术 + 工程 |
| 光照可关 | `lightLayer.ts` 已有 `lightingOn()` ✅ | 工程（保留 + 设置面板暴露） |
| **地图可达染色（④）** | 见下方专段。**归 §2 #2（1.4.11，信息承载描边）+ §2 #10（1.4.1 冗余）** | 美术（色）+ 工程（常量） |

> **④ 地图可达染色的 a11y 判定（2026-09-21 · 触发：`engineering-lead-2` 实测「纯色相线索、灰度 ~1.1–1.4:1」并问 scope）**
> - **在范围内**；SC 归属 **= §2 #2（WCAG 1.4.11 非文本 3:1）+ §2 #10（1.4.1 非色彩唯一）**。
>   ⚠️ **本行 2026-09-21 归一**（原写「归 #10、**不归 #2**」，与 team-lead 裁决冲突 —— `ux-ia` 报、`68abf37`）：**1.4.11 的 3:1 适用** —— 可达 / 不可达是**信息承载的 UI 元素**（不读它下不了令），**不是画面层**（team-lead 裁定 · `in-game-ia.md §15.4` / `6bb923c`）。
>   **但"量的对象"要分清**（这是原写法的正确内核，保留）：3:1 量的是**承载信息的"边界描边" vs 其相邻色** —— 描边的相邻色**是确定的**（线两侧那两格地形），**不是**"半透明整格填充 vs 无界地形"。**蓝填充**只是**冗余"区域水洗"**（色觉正常者读得到；色觉障碍者另有描边兜底）⇒ **不单独套 3:1**。⇒ 两条不矛盾：**3:1 打"描边"、不打"填充"**。
> - **判据**：可达 / 不可达**两态在灰度下彼此可辨** —— 量化锚在 WCAG 1.4.11 的 **3:1**（量「状态 vs 其底」），**不套**「vs 无界地形 3:1」。量化首选 **A/B 口径**（同像素同地形、只差染色层，见下），空间口径作旁证。
> - **现状 = FAIL**（`engineering-lead-2` 真 Chrome CDP，seed 20260917；**两个口径都记，量化锚用 A/B 口径**）：
>   - **A/B 口径（首选锚）** —— 染色开/关、**同页同相机、同像素同地形**，只差染色层（**去掉"被染区恰好是亮地形"的混淆**）：**WCAG 对比度中位 1.15(午) / 1.12(夜)**，max 2.93 / 2.43，**≥3:1 的像素 = 0.0%**；染色占屏 **19.4%(午) / 19.3%(夜)**。
>   - **空间口径（旁证）** —— 真实被染格 vs 紧邻未染格（钩子记录被染集、不靠猜）：**被染蓝 vs 未染底 1.74(午) / 1.53(夜)**；**红格缘 vs 未染底 1.18(午) / 1.12(夜)**；逐对 **min 1.00**（有格完全分不开）。

>   - **复算对照（`engineering-lead-2` 直连口径，与上同量级）**：蓝 **1.14** · 红缘 **1.05** ⇒ 与 A/B 口径（1.15 / 1.12）**同量级、差在口径**。**以本节为全仓唯一权威数**（`in-game-ia.md §15.4` 已指向本处、不另存第二份）。

> ### ★ 两条 a11y 裁定（2026-09-21 · 应 team-lead 请裁；**裁定权在本文档**）
>
> **(a) 夜间是否仍以 WCAG 3:1 为判据？ —— 是：判据不随相位变，夜间不豁免、不降尺。**
> - **1.4.11 无「夜间」豁免**：它管的是**渲染出来的状态**的可辨性；夜间是渲染结果的一部分，**不是**另一种可豁免的呈现。
> - **降夜间尺 = 正被禁的「调到达标」**（`production/roadmap.md` `bd4ebb0`）。若因夜间过不去就把夜间阈值降到能过的水平，等于绕开与 `a35f923`（阈值必须与所守护代码同构建）同源的纪律。
> - **`ΔL* 16.8` 与 `1.56:1` 不矛盾、也不互替**：前者是「**看得出**」（感知量），后者是「**达不达标**」（规范量）。按 `3f11752`（尺子必须与要回答的问题同维度），**判据仍是 WCAG 3:1**；`ΔL*` 只作**旁证列**，**不能顶替 1.4.11**。
> - **⇒ 夜间墨线对草地 ≈ 1.56:1 时，「夜读 FAIL」如实成立**（与我 V1.2 的 **1.12(夜)** 同向；(α) 已改善但仍不足）。**不换尺子、不叠下一层。**
>   - **⚠️「不叠下一层」禁的对象（写死，防误禁标准技法）**：禁的是「**为凑一个标定值而叠加的装饰性色层**」（= `5.09` / 「调到达标」那一类）。**不在禁列**：(a-1) 的 **双色 halo（亮芯 + 暗边）** —— 它是**同一个「边」语义载体**在**两个底色方向**上各给一条，**不是两层装饰**（1.4.11 本就要求对**两侧**相邻色**各** ≥3:1）。⇒ **判 (a-1) 可做，不算"叠层"。**
> - **处置（要求，本轮不实现）**：④ 是**信息层**，不该被氛围层调暗。三条路：
>   - **(a-1) 「双色 halo（亮芯 + 暗边）」【推荐】** —— 原写「相位感知描边」，2026-09-21 按 `ux-ia` 提法**归一命名**（同 = team-lead 的 **(ii)**，勿再当两套处方）：**边界同时给亮芯 + 暗边**，使描边对**亮底与暗底各自 ≥3:1**（暗底吃**亮芯**、亮底吃**暗边**）。**成本小**（④ draw 块再画一条更亮的线）；归属 `MapRenderer.ts`（engineering-lead）。
>     - **为什么主句必须是"双色"而不是"整条换亮色"**（`ux-ia` 指出 · 我按**绑构建读数**确认）：**同一相位内"极亮底"与"极暗底"同时存在** ⇒ **整条换成任何单一颜色，必把其中一类留在失败侧**。实测（见 §4.6 状态行）：单条暗墨在**亮底过**（沙/土 **8.98**）、**暗底败**（草·深 **2.33** / 暗 1.16 / 夜 **2.08**）⇒ **"整条换亮色"只会把失败从暗底挪到亮底**（= team-lead 判 (i)「换极性」为伪修法的同一逻辑）。⇒ **必须双向。**
>     - **「相位感知」降为可选增益**（按相位微调亮芯亮度或可让某侧更稳），**不靠它救夜读**。
>   - **(a-2) 让 ④ 免于 `applyLighting` 的 multiply 【不推荐】**：④ 画在**世界坐标**、光照是**屏幕空间**且在**实体循环之后**（源码注释已写明）⇒ 搬到光照之后会**既错坐标、又盖住单位**。
>   - **(a-3) 不修、如实记 FAIL**：`#15 光照可关` 仅作**缓解**，**不是** 1.4.11 的合规替代（1.4.11 没有「关掉功能即合规」的机制）。

> **(b) 「全色相」是否构成 1.4.1 失败？墨线的「边界形状」够不够当非色兜底？ —— 不构成失败；(β)/(γ) 都不需要。**

>   1. **形式腿（面 vs 边）**：可达 = 整格**面**水洗（`REACH_TINT`）；不可达 = 只在**邻接可达区那一侧**画**线**（`NOGO_EDGE` + `NOGO_EDGE_INK`，`EDGE_W`）。灰度下「一片被洗过的**面**」与「一条**暗边**」是**结构差**，与色相无关。
>   2. **明度腿**：外侧墨 `#2a1a12` **不透明** ⇒ 自带明度分量（= (α) 的贡献）。
> - ⇒ 「纯色相线索、灰度 1.1–1.4」这句**只对「水洗」那一半成立** —— **这正是 (α) 把明度锚改打在「边」上、而不再加在「填」上的原因**。把「水洗灰度低」读成「整个编码色相唯一」，是**把半个线索当了全部**。
> - ⇒ **1.4.1（非色彩）满足**（形式腿**相位不变**）。**不要 (β)**（可达侧也描格缘：格缘本身无亮度分量，与 (a) 同病，**解决不了夜读**）；**不要 (γ)**（点纹 / cost 数：最稳但**改管线**、伤观感，**留备选** —— 仅当 (a-1) 仍推不到 3:1 才上）。

## 5. 验收口径

**可机检（自动化，进既有探针批）**
1. **UI 壳**对比度：前景 / 背景对 ≥ 4.5:1、非文本（图标 / 边框 / 焦点）≥ 3:1（抽查木框 + 羊皮纸配色，`cartoon-style.md §7` 已提示可能不足）。**地图覆盖层**：**可达性「边界描边」套此 3:1**（WCAG 1.4.11，量「描边 vs 其相邻色」）；**蓝填充是冗余水洗、不单独套**（见 §4.6 专段）。
2. **无 emoji 当图标**：`rg "🔇|🔊|🌗|☀️" src/` 应为 0（G-17 防回归）；图标**只来自** `atlas.url()`。
3. **每个 `.icon` / 图标按钮有可访问名**：`rg 'class="[^"]*icon'` 的每处须有 `aria-label` 或相邻文字。
4. **焦点环厚度**：`focus-visible` 规则存在且 `outline-width ≥ 2px`。
5. **减少动效**：存在 `@media (prefers-reduced-motion: reduce)` 块。
6. **无全局 `outline: none`**（除已声明的受控例外）。

**手检（真机走查）**
7. 键盘 / TalkBack 走查：顶栏（图标 + 数字）、拇指带（文字标签）、setup（音效 / 光照开关）—— 逐项播报**有意义**且**不重复**。
8. 焦点环截图（≥ 2px、金对棕 ≈ 3.5:1）。
9. 文本缩放 200%：不裁切、不重叠。
10. 色盲模拟（灰度 + 红绿）：4 族可辨、队伍可辨；**地图可达染色两态在灰度下可辨**（可达 vs 不可达 ≥ 3:1，**判据全天候含夜、不随相位放宽**，判据与现状见 §4.6 专段 + 裁定 (a)/(b)）。
