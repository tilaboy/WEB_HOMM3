# M9 · 会生长的城市场景（HOMM3 观感重画，2026-11-19）

## 结论

城镇面板的「城内一览」已从旧版 8×3 固定网格**直接替换**为会生长的城市场景：16 座建筑按 80×80 逐笔重画，四族各有**结构不同**的空城底子（石堡山丘 / 火山营地 / 巨树 / 神殿），**只有已建的地块放建筑**，未建地块留一圈浅地基，按地块 y 做深度排序。每建一座，城里真的多一座。

本批按三点拍板执行：① 16 座全量重画；② 四族各自底子；③ 直接换掉旧网格，不并存两套视图。

## 为什么重做旧版

旧版把 44px 建筑用 `Scale2PixBuf` 做成 88px 大图，再塞进 8 列 × 3 行网格。它证明了"能一览"，但观感是一张**建筑清单**：16 座从开局就全在画面上，未建只是灰像，建与不建的区别只是透明度；四族底子也只换配色与太阳位置。用户要的是 HOMM3 那种"光秃秃的山上慢慢长出城市"，因此这次改的是呈现模型，不是调色。

## 关键取舍

1. **建筑结构四族逐像素相同，材质才换色**：沿用 B1 建筑帧的口径，16 种形状只画一次；族差异由材质 + 底子承载。S1/S2 分别钉住"结构同"与"材质不同"。`wall1` 初版四族均值色只差 0.4（木栅本体同色、阵营色面积太小），改成尖桩顶面 + 一道宽的阵营漆带后才分开。
2. **底子要结构不同，不是换天空色**：S4 用亮度梯度掩码量边缘，四族两两 IoU 0.191；`sameBase` 负向臂让四族都画 p1 ⇒ IoU 1.000。这样"四张底子不同"不是靠人眼印象。
3. **升级必须改剪影**：L2/L3 加宽石台基（80px 画布上 L3 能占到 x=0..79），16 座 L3 面积全部大于 L1；不是往同一张里加内部像素。
4. **空地画地基，不画灰色未来建筑**：未建 10 块共用一张程序化地基，统一淡显；点它出详情和建造按钮。这样"哪里能长东西"可见，又不会提前剧透形状。
5. **两套规则不许分叉**：城景点击与建筑卡共用 `buildStatus()` / `build()`，价格、解锁、每日一次都不另写。
6. **触屏可读**：详情按钮上直接写「建造 / 升级」，禁用原因 inline 在 `.cv-why`，不靠 hover 的 `title`。

## 读数

`node tools/probes/townview.mjs --gate` → **rc=0**，S0–S4 / N0 / N0b / U0–U8 / N1–N3 全过：

- 美术：64 张 80px；四族结构差 0、材质色距全部 ≥6；16 座 L3 面积全大于 L1；四底子边缘最大 IoU **0.191**。
- 接线：城堡 + 16 地块；built **6** / unbuilt **10**，建筑帧 6、地基 10、错画 0；深度排序正确、`outside=0`；5 座 `_u3` 上屏；背景按舞台实际像素 **832×275** 绘制。
- 交互：点已建出名字 / 大图；点空地选中地基出「建造」按钮。
- 负向：`sameShape` 建筑 IoU 1.000；`sameBase` 底子 IoU 1.000；`devtownview=0` 入口与城景都消失；本门同时保留英雄页签 `devhiretab=market` 与存量转换 `devnoconvert=1` 两对负向臂。

## 边界

- 仍是固定地块布局，不做 HOMM3 式可拖动连续地图；16 座全放满后也不会互相挤掉。
- 底子是程序化色块场景，不引用概念图；四族差异在底子结构 + 建筑材质，不在地图世界地形。
- 城景不新增第 6 个标签页，R4「每页纵向可点行 ≤5」不变。
- 本批只改呈现，不改经济、战斗、存档结构；存量转换仍是上一批的决策 59 规则。
