# M9 · 城景美术第二版：从“建筑清单”改成“一座城”（2026-11-19）

## 用户反馈与结论

第一版把 16 座摆进场景后，实拍得到一句直接的批评：**“所有建筑风格都没什么差别，都是一个小圆尖顶；整个城镇看起来也不像城镇。”** 这个反馈是对的：16 张里有 12 张是“米色方盒 + 蓝色三角屋顶”，画面也没有街道、广场、城门和前后关系。

第二版按两条线重做：

1. **单体：按建筑原型重新设计剪影**，不再共用一套尖顶模板。
2. **整体：先搭城市骨架**——城堡远景、城墙塔楼、城门、主干道、中央广场、喷泉、支路、路灯——再让建筑沿街按远/中/近三档落位。

第二轮实拍又得到一条批评：**“整体好看很多，但所有房都是蓝房顶、白房墙，略显单调。”** 这条也对：上一版虽然轮廓分开了，但材质仍是一族一色，同一座城里 16 座共享同一个屋顶色。于是补了第三轮**建材分化**：每座建筑一套材质，阵营色退成旗、饰带、窗光与轻微偏色（屋顶 22%、墙 8%、石/木 38%），既能在一城里看到红瓦、茅草、石板、砖窑、铜绿和水晶，也仍能看出是谁的城。

## 第四轮：城堡与落地（自查，2026-11-19 晚）

第三轮交付后把实拍放大自查，发现两处比配色更伤观感的问题，都不是用户提的，但一眼就能看见：

1. **中央城堡是一整块灰墙开个黑洞。** 它是画面里面积最大的东西，却最没有设计——没有收分、没有城垛、没有门楼，只有一扇黑拱门。现在改成：幕墙（城垛 + 箭孔 + 两面色旗）、四座锥顶角塔、**三层收分主堡**（每层各自明度台阶 + 砌石横缝 + 城垛暗带 + 箭孔 + 亮窗）、两条垂旗、顶收两座小角楼、门楼（拱券 + 闸门栅条 + 门洞火光 + 带托架的火把）。三层收分第一版还画错过一次：三段都铺到墙根，后画的一段把前一段整段盖掉，收分变成一个方盒子——必须每段只画到自己头顶为止。
2. **每座房子都浮在同一块灰石板上。** 旧 `base()` 给每座画一条同宽石板，16 座排成三排横线，读起来像模型摆在托盘上。改成：地面暗部与投影**放到 `outline()` 之后画**（先画会被描边圈成一圈墨线，还是"板"），宽度跟着每座实际落地宽度走，方向朝左下（月光在右上）；地面只留两簇草咬碎边缘。
3. 顺带修掉：**压在城门前的第二座城堡**（DOM 里原来还塞了一张 `buildCastleFrame` 小图，底子有了主堡之后就成了两座城叠在一起）——改成透明热区，点它仍出「城墙」详情；**未建地块被选中时那个悬空方框**（`outline` 沿 `<img>` 盒子画，空图就是一个空框）——改成地面短横线 + 金色辉光；**路面一族一块米色**（铺在火山黑土和紫色神殿地上像贴上去的沙盘）——按族调色并加铺石纹理；**熔岩裂缝一根细红线**（读成涂鸦）——改成岩唇 / 熔岩 / 高光三层。

## 第五轮：让城“活着”（动画，2026-11-19）

第四轮交付后城景已经“像一座城”，但整幅画面是死的：旗不动、烟不升、水车不转、喷泉不喷。HOMM3 的城景之所以耐看，很大一部分是这些**便宜的循环动效**。用户说“继续”，这一轮就做这个。

### 做法：8 帧离线动画，浏览器只换图

| 决定 | 理由 |
|---|---|
| **8 个相位 × 170ms（≈5.9fps）**，一次 1.36s 循环 | 像素画不需要 60fps；5.9fps 已经能读成“在动”，再把频率提上去只是让手机一直解码 |
| 每帧都是**从头 build 一遍**（`buildSceneBuilding(owner,id,tier,phase)`） | 不会出现“上一帧的辐条留在原地”的残影；也让闸门能在 Node 里逐帧量 |
| 底图**不整帧烘 8 份**，只烘一次；动的部分走**独立特效层** | 832×275 一张 RGBA 就 0.9MB、p1 山丘底子一次 12ms，8 张 = 7MB + 常态卡顿；特效层每帧只重画十来个几十像素的精灵 |
| 特效层放 **`.tv-fx`**（底图之上、地块之下），DOM 结构与点击区一帧都不动 | 动画不该让 16 个 `<button>` 重建；U3 直接判“16 块地还在、点已建仍出详情” |
| `prefers-reduced-motion: reduce` 直接停 | 尊重系统设置，不做第二个开关；`?devtownanim=0` 只给闸门当负向臂 |

**动的（8 座 / Lv.1）**：酒馆（烟）、市政厅（旗）、工坊（烟 + 水车 + 炉火光晕）、三阶城墙（旗）、旗柱（大小两面旗各按自己的相位飘）、农舍（烟）、庄园（旗）、水晶塔（四粒光尘绕晶体转）。
**不动的（8 座）**：市场、木栅、石墙、长屋、排屋、柱廊宅、两座行会 —— 闸门把“它们必须零帧差”写成判据，这是脚本自带的负向对照。
**Lv.3**：16 座全部有冠旗，16/16 有动效。

### 这一轮自己看出来的两个缺陷

1. **8 座建筑的“升级冠旗”悬在半空。** `tierCrown` 原来是“给一个 y，画一条 24px 横杆 + 一面旗”，横杆在尖顶/穹顶上必然悬空（×4 对照表里就是八块插在空中的招牌，闸门量不到这种错）。改成：**按列从上往下找最高实体像素**当杆底，杆必须落在屋顶上。顺带删掉那条横杆。
2. **工坊烟囱顶在 y=8，烟只有 4px 可升。** 第一版烟是“等距 4 团”，逐帧看 topY 是 5,8,5,8 —— 第 k 帧和第 k+2 帧是同一组烟团，只是换了画序，读起来像原地蹦。改成非等距相位 + 两端淡出，并把烟囱降到 y=18（留 16px 烟道）。

### 两个渲染陷阱（都用负向臂钉住）

- **半透明特效必须画在 `outline()` 之后。** 描边把所有 alpha>8 的像素都算进剪影，先画烟会被墨线圈成一个灰泡泡。负向臂 `fxBeforeOutline` 把烟区墨色像素从 **0** 抬到 **423**。
- **水车转 90° 只有 4 种姿态。** 8 根辐条对称周期是 45°，一轮转 90° = 两个对称步 ⇒ 第 1 帧和第 5 帧长得一样，而且 265°/s 快得像风扇。改成一轮 45°，8 个相位各自站位不同。

### 读数（`node tools/probes/townanim.mjs --gate` → rc=0）

- **[A0]** 8 相位 × 16 座 × 4 族 × 两档 = **1024 帧**全非空，帧间差包围盒不贴 1px 边框。
- **[A1]** Lv.1 覆盖表：该动的 8 座帧差 **99~435px**；不该动的 8 座 **0**。
- **[A2]** Lv.3 **16/16** 有动效，最小帧差 **31px**。
- **[A3]** 烟成缕：竖向跨度 **14 / 11 / 14px**，相邻帧差值 **89~173**，**0 对 2 周期帧**。
- **[A4]** 水车轮毂 2×2 **8 帧逐像素相同**、轮辐 **8 种**。
- **[A5]** 庄园旗杆整列 8 帧逐像素相同、旗面累计变化 **156px**。
- **[A6]** 烟区墨色像素 **0**；`fxBeforeOutline` 负向臂 **423**。
- **[A7]** 底子锚点 p1/p3 = **7 旗 + 2 火把 + 4 路灯 + 喷泉**，p2 加 2 篝火、p4 加 2 水晶；`noStreet` 抽掉喷泉与路灯。
- **[A8]** 6 类精灵逐帧都有变化；`noAnim` 负向臂把喷泉帧差打到 **0**。[A9] 酒馆 8 帧互不相同。
- 真 Chrome 844×390：相位推进 **1→7→2**、已建 `<img>` **6/6** 换图；特效层 **1519px** 非空白且在变；动画期间 16 块地都在、点已建仍出详情；`devtownanim=0` 与 `prefers-reduced-motion` 两条臂都恒 0。
