`castleBackdrop()` 从"一座石堡换色"拆成四套骨架。第六轮先做到"四座城不一样"，

## 读数

- `probe:townview` **S10**：四族城心边缘两两 IoU **0.249**（阈值 ≤0.55，边缘 771/801/980/660）。
- **S11** 城心材质呼应兵种（±8 容差，城心 x 0.38–0.62 × y 0.02–0.42）：
  p2 熔岩 **278** px / 黄铜 **331** px；p4 紫晶 **389** px / 骨 **487** px；p1 仅 88 骨色误命中、p3 全 0。
  判据用数量级差（p1 骨 ×3 < p4 骨）而非绝对零——石灰岩在 ±8 容差下会误命中几个骨色像素。
- **N0h** `flatCastle`：城心塌成同一面灰墙后 IoU **0.802**（阈值 ≥0.60）。
- **N0i** 同臂：熔岩 / 黄铜 / 紫晶 / 骨四类标记**全部归零**，证明 S11 量的是城心构件而非底子色差。
- **S12** 布局识别：四族逐地块位移最小 **155px**，844×390 零越界、最小格 76px；**N0j** `sameLayout` 负向臂位移归零 **0px**。
- `probe:townanim`：全过。A7 锚点没变——p2 两团跳火仍在 `baseCamp`，p4 两簇水晶仍在地面，城心只画静态材质。

## 满城建制（2026-11-20）

用户追问「每个种族建满了建筑的时候城堡是什么样子」。旧四张 `shots/` 是**中期**：
默认存档只有 3 座，`devtier=3` 把五座兵营拉满也仍留 13 块空地基，不能回答这个问题。
新增 `?devtownfull=1` 后四族各出一张**真满城**：

| 族 | 满城读到的样子 |
|---|---|
| p1 人类 | 棋盘铺满：后排城墙/市政厅/行会，中排五座兵营，前排酒馆·市场·工坊；十字大街与广场喷泉仍露得出来，石砌主堡压在正中。 |
| p2 妖兽 | 16 座围成一圈，中央熔池和旗杆留空；环形火山岩路把铜人、熔炉门、恶魔角塔串起来，远景熔岩要塞没被房子吃掉。 |
| p3 精灵 | 四层树枝上挂满建筑：高层塔与树冠厅、中层弓手/矮人屋、地面酒馆市场；中央树干、横枝与树根门仍是主脊。 |
| p4 亡灵 | 五条放射甬道从紫晶塔脚铺到前排：骨垛、黑石尖拱、紫晶尖塔沿列排开，巨型紫晶塔冠在最高点。 |

**读数**：`probe:townfull` 全过 —— 四族各 16/16 built、0 unbuilt、0 越窗、**0 切边**，u3 5/5，城堡帧 `tv_<owner>_castle_lv3`；负向臂不传 `devtownfull` 时 built **3** / unbuilt **13**，门不是恒绿。

⚠️ 同轮修掉一个旧门量不到的缺陷：前排 13 块地原来 `y=0.88`，地块按钮框没越窗，但 Lv.3 的 112~140px `<img>` 按 `translate(-50%,-72%)` 下探 28% 后被详情栏**切掉底边**（实测 p1 2 / p2 4 / p3 3 / p4 3 张）。统一退到 `y=0.84` 后切边归零。`probe:townfull` 刻意量 `<img>` 真边界，不量按钮框 —— 后者会让这个缺陷继续假绿。

## 边界

`?devtownowner=` 只改这一张城景的呈现，用于美术评审；不改存档、建造规则与城镇名（所以整屏截图标题仍是「曙光城」，四族对照请看 `full-towns-4up.png` 的外部标签）。
`?devtownfull=1` 同样只改这一局运行时状态：不进存档、不改造价、不解锁游戏规则。
图都是 `buildTownScene()` / `buildSceneBuilding()` 的真实输出（`dist/render/townSceneArt.js`），不是另画的一套。
