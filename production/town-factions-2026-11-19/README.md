# 四族城心 · 与兵种呼应（2026-11-19）

`castleBackdrop()` 从"一座石堡换色"拆成四套骨架。第六轮先做到"四座城不一样"，
第七轮按用户追的要求重做 p2 / p4，**从兵种阵容反推城的材质与轮廓**——
骨架不同不等于种族对：木栅茅草营地对不上熔岩巨人，白色大理石神殿对不上摄魂怪。

## 第十版：骨架级重画（2026-11-21）

用户看完第九版满城对照表后要求"骨架级重画"：第九版仍是**16 张人类方盒**共用骨架，
只在屋顶贴叶冠/黑岩尖齿/骨肋、背景换地貌——满屏方盒子的轮廓一眼就认得出是同一个村。
第十版把**建筑本体**按族重画，p1 保留原 16 座功能建筑作基准：

| 族 | 建筑骨架（16 座各自成形，不是同一原型换皮） |
|---|---|
| p2 妖兽 | **熔岩洞穴**：黑岩不规则洞体 + 发光熔岩洞口 + 三种按位置变化的獠牙；塔楼是角柱，工坊是熔岩轮，行会是晶洞/喷口；地面玄岩裂纹。没有一面直墙、一片瓦 |
| p3 精灵 | **活木树洞**：锥形树干（树皮竖纹）+ 拱形树腔（内透 leaf 光）+ 叶冠 + 根须；酒馆挂木牌、树城走廊是粗枝平台、行会是球果/螺旋枝；地面是根土不是草皮 |
| p4 亡灵 | **石椁墓窟**：斜石椁 + 尖拱墓门（绿火 soul 光）+ 三段骨肋 + 颅饰；塔楼是紫晶尖碑、骨栏/骨栅/骨桥；墓门最后补画，保证尖塔压下时入口仍可见 |

16 种功能身份（酒馆/市场/市政厅/工坊/城墙/旗/五兵营/三行会）与 Lv.1/2/3、8 相位动效全部保留。
`?devtownowner=pX&devtownfull=1&devtownanim=0` 的四张真机满城实拍已重生成。

**读数**（`probe:townskeleton`）：身体带 y42..64（避开屋顶皮肤与根脚装饰）里
p2 空腔 7~358px / p3 133~398px / p4 11~177px，**零腔 0/48**；
骨架专属建材 p2 玄岩 6908 / p3 树皮 4914 / p4 椁石 6840；

## 第九版：从换色改成换世界（2026-11-20）

用户的批评是准确的：前八版**四族仍是同一套 16 间方盒子 + 同一片丘陵**，bg 只换主色，
"建筑风格的差别不是很大，没有显示出各个种族的特征"。这一版动了两层：

**背景 = 地貌，不是调色盘**

| 族 | 背景里真正画的东西 |
|---|---|
| p2 妖兽 | 两座火山锥、火山口熔岩、熔岩瀑布直通城中熔池、灰烟柱、玄武岩柱阵、三张透岩浆的地穴口、火山灰火星 |
| p3 精灵 | **一整棵大树**：34 团树冠吃掉上半张天空、贯穿全画的主干（树皮纹 + 树瘤）、扇形根系、四条承托枝；城墙改成一根横贯画面的巨枝，不再是一排小树干 |
| p4 亡灵 | 墓园：三排歪墓碑、四棵枯树、两座尖顶陵墓、坟包与骨片、贴地雾、月亮；紫晶塔立在碑林中间 |

**建筑 = 共用功能骨架 + 族别皮肤**

先在既有像素上重染建材（p2 黑岩/铜、p3 树皮/浅木、p4 墓石/骨），再按**实际屋顶轮廓**
（`roofEdge()`，不按建筑 id 写死 y）叠三套件：p2 黑岩尖齿 + 檐下熔缝 + 铜角；
p3 叶冠 + 垂藤 + 根脚；p4 骨肋 + 颅饰 + 歪墓碑。16 座功能原型和 Lv.1/2/3 升级档都保留。

**读数**（`probe:townworld`）：p2 天空熔岩 454 / 玄武 5839 / 地穴 879（p1 全 0）；
p3 天空树冠 20776 / 边缘树皮 1616；p4 碑林 4671+1751 / 枯树 342。
建筑族别 token p2/p3/p4 = 1575/4761/3040（p1=0），与 p1 最小剪影 IoU
0.803/0.784/0.789。负向臂 `sameWorld` 把四族底子逐像素塌回 p1（差 0）、
建筑剪影 IoU=1，证明门量的是地貌与皮肤而不是"又换了一次色"。
`townview` 的 **S1** 同步从「四族结构逐像素相同」改成「16/16 长出族别剪影」；
**N0h** 也补了 `sameWorld` 冻结地貌，否则火山和树冠留在天上，量不到城心塌没塌。

## 满城建制（2026-11-20）

用户追问「每个种族建满了建筑的时候城堡是什么样子」。旧四张 `shots/` 是**中期**：
默认存档只有 3 座，`devtier=3` 把五座兵营拉满也仍留 13 块空地基，不能回答这个问题。
新增 `?devtownfull=1` 后四族各出一张**真满城**：

| 族 | 满城读到的样子 |
|---|---|
| p1 人类 | 棋盘铺满：后排城墙/市政厅/行会，中排五座兵营，前排酒馆·市场·工坊；十字大街与广场喷泉仍露得出来，石砌主堡压在正中。 |
| p2 妖兽 | 16 座围成一圈，中央熔池和旗杆留空；环形火山岩路把铜人、熔炉门、恶魔角塔串起来，远景熔岩要塞没被房子吃掉。 |
| p3 精灵 | 四层树枝上挂满建筑：高层塔与树冠厅、中层弓手/矮人屋、地面酒馆市场；中央树干、横枝与树根门仍是主脊。 |
| p4 亡灵 | 五条放射甬道从紫晶塔脚铺到前排：骨垛、黑石尖拱、紫晶尖塔沿列排开，巨型紫晶塔冠在最高点。 |

**读数**：`probe:townfull` 全过 —— 四族各 16/16 built、0 unbuilt、0 越窗、**0 切边**，u3 5/5，城堡帧 `tv_<owner>_castle_lv3`；负向臂不传 `devtownfull` 时 built **3** / unbuilt **13**，门不是恒绿。

⚠️ 同轮修掉一个旧门量不到的缺陷：前排 13 块地原来 `y=0.88`，地块按钮框没越窗，但 Lv.3 的 112~140px `<img>` 按 `translate(-50%,-72%)` 下探 28% 后被详情栏**切掉底边**（实测 p1 2 / p2 4 / p3 3 / p4 3 张）。统一退到 `y=0.84` 后切边归零。`probe:townfull` 刻意量 `<img>` 真边界，不量按钮框 —— 后者会让这个缺陷继续假绿。

## 边界

`?devtownowner=` 只改这一张城景的呈现，用于美术评审；不改存档、建造规则与城镇名（所以整屏截图标题仍是「曙光城」，四族对照请看 `full-towns-4up.png` 的外部标签）。
`?devtownfull=1` 同样只改这一局运行时状态：不进存档、不改造价、不解锁游戏规则。
图都是 `buildTownScene()` / `buildSceneBuilding()` 的真实输出（`dist/render/townSceneArt.js`），不是另画的一套。
