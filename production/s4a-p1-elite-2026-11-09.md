## 1. 做了什么

**数值层（20 个，全代码生成，不排表）**

`units.ts` 新增 1b 节：`UPGRADE_NAMES`（20 条中文名）+ `makeUpgrade()` + 生成循环。
每个 `p*_xxx_u` 由基础版经 §2.5 五条系数算出：

| 项 | 规则 | 备注 |
|---|---|---|
| 攻 / 防 | **+1** | |
| 伤害 | **上限 +1、下限不动** | |
| HP | **×1.25 向上取整** | 天使 65→82（不是 81） |
| 速度 | **不动** | 不许拿速度当升级卖点 |
| 招募价 | **×1.2 逐项取整**（非零项至少 1） | 天使 1500→1800 |
| `aiValue` | **按新四维重算**（`aiValueOf`） | 远程 ×1.25 只进 `aiValue` |
| `expValue` / `growthPerWeek` / `shots` / 族色 | **照抄基础版** | 抄错 = 白送经验或白送产量 |

**解锁层（兵营三档）**

`maxLevel: 3` 只加在五座兵营上（市场 / 魔法链等在 S5 之前不许写 3）。
L1 帐篷（基础版 100%）→ **L2 石堡（升级版 100%）** → L3 要塞（升级版 **+25% 周产**）。
**L2 是唯一的兵种升级入口**，L3 只加产量。

- 兵营本身升级**收 0 金**，只收 **L1 木/矿 × 0.5 向上取整**（决策 60）；L2 与 L3 **各取 50%**，不是逐级折半。
- `town.levels?: Record<string, number>` 单独一张表（不写进 `buildings`，否则日收入/城防/周产会结算两次）。
  **缺失按 1 读，不需要迁移器**（与 `equipped?` / `growthRemainder?` 同一口径）。
- L2 那一刻池内基础版**免费**转升级版：`convertPoolToUpgrade()` 同时搬 `growthPool` 与
  `growthRemainder` 两张表、`delete` 基础版键（绝版）。

**美术层（仅 p1）**

- `baseUnitOf()` / `planOf()`：升级形态**没有自己的体形档**，直接读基础版那条（§2.5「脸不动、比例不变」）。
- `drawBodyPlanUnit` 加第四个开关 `elite`（`baseUnit !== unit`），五个 p1 函数各加一段 `if (elite)`。
- `ELITE_ART_FAMILIES = new Set(['p1'])`；`unitIdForTier(owner, tier, upgraded)` 在族未开放时
  **退回基础版**——缺形态是内容缺口，缺产能是玩法 bug，两者不能混成同一个崩。

## 2. 封顶闸（唯一硬闸）

`powerRef(升级版) ≤ 同族下一档 × 0.9` —— `tools/powerref.mjs` D 段，逐条复算五条系数、
`upgradeOf` 自指、三张表未被改，另带两条负向对照。

- 覆盖 **20/20**
- **16 条生效 / 4 条不适用**（T5 四支已是本族封顶，没有"下一档"）
- **最紧 = p2 黄铜人 闸内 91.8%**（= 升级版战力 ÷ 闸上限；同一个兵"占下一档"是 **82.6%**）

  ⚠️ **两个百分比不是矛盾，是两个分母**，本轮踩过一次：
  `powerref.mjs` 原先只印"占下一档"（82.6%），`balance-p2.mjs --upgrades` 印"占闸上限"（91.8%）——
  同一个兵两个数，谁看都以为其中一个错了。现在 `powerref` **两个都印**（`对下一档 82.6% · 闸内 91.8%`），
  判词统一用闸内占用（>100 才算越界），"最紧"也按闸内占用排序。
  spec §2.5 注里那句"铜人 91.8%"因此是对的（它一直说的是闸内占用）。
- 负向对照：HP 改回基础值 ⇒ 系数闸报警；把铜人抬到 8/10/40 ⇒ 占下一档 **210.6%** · 闸内 **233.9%**，闸仍红。

## 4. 判据返工：为什么 [6] 不量「外接框凸起」

原计划写的是「升级形态至少一侧比基础版多 ≥4px」。实测三件事说明这把尺子量的是假对象：

1. `normalizeTier` 按**高度**等比缩放、再**按帧中心**居中 ⇒ 单侧伸出的东西被对半分。
   孩子王的旗让自然宽度 +50%（14→21px），落地只剩左右各 3px。
2. 骑士与天使**四边顶满画布**（骑士 58/64 宽、天使 56×56 全高）⇒ 凸起在物理上不存在。
3. 更糟的是**反向**：骑士第一版把枪旗往上挑 0.12h，自然身高 +3px ⇒ 归一化把整只压小 7%
   ⇒ **升级版比基础版还窄**。越"加东西"越缩小。

因此 [6] 改成守三条：**自然身高不变（±1px）· 43×37 兵牌像素差 ≥8% · 升级版不许自带 `BODY_PLAN`**。
凸起降级为读数（并在读数里标"顶满"）。`[N4]` 负向对照证明这把尺子有分辨力：
自比 0.0% / 改 1 像素 0.8% / 真升级 22.3% / 跨兵 87.6%。

> 想让"凸起"重新成为判据，得先改归一化的居中/缩放口径 —— 那是另一把尺子，不在 S4 里动。
