# M7 · B3c：§14.4 按 A 案重登记 + AI 墙估值改用实测倍率

> 2026-11-13 · 决策 61 的收尾批。两个问题，一个口径，一个常数。
> 前置：`m7-b3b-wall-2026-11-13.md`（读数来源）、`m7-b5-baseline-2026-11-13.md`（A1–A6 基线）。
> 门：`probe:wallgate`（G1–G7 + 新增 W1–W4）；全套 **63 门非 0 = 0**。

---

## 0. 六条结论

1. **§14.4 的「+0~30pt」正式作废**（主理人拍板 A 案）。作废的理由不是"实测更高所以放宽"，
   而是**口径错位**：价格只改变"有多少城会建墙"，改变不了"墙已建好那一局"的守方胜率
   ⇒ 拿价格永远洗不绿这条上限。方向由 `≥ 0` 守，上限交给**破城门槛**（L1 ≤ +30% / L3 ≤ +100%）。
2. `wallgate.mjs` 里那条"只报不判"的 `⚠️` **已删除**。现在没有"打印但不判"的判据 ——
   报告里出现的每一条阈值都进退出码。这比"留个警告"重要：警告会被当成噪声忽略三个月。
3. **AI 墙估值从常数改成乘法**：`守军 + townDefenseBonus × 24` → `守军 × WALL_NEED[守方族][级]`。
   旧式给 L1/L2/L3 只折 48/96/144 战力，与守军规模无关；实测墙值占守军的 **0~85%**。
4. 低估倍数实测 **L1 ×13~58、L2 ×22~87、L3 ×44~78**（p1 L1 实测 +0%，无低估可言）。
   之前文档写的"12~88 倍 / 中位 35×"指的是整个 L1~L3 区间，两个说法都对，但**别拿"中位 35×"当每一格的读数**。
5. 查表轴是**守方阵营**，不是攻方。差异来自守军的兵种构成（弓手多、T1 便宜的族，同一道墙的边际更大），
   与"哪个族在攻城"无关 —— 按攻方查表在语义上就是错的。
6. 回归全绿且**没有副作用**：A1 场均战斗 +5.1%（在 ±10% 内）、D28 英雄战力 **0.0%**、
   丢光城镇 **0/8**、T5 35 天 **8/8**。AI 没有因为"墙变贵"而不敢出门，只是更少去啃有墙的城。

## 1. 改了什么

### 1.1 规格（`spec-implementation.md` §14.4 + 决策 61 行 + §3 验收清单）

| 项 | 旧 | 新 |
|---|---|---|
| 守方闸 | 建 `wall1` 胜率上升 **0~30%** | 上升 **≥ 0**（方向闸） |
| 曲线无关锚 | 无 | `k1 ≥ k0 − 0.01`（建墙不许让城更好打） |
| 上限 | 30pt（**不可执行**：价格够不着） | 破城门槛 **L1 ≤ +30% / L3 ≤ +100%**，且 L1≤L2≤L3 |
| 报告里的 `⚠️` | 保留 | **删除**（没有"只报不判"的判据） |
| L3 +85%（紫晶） | 触发断言 | 记为**已知设计边缘**，打印但不判 |

作废记录写在 §14.4 正文里，不删原文 —— 读者要能看到"为什么当初写了 30pt，后来怎么废的"。

### 1.2 代码

**`core/combat/siege.ts`**：新增 `WALL_NEED` 与 `wallNeedMultiplier(owner, level)`。

```
WALL_NEED = {
  neutral: [1.0, 1.09, 1.24, 1.57],   // 四族中位
  p1:      [1.0, 1.00, 1.16, 1.60],   // 晨曦
  p2:      [1.0, 1.05, 1.25, 1.52],   // 赤焰
  p3:      [1.0, 1.13, 1.23, 1.54],   // 翠林
  p4:      [1.0, 1.21, 1.63, 1.85],   // 紫晶
}
```

**`core/game/ai.ts`**：`pickTarget` 的城门门槛改成乘法，并把公式提成 `townNeedForAI(town)` 导出
（两个消费者：`pickTarget` 与 `probe:wallgate` 的 [W4] 接线检查 —— 探针不许另抄一份公式）。

```ts
// 旧：need = garrisonStrength(garrison) + townDefenseBonus(town) * 24;   // 48 / 96 / 144
const need = townNeedForAI(town);   // = garrisonStrength × WALL_NEED[守方族][级]
```

空城返回 0（城墙挡不住"走进去"），门槛仍由调用方的 `max(120, need × 1.15)` 地板负责。
`townDefenseBonus` 从 `ai.ts` 的 import 里删掉了 —— 它仍然参与**战斗**的防御修正，只是不再冒充"兵力门槛"。

## 2. 读数（`probe:wallgate --gate`，40 校准种子 / 120 表种子）

### 2.1 表与实测同源

| 族 | L1 实测 | 表 | L2 实测 | 表 | L3 实测 | 表 | 最大偏差 |
|---|---|---|---|---|---|---|---|
| 晨曦 | 1.000 | 1.00 | 1.160 | 1.16 | 1.596 | 1.60 | 0.3% |
| 赤焰 | 1.048 | 1.05 | 1.250 | 1.25 | 1.519 | 1.52 | 0.2% |
| 翠林 | 1.130 | 1.13 | 1.228 | 1.23 | 1.543 | 1.54 | 0.2% |
| 紫晶 | 1.202 | 1.21 | 1.635 | 1.63 | 1.846 | 1.85 | 0.7% |
| 中立（中位） | 1.089 | 1.09 | 1.239 | 1.24 | 1.570 | 1.57 | 0.001 |

实测列 = `k_level / k_0`，同一族的同一份 3 周守军，只换城防等级。
容差 5%：`k` 的二分粒度是 0.01，比值本身带 ~1% 量化误差。

### 2.2 墙值 = 守军的百分之几（这是旧公式漏掉的东西）

| 族 | L1 | L2 | L3 | 旧式折的战力（L1/L2/L3） | 新式（L1/L2/L3） | 低估倍数 |
|---|---|---|---|---|---|---|
| 晨曦 | +0% | +16% | +60% | 48 / 96 / 144 | 0 / 2,069 / 7,760 | — / ×22 / ×54 |
| 赤焰 | +5% | +25% | +52% | 48 / 96 / 144 | 604 / 3,018 / 6,278 | ×13 / ×31 / ×44 |
| 翠林 | +13% | +23% | +54% | 48 / 96 / 144 | 1,685 / 2,982 / 7,002 | ×35 / ×31 / ×49 |
| 紫晶 | +21% | +63% | +85% | 48 / 96 / 144 | 2,782 / 8,347 / 11,262 | ×58 / ×87 / ×78 |

守军基准 = 3 周产量（战力 12,072~13,250，四族）。"低估倍数" = 新式给墙折的战力 ÷ 旧式给的。
**p1 L1 是 0%**：晨曦的守军不是弓手带队，木栅栏对它的边际就是零 —— 这不是噪声，
是 [G5]/[G6] 允许 L1 从 0% 起的原因（四族 L1 需求 0/5/13/20%）。

### 2.3 边界情形

- **空城**：`townNeedForAI` 返回 0，门槛落到 120 地板 ⇒ 空城仍然可以走进去。
  城墙挡不住"walk-in"，这是对的；旧式给空城 +48 战力反而是假的（L1 没有塔）。
- **中立城**：没有阵营兵种构成，只能取中位行（1.09/1.24/1.57）。
- **越界等级 / 未知阵营**：夹到 0~3、落到中立行（存档里可能有 `wall4` 之类的脏数据）。

## 3. 负向对照（都可执行，不是"理论上会红"）

| 对照 | 做法 | 结果 |
|---|---|---|
| 双向挡视线 | `cp -R dist /tmp/dist-bidir`，删 `blocksLine` 里的 `isInsideCity(from)` 早退 | [G1]/[G3]/[G5] 红，p1 L1 守方胜率 **55.0% → 1.7%**，rc=1 |
| 旧 AI 公式 | `cp -R dist /tmp/dist-oldai`，`townNeedForAI` 改回 `守军 + 级别×48` | **[W4] 四族全红**：L3/L0 = **×1.01**（要求 ≥1.4 且 = 表内值） |
| 坏表 | `cp -R dist /tmp/dist-badtable`，`p4: [1, 1.21, 1.63, 1.85]` → `[1, 1.5, 1.2, 1.85]` | **[W1]/[W2] 红**：非单调 + 偏差 26.6% |

第三行是最重要的一条：它证明 [W2] 不是"表自己和自己比"的恒真式 ——
**改了城墙而没重跑探针，表就红**。第二行证明 [W4] 抓的是"接线断了"而不是"表错了"：
旧公式那一次 [W1]/[W2]/[W3] 全绿，只有 [W4] 红，定位很干净。

如果 D28 战力也涨了，说明 AI 在"用更少的兵打更多的仗"，那才要担心。

## 5. 没做的（别以为是漏了）

1. **墙价仍然不改**。B3b 的结论（每 1% 优势 111/139/172 金、单调无断层）不受本批影响 ——
   AI 的估值不影响玩家看到的价格。
2. **B5 的四条待拍板原封不动**：T5 稀有资源价、强档怪数、p3/p4 镜像偏置、T5 驻军编成。
   本批没有碰任何一条。
3. **紫晶 L3 的 +85% 破城优势**仍是已知设计边缘（[G6] 上限 100%）。要收它得动塔数或护城河，
   那是规则批，不是估值批。
4. **F2（城防线采纳率 40%~70%）** 仍然只能真人试玩 —— AI 的估值不等于玩家的意愿。
