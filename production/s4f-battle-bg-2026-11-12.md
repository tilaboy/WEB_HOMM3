# S4f · 五套战场地形背景（2026-11-12）

> 计划：`production/ui-redesign-2026-10-28/PROJECT-PLAN.md` §11.1 / M5 · U3
> 规格：`production/ui-redesign-2026-10-28/spec-implementation.md` §11.1
> 门：`npm run -s probe:battlebg` → **10 条断言全绿**；全库 **55 门实跑**同批全绿
> （`package.json` 里共 57 条 `probe:`/`audit:`，其中 `probe:pockets`、`probe:outbreak`
> 是 M6 的**预注册空壳**，`tools/probes/*.mjs` 不存在 —— 不在本轮计内）

这一批和 S4a–S4e 都不同：**没有一张兵种帧**，动的是"战场这张底图"——
数据（`battleBg.ts`）、图集（20 张地砖）、绘制（远景 / 前景 / 地砖）三层。

## 一、做了什么

### 1. 数据是纯表 + 纯函数（`render/battleBg.ts`）

`BATTLE_BG_SPECS` 每套 6 个色（`base / ink / outer / rim / far / fore`），
`battleBgOf(terrain, siegeLevel)` 是**地形→套**的唯一映射，`bgSeparation()` 是
**判据的唯一实现**——门直接 `import` 它，探针里不重写色差公式（抄一份就是第二真值来源）。

| 套 | 地形 | base | 判据读数（对最紧的那一对） |
|---|---|---|---|
| `grass` | 草地 | `#4c6b34` | ↔ swamp ΔH 16° / ΔL* 17.6 |
| `dirt` | 土路 + 沙地 | `#94734b` | ↔ siege ΔH 3° / **ΔL\* 18.1**（靠明度过） |
| `snow` | 雪原 | `#cfdbe6` | 唯一浅色套，与其余全部 ΔL* > 40 |
| `swamp` | 沼泽 + 岩地 | `#333d1c` | ↔ siege ΔH 30° / ΔL* 4.6 → **靠 grass 那条才过** |
| `siege` | 城战（`siegeLevel > 0` 强制） | `#5a4a3a` | — |

**规格给的五个底色不够用**（实测 3 对不合格）：`grass↔swamp` 34°/10.6、`dirt↔siege` 3°/14.5、
`swamp↔siege` 30°/1.6 —— 两两全是"两个绿""两个土黄""两个暗橄榄"。改法只动**明度与一个色相**：
`dirt` 提亮一档（土路本来就比战场土浅）、`swamp` 压暗并偏绿（沼泽是湿暗，不是干土）、
其余三套保持规格值。改后 10 对全过，判词里同时印"最紧的一对"。

### 2. 地砖：同一块六边形，地上长不同的东西

`combatAtlas.hexFloor(bg, variant)` 现在烘 **5 套 × 4 变体 = 20 帧**（`cf_<bg>_<v>`；
旧的 4 张 `cf_<v>` 作为 `grass` 的别名保留，老调用点不用改）。

只换颜色的地砖在 ×1 下读到的是"同一个场地换了五种颜色"——**三块砖并排看，
噪声斑点与碎石位置逐像素相同**。所以加了 `groundMarks()` 这一层，按套画**地纹**：

| 套 | 地纹（三种） | 读法 |
|---|---|---|
| grass | 草簇（三叶中高旁低）/ 土斑 / 小白花（半数砖） | 草没长满的野地 |
| dirt | 车辙（两条同向斜线）/ 干草 / 有体积的石头（2×2 + 亮顶） | 被车马压过的路 |
| snow | 冰裂（四段折线）/ 雪堆（亮顶 + 暗底）/ 冰屑 | 硬边 = 只有冰才有 |
| swamp | 水洼（暗底 + 冷亮反光）/ 苔斑 / 骨片（每三块一块） | 湿地，不是暗绿草 |
| siege | 石板缝（T 形主缝 + 支缝）/ 泥 / 缝里的草 | 铺过的城内地 |

> ⚠️ **与规格标题的一处有意冲突**：§11.1 标题写"同一套几何，只换调色板"，
> 但同一节表第 4 列**逐套列了不同的斑点**。两句话不能同时满足，本批按**表**做
> （地点感只能来自"地上有什么"），并在 `battleBg.ts` 头注里写明"只差配色"这句话
> **只对底色与格缝成立**。

### 3. 远景 / 前景（纯 canvas 图元，0 新图集）

- 远景带：画在**战场矩形之外**的 `y ∈ [0, PAD]` 里（`PAD = 6`）。形状逐套不同：
  阔叶树冠 / 1px 枯树 / 三角雪松 / 参差岩柱 / 城垛 + 每 4 格一座方塔。
  18 个锚点、`hash2(i,11,77)` 稳定抖动 ⇒ 同一套每帧一致，不闪。
- 前景：底边两角，**左右各内缩 16px**（保证碰不到第一/最后一列单位的脚）。
  草叶 / 石堆 / 雪堆 / 芦苇 / 木栅。
- **规格的 12px 带高与 8px 前景做不到**：画布外边距只有 `PAD = 6`
  （`BASE_W/H = FIELD + PAD*2`）。把 PAD 抬到 12 ⇒ 482×310 变 494×322，
  `fit()` 缩放变、所有战斗截图基线与 `probe:battle` 的坐标换算作废。
  代价远大于收益 ⇒ 剪影按**可用外边距**画，硬约束"不压格"优先于规格里的绝对像素数。

## 二、四次返工（都是"画出来了，但读不出来"）

| # | 现象 | 原因 | 定稿 |
|---|---|---|---|
| 1 | 远景/前景在 6px 带里**几乎看不见** | α 0.55 是按 12px 带定的；6px 的中间调压在同色外圈上等于没有 | α → **0.85**，`far/fore` 各压深一档 |
| 2 | 探针把"可达高亮"当地砖色（读到 `#4a726c`） | 玩家回合 col ≤ 7 整片染蓝，单点采样读到的是高亮 | 右半场 **6 格 5×5 均值 → 取中位数**（少数污染点被中位数天然剔掉） |
| 3 | C3/C4 把**画布边缘**读成前景（dirt/siege 各误报 30px） | 边缘 `outer` 与 `fore` 同色阶，`near(fore)` 把边缘算成前景 | `fore` 再压深（`#241a10` / `#1a130c`）+ 判据改**精确匹配该套 fore**（tol 20）、阈值 20→10 |
| 4 | 探针全部 PASS，命令却**永不返回**（被我手停，挂了 14 分钟） | `serveInProcess` 的 http server 让事件循环一直有活，收尾没 `process.exit` | 末尾显式 `process.exit(bad ? 1 : 0)`；本仓所有带 server 的探针都该这么收尾 |

第 3 条值得单独记：**"暗色缝不是边界，透空缝才是"**的同一族错误 ——
判据抓的不是"有没有前景"，而是"这个颜色像不像前景"，于是任何同色阶区域都会中招。

### 2.5 地纹本身又返工三轮（同一族病：画出来了，但读成别的东西）

`groundMarks()` 第一版五套都"有东西"，×9 目检后三套不合格 —— 判据都不是"有没有画"，
而是"像不像那个东西"：

| # | 现象 | 原因 | 定稿 |
|---|---|---|---|
| 1 | 草簇读成**栅栏 / 条形码** | 三根等距、等高、同色的竖线 | 间距拉开（`i*2`）、中高旁低、每砖整体往一侧歪（`variant % 2`）；下宽上尖 |
| 2 | 雪原读成**脏雪** | 逐像素噪声幅度 ±0.22 在浅底上就是脏点；且没有体积线索 | 噪声降到 −0.16/+0.13 且只占 16%；雪堆改 3px 亮顶 + 下缘压暗；冰裂改**冷蓝**折线（灰会混进噪点） |
| 3 | 沼泽水洼读成**贴了一条 UI** | 3px 亮蓝横条是整块砖最显眼的东西 | 水洼压暗（−0.45）、反光降到 2px 并错开一格（`x-1..x`），苔斑保留 |
| 4 | 车辙读成**划痕** | 5px 太短，两条不成对 | 拉到 7px、两条**同向同斜**、间距 2px |
| 5 | 石板缝读成 **T 字形符号** | 主缝 + 垂直支缝 = 一个字母 | 改为长而细的斜向裂纹，支缝跟着主缝同向 |
| 6 | 草地读成**等距圆点壁纸** | 四块砖**每块都长一簇草**、锚点又都在内切圆里 ⇒ 排布出来是均匀点阵 | 四块里只长三块（`variant !== 3`）；"地面感"靠疏密不均，不靠"每格都有" |

> 通则（与兵牌那批同一条）：**同距同高的平行线一定读成符号**（栅栏、条形码、速度线）；
> 要它读成"自然物"，必须**破对称**（间距、高低、朝向三样里至少动两样），
> 且**暗底要压痕、亮底要堆体**——方向搞反就是"脏"。

  B1     9 条地形映射（含 sand/rock 归并、siegeLevel>0 强制 siege）
  C0     五套都拿到离屏画布读数
  C1     中场格**实拍色** 10 对可区分（grass=#4c6b34 dirt=#96764c snow=#cedae5
         swamp=#343f1d siege=#584a39）· 最紧 ΔH=1° ΔL*=19.4
  C2     顶边 6px 有远景剪影（暗于 outer 的像素数）21 / 292 / 301 / 268 / 480

**C1 和 A3 是两条不同的尺子**，必须都留：A3 读配色表（"我打算不一样"），
C1 读**渲染结果**（"画出来真的不一样"）。只有 A3 的话，`drawFloor()` 写死
`cf_grass_` 也照样全绿——这正是文件头第一条负向对照。

**负向对照（复跑手册写在 `tools/probes/battlebg.mjs` 文件头）**：

| 改一处 | 该红的断言 |
|---|---|
| `drawFloor()` 忽略 `bg`（写死 `cf_grass_`） | C1（五套两两相同） |
| `draw()` 不调 `drawBackdrop()` | C2（顶边暗像素 0） |

## 四、人工目检（×3 原生画布，五套逐张）

五套各导一张 `__battleOff`（482×310 原生、1px = 1 场单位）放大 3 倍逐张看：

- **雪原的白兵**：§11.1 点名的风险项。白马／天使的白身**靠墨边活下来**（深棕 1px 轮廓），
  底盘圈只是第二线索 —— 结论：可辨，但**不改地砖就不该再加深雪地**（会显脏）。
- **草地的树冠**在 6px 带里读成"一排半圆"，**城战的垛口**读成"锯齿"，
  **沼泽的岩柱**读成"参差的暗边"——都在"远端一条暗边"的语义内，没有一个是独立可读的物体。
  这是 6px 的物理上限，不是画法问题。
- **dirt / siege 的区分**只靠明度（ΔH 3°）：并排能分开，单独看会都叫"土地"。
  这是 A3 判据允许的（"或"字），但**记在这里**：若将来加第六套，先解决这一对。

## 五、仍欠（别记"通过"）

1. **五套背景没有真机目检**：本轮是桌面 Chrome 1280 宽 + 原生画布放大。
   手机 CSS 缩放 ≈1.6 × dpr 3，6px 的剪影带会变成 ~29 设备像素 —— 比截图更清楚，
   但"更清楚"也可能让"锯齿"变成"明显的锯齿"，得看一眼。
2. **地纹的密度没有读数**：`groundMarks()` 只保证"每块砖都有"，没有断言
   "四种变体的地纹不重复/不过密"。现在的判据仍是 0 新门。
3. **攻城套的城垛与真城墙的关系没验**：`drawSiege` 画的墙在场地内，
   `drawBackdrop` 的垛口在场地外 —— 两者同屏时是否读成"同一座城"没拍过。
4. 旧账不变：`estimateDamage` / `estimateRetaliation` 漏 `au.attack`；
   `cu_p2_threewolf` 在兵牌之外仍读成一颗头。
