# 美术 / UI 换皮可行性评估（2026-10-22）

> 触发：主理人「所有的文本都还是 text box……小人、石头、树、城堡都比较粗糙，可不可以换成
> 图有一些图形设计在里边的，把这些 text 也做点 CSS 设计……这个转换需要多大工作量？有没有
> 已经可以用的游戏设计（CSS 的或游戏图形的）？」
>
> 本文所有数字都是**本机实测**（`atlasaudit` / 源码计数），不是估算口径。

---

## 0 结论先行（三句话）

1. **「文本像 text box」的根因只有一个**：全项目 **0 个 `@font-face`**，正文走
   `Palatino / Songti SC` 系统衬线，字号 12–13px 且开抗锯齿 ⇒ 无论边框怎么画，
   它永远是"网页字"。换成 **12px 中文点阵字 + 2px 硬描边面板**，观感立刻换赛道。
   **工时 ≈ 1.5 人日**（样张已出：`tp9/tp10/art-skin-mock/inmap.png`）。
2. **「图像粗糙」的根因不是渲染器**：全部 209 帧都是**代码画的像素图元**
   （`atlas.ts` 1310 行 + `unitArt.ts` 3274 行），一棵树 ≈ 20 行矩形/三角。
   要变好看**只能换资产**，改代码改不出新画风。
3. **现成可用**：CC0 的 Kenney（可提交进公开仓库）、Tiny Swords（最接近你要的卡通气质，
   但**禁止再分发** ⇒ 公开仓库不能放）、OFL 中文点阵字体（可提交）。

图集容量（`npm run audit:atlas` 实测）：

- 冒险图集 **150 帧**，2048×2048，**横向已用 2042/2048 = 99.7%**，面积 7.2%

字体栈（`style.css`）：

```css
font-family: "Palatino", "Palatino Linotype", "Songti SC", "STSong", Georgia, serif;
```

## 2 三条路线

### A. UI 换皮（不碰世界美术）—— **1.5–2 人日**

| 改动 | 做法 | 覆盖 |
|---|---|---|
| 字体 | `@font-face` 嵌 **缝合像素字体 12px**（OFL，实测 woff2 588KB，子集化后 ~200KB）；字号只允许 12/24/36，`-webkit-font-smoothing:none` | 全站文本 |
| 面板 | 2px 硬描边 + 1px 高光/暗边（`box-shadow` 阶梯）+ `clip-path` 切角；**零图片、零依赖** | 侧栏 / 弹窗 / 城镇 / 战斗 HUD |
| 按钮 | 三段 bevel（高光 / 底 / 外描边），按下位移 2px；去掉 `linear-gradient` 的"网页感" | 26 个按钮 |
| 圆盘 | 4 个**真圆**（56/64px）+ 16×16 像素图标 + 12px 标签；不再是圆角矩形 | 探索 HUD |
| 图标 | 16×16 内联 SVG（`shape-rendering:crispEdges`），资源/英雄/城/结束一天/菜单各一枚 | 顶栏 + 圆盘 + 列表 |
| 数值 | `tabular-nums` + 定宽槽（已有），换点阵字后不再抖 | 资源 / 日期 / 面板 |

样张：`tp9/tp10/art-skin-mock/skin.png`（旧 vs 新同屏）、`inmap.png`（合成到真实地图上）。
**这一步只改 CSS/字体/图标，不动 `render/**`，图集与探针零风险。**

### B. 世界换皮（换资产）—— 分两档

先算清"要换多少帧"：

- 现有：地图 150 + 战斗 59 = **209 帧**
- 目标还需要：4 阵营 × 城堡 3 级 = 12、中立怪 12 种 × 3 帧 = 36、
  英雄 4 阵营 × (地图/待机/攻击) ≈ 12、地形 7 类 × 变体 + 岸线 8 向
- 合理估：**260–320 帧**

| 档 | 资产 | 授权 | 能不能进公开仓库 | 工时 |
|---|---|---|---|---|
| B1 | **Kenney Tiny Battle / Tiny Town**（16×16，190 / 130 文件） | **CC0** | ✅ 可以 | 2–3 人日接管线 |
| B2 | **Tiny Swords**（Pixel Frog，64px 单位/建筑/地形/UI） | 自定义：**可商用、禁再分发/转售** | ❌ **不行** | 3–5 人日（含 4 阵营染色、12 城堡、autotile 适配） |

> B1 风格是"俯视战棋小方块"，跟现在气质接近，**提升有限**；
> B2 才是你要的"有设计感的卡通"，但仓库是 public（`tilaboy/WEB_HOMM3`）⇒ 资产只能
> 本地放置 + `.gitignore`，或把仓库转私有。**这是流程决定，不是技术问题。**

### C. 定制 / 外包一套统一画风 —— **2–3 周，¥15k–30k**

260–320 帧按商用像素外包价（¥60–120/帧）落在 1.6–3.8 万。
风险是**风格漂移**，控制办法：先 1 屏样张 → 再 3 帧试做 → 批量。

## 3 为什么"换图"不等于"换文件"（技术成本清单）

1. **图集是运行时手算的**：`Packer` 是 shelf-pack，帧的 `x/y` 与锚点 `ax/ay` 都是算出来的；
   换尺寸/换数量必须重排，且"横向 99.7%"意味着**没有余量**。
2. **四阵营靠调色**：`ownerPalette()` 给屋顶/墙体上色；外部资产是整张彩图 ⇒
   要么每个阵营出一套（×4 工作量），要么改 HSL 分区替换（有失真风险）。
3. **地形是程序化 7 类 × 变体 + 8 向岸线**：外部 tileset 的 autotile 规则不同，
   **岸线是最大坑**（现有一套 `shoreTile(dir)`，8 个方向与地形边缘耦合）。
4. **兵种有 tier 归一化**：`normalizeTier()` 把 1–5 级压到 62–100% 占格；
   外部整张 sheet 需要切帧表 + 重新标定"脚底/剑尖"，否则升级会"跳"。
5. **字体要在 canvas 之前就绪**：`BattleRenderer` 有 3 处 `fillText`，
   换自定义字体必须 `await document.fonts.ready` 再首帧，否则第一场战斗跳字是回退字体。
6. **中文点阵字有硬约束**：字号只能取 12/24/36（整数倍），任何 `transform: scale(1.5)`
   都会把格点点糊 —— 与现在 `zoom 1.2` 是** canvas 缩放、不冲突**，但 DOM 侧不能随手缩放。

## 5 建议的推进顺序（每步都有可验收产出）

| 步 | 内容 | 工时 | 验收 |
|---|---|---|---|
| 0 | 1 屏样张（**已完成**） | — | `skin.png` / `inmap.png`，你点头才继续 |
| 1 | **UI 换皮**：字体 + 描边 + 图标 + 真圆按钮 | 1.5 天 | 真机 792×360 截图；`audit:touch` / `probe:dockoverlap` 全绿 |
| 2 | **地形 + 装饰**（树 / 石 / 山 / 水 / 岸线） | 2 天 | 同机位前后对比图；`audit:atlas` 不越界 |
| 3 | **城堡 + 兵种**（按阵营分批，先 1 族） | 2–3 天/族 | 战斗截图 + `sheet:units` 肉眼对圣经 |

> 顺序的理由：**屏幕面积占比**。HUD 文字 + 面板占观感权重最高、成本最低；
> 地形/装饰铺满全屏、次之；城堡与兵种最贵但只占局部。

## 6 需要你定的三件事

1. **走哪条**：只做 A（快、稳），还是 A + B（画风整体换代）？
2. **仓库能否转私有**：决定能不能用 Tiny Swords（否则只能用 CC0 的 Kenney，气质差一档）。
3. **风格取向**：保持现在"土黄羊皮纸 + 暗金"，还是换更亮、更卡通的（Tiny Swords 系）？
