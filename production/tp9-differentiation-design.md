## 1. ① 定位押注文档（D-8 ✅ 已拍：2026-10-16 用户裁定）

### 1.1 一句话押注（用户裁定版）

> **《骑士信条》是横屏手机上的 HoMM3。**
>
> 它**完整保留 HoMM3 的核心循环**——探索经营、**时间来换兵力**（每天每周的增长）、英雄成长——换成**卡通喜剧调性**与**全新的种族**（不是换皮肤：完全新的种族、不同调性、更诙谐幽默卡通），在**打磨好的地图**上给出高可玩性，**UI 为拇指设计**。
>
> 它针对**老玩家**：原版在 PC 上、一局以小时计、UI 为鼠标设计；在这里，**可以坐下来沉心来打一下午，也可以每天打几分钟、推完一天，下一天继续**——两种会话形态都成立，不强制哪一种。
>
> **商业模式即设计约束：一次买断制。** 不插广告；不像流行手游那样等 1-2 小时才能建一个建筑、或打几仗就要休息除非掏钱。**用户体验优先。**

它回答"为什么玩你这版，而不是带 HD 模组的免费原版"：**同一个核心循环的横屏手机改编**——原版在 PC / 键鼠 / 小时局 / 原版族；我们在手机 / 拇指 / 弹性会话 / 喜剧调性 / 全新种族。不是移植，不是换皮。

**版本沿革（订正可见）**：2026-10-15 我起的押注句是"横屏手机上的 **8 分钟** HoMM3"（把核心循环"压进一节课时间的碎片局"）。用户 2026-10-16 裁定修正：**不把"8 分钟碎片局"当目标**——HoMM3 真正的兵力增长以时间（每天/每周）为根，玩家应能选择"打一天存一次"的碎片形态，也能坐下来打一下午。⇒ "8 分钟"框架废弃，改为"**一天为天然单位的弹性会话**"；`game-concept.md` §4/GC-1 与 `ux/in-game-ia.md` Q1b 同步改述（权威落点不能漂，见 §8）。

### 1.4 押注否决什么（负面清单，同等重要）

| 否决 | 理由 |
|---|---|
| **内容量竞赛**（140 兵种 / 全族建筑树） | 预算不允许；保真度追平原版是克隆品竞争的两条死路之一（repair-plan §2-F1） |
| **写实 / 高清位图美术** | 零位图不变式（除 Capacitor 外零运行时依赖）+ 卡通圣经 V2.1 已锁；HD 模组免费原版在这个维度我们永远赢不了 |
| **等待型机制**（体力 / 计时建筑 / 广告 / "休息除非掏钱"） | 用户裁定：一次买断，用户体验优先；且与"随时推完一天"的弹性会话直接冲突——等 1 小时建建筑的体验，在"打一下午"和"打几分钟"两种形态下都是垃圾 |
| **换皮式种族** | 用户裁定：完全新的种族、不同调性；`races.md` 已按此设计（§0），实现不得退回"配色差异" |
| **只有一种会话形态成立的设计** | 用户裁定两种都成立 ⇒ 否决两个极端："一局必须几十分钟不能停"（多线微操 / 长局 UI 复杂度，与拇指输入冲突）与"一局必须几分钟草草收场"（砍循环环，丢 HoMM3 血统） |
| **为第一次玩的人加教学负担** | 阿凯画像：不需要教学。教学场是**可选场景**（已落地），不是默认流程 |
| **加新系统** | repair-plan §1 核心判断：修补主旋律是"接线 + 补真 bug + 补音频 + 显式押注差异化" |

### 1.5 与 HoMM3 的关系（写清楚，避免内部误读）

- **学它的**：核心循环（**完整保留**，押注第一条）、迷雾三态、遭遇预览、矿场经济、AI 出击逻辑、**时间换兵力**（每天/每周增长的节奏）。
- **故意不同的**：输入（拇指 vs 键鼠）、调性（喜剧 vs 史诗）、地图量（3 张打磨 vs 随机）、兵种量（20 vs 140+）、**种族（全新四族 vs 原版族）**。
- **商业模式**：HoMM3 原版本身也是买断制——"买断无等待"这条**不是与原版划界，是与流行手游划界**（广告/体力/计时那套）。原版与我们同侧。
- **明确不做的**：战役剧情、地图编辑器、事件脚本系统（`gdd/maps.md` §0 维持原样暂不实现）、飞行/技能系统（`races.md` §7.2 Phase 2）。
- **对"克隆品"质疑的回应口径**：我们是**同一个核心循环的横屏手机改编**，不是移植，也不是换皮——差异化在输入 / 调性 / 种族 / 会话形态，不在内容量。

### 4.1 rush 中位 3 天是否太快

### 4.2 难度三档曲线

`difficulty-spec.md` §5.1 的等距校验成立（压力比对数尺度 −0.539 / 0 / +0.580，三档等距）。**缺口：三档没有任何运行时门控**（规格的 V1-V9 是 2026-09 落地验收，不是持续门）。建议补一个 `tools/diffcurve.mjs`：三档 × 8 seeds 跑 15 天，报"玩家 D5/D10 金 + 兵力峰值 / AI 同项"比值——这是 TP-9④ 交付给工程线的**门控需求**，不是本轮实现。

### 4.3 `expValue` 缺口补规（races.md 从未规定）

现状：`EXP_BY_TIER = [4,12,20,45,120]`（`units.ts:31`，注释自标"设计缺口"）；中立 wolf 8 / boar 18 / ogre 40；升级曲线 `expToNext(L) = round(100 × L^1.8)`（`hero.ts:52`）⇒ L1→2 **100** / L2→3 **348** / L3→4 **761** / L4→5 **1309**（到 L5 累计 **2518**）。战斗经验 = Σ 击杀数 × expValue（`battle.ts:1155`）。

**实测推算**（duel 图典型）：1 堆弱狼 23×8 = **184 exp** ≈ L1→2 + 24% ⇒ 两堆弱怪即 L3。以 duel 12-18 天计，L4-L5 终局可期，**曲线方向没错**；但两个真问题：

1. **中立怪经验与战力脱钩**：食人魔战力 ≈276/只，却只给 40 exp；战力/经验 = 6.9，而狼是 2.3 ⇒ **高阶中立怪被严重低估**，打强怪的收益曲线是凹的（应该凸：越危险回报越成比例）。
2. **没有规格**：数值是"档位基线"占位，races.md 不背这个数。

**补规（区间，待 `racebalance` 实测收敛）**：

| 对象 | 现 expValue | 提案区间 | 依据 |
|---|---|---|---|
| 按战力折算 | — | `expValue ≈ round(战力 × 0.35~0.50)` | 保持"两堆弱怪 ≈ L3"的现有手感（0.44 是现状隐含值） |
| ogre | 40 | **90~140** | 修正脱钩（战力 276 × 0.35~0.5） |
| boar | 18 | 40~60 | 同上 |
| wolf | 8 | 8~12 | 基准不动 |
| 各族 T1-T5 | 4/12/20/45/120 | 暂不动，随 racebalance 回归 | 与中立统一口径后再调 |

落地动作：races.md §1.3 旁增"经验值表" + `units.ts` 改公式或显式表 + smoke 加一条"expValue 与战力同序"断言（防再占位）。

### 4.4 `body` / `accent` 去占位

现状：占位 = 族主题色（`units.ts:21-24` `theme()`），唯一消费者是 `HeroPanel` 兵种圆点，不参与战斗。**补规**：按 `cartoon-style.md` §3.3 逐兵种色板出 20 组（body/accent 必须与族色可区分——races.md §8.3 已要求）。这是**美术包**（归 TP-4/TP-8 批次），本节只锁"去占位"的决定与验收：圆点颜色在同族内可分辨（去色盲测一并归 TP-8 §5.6.5）。

### 4.5 中立守卫用旧通用树（新决策点）

`mines.ts:68` 宝库守军 = `pikeman`/`archer`（旧统计：枪兵 5/5/18HP 等），全图 5 座库对所有族都是同一组旧树兵。两个选项：
