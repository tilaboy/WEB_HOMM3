# S4g · 六类施法模板（2026-11-12）

> 计划：`production/ui-redesign-2026-10-28/PROJECT-PLAN.md` §7.4 / U3
> 规格：`production/ui-redesign-2026-10-28/spec-implementation.md` §11.2
> 门：`npm run -s probe:spellfx` → **13 条全绿**；全库 **58 门**同批全绿

这一批把"每个法术都放一个圆环"换成**六类形状**。规格原文的判据是"演出从点变成屏"，
所以重点不在"有没有特效"，而在**玩家能不能只看形状就分出这是火球还是祝福**。

---

## 一、做了三层

### 1. 映射是纯表（`core/data/spells.ts`）

```ts
export type SpellFxTemplate = 'proj' | 'burst' | 'chain' | 'buff' | 'debuff' | 'revive';
export const SPELL_FX_TEMPLATE: Record<string, SpellFxTemplate> = { … }
```

这张表是"法术 → 模板"的**唯一**映射。渲染器按它分派，`probe:spellfx` 的 [A1] 按它做覆盖闸：
`SPELLS` 里每个 `combat: true` 的法术都必须有模板，落到缺省 `ring` 就是漏配。

**12 个战斗法术 → 6 类**（规格写"14 个"，表里实际只有 12 个；缺的是流星雨 / 群体减速，
两个都没实现。覆盖闸按**表**算、不写死 14 —— 将来补上这两个，忘了配模板当场红）：

| 模板 | 法术 | 数 |
|---|---|---|
| ① `proj` 投射 | 魔法箭 / 冰箭 | 2 |
| ② `burst` 爆发 | 火球 | 1 |
| ③ `chain` 链 | 闪电 | 1 |
| ④ `buff` 增益 | 祝福 / 加速 / 护盾 / 石肤 / 嗜血 | 5 |
| ⑤ `debuff` 减益 | 诅咒 / 减速 | 2 |
| ⑥ `revive` 复活 | 复活 | 1 |

### 2. 形状在 `drawSpellFx`（`render/BattleRenderer.ts`）

五类新分支（`revive` 是 S4e 就有的），全部 canvas 图元、**0 新图集帧**：

| 模板 | 画法 | 为什么这么画 |
|---|---|---|
| 投射 | 命中点 2px 亮芯 + 小环 + 沿 `to` 方向 3 颗递减拖尾 | 拖尾方向**取施法方所在格**（`fx.to`）。没有 `to` 就**不画拖尾** —— 固定朝右上会在施法者在右半场时把拖尾画到弹体前面，读成"两个弹体" |
| 爆发 | 三圈错相位（6→22/31/34）+ 8 片碎屑飞到 44px | 三圈同时出生会糊成一个粗环；碎屑必须飞得比最外圈**更远**，否则全程压在环内、看不见 ⇒ 读成"水波纹" |
| 链 | 折线主干（46px，段长 12/10/8/6）+ 两道分叉 + 2px 色芯/1px 亮芯 | 与旧 `drawBolt` 同源 —— 那段**搬进来后删掉**了：两处各画一份就是第二真值来源 |
| 增益 | 3 个菱形符文上浮（22px）+ 1px 光柱 | 方向是唯一的类别信号：增/减益都画环时，玩家分不清"被帮"还是"被打" |
| 减益 | **两道**暗环下沉 + 3 片碎屑下落 | 与 `dread`（威压，单环）形似但不是同一个；像素掩膜不同，[C1] 才分得开 |
| 复活 | 4px 金柱 + 8 粒上浮 | 沿用 S4e |

### 3. 闪电的独立状态删掉了

旧实现里闪电是 `let bolt`（一条常驻状态，靠主循环手动 `bolt.p -= dt/360` 衰减）。
玩家报过"施法后一道雷永远钉在战场上"，本尊就是它漏衰减。现在走 `spellFx` 的 `chain`，
由 `life` 自动衰减 —— **没有独立常驻状态，这条病不可能再犯**。

## 二、六次返工（四次"画出来了但读成别的东西" + 两次"门自己炸了"）

| # | 现象 | 原因 | 定稿 |
|---|---|---|---|
| 1 | 链的命中点读成"闪电下挂了个**雪球**" | 首版画的是半径 4~12 的**白色实心圆** | 改成 2px 亮芯 + 四道 3~6px 短芒（放射状）；闪光不能是球体 |
| 2 | 爆发读成**水波纹** | 碎屑只飞 26px，全程压在最外圈（40px）以内 | 碎屑 10 → 44px，飞到环外；[B4] 同时量"增宽 ≥15px" |
| 3 | [B6] 复活按"宽 ≤14px"判红 | 颗粒本来就散在柱两侧（实测宽 16px），bbox 宽不是"柱"的性质 | 判据改成**中轴 ±3px 的墨占比 ≥35%** + 高 ≥20px。改成这个才发现：圆环/爆发在同样宽度下到不了 35% |
| 4 | [B7] "无 `to` 时左缘 ≥68" 判红 | 弹体自带的环半径 7.5px，本来就伸到 62 | 判据改成**有 to 比无 to 多 ≥6px**（17 vs 9）。"方向不许编"要量**差值**，不能量绝对值 |
| 5 | 全量顺序跑时本门 **4 秒 rc=1，而前面 13 条断言全绿**（单独跑 4 次全绿） | 探针把渲染页写进 `dist/__spellfx.html`、跑完 `rmSync`。本机 node 带 safe-delete shim：**同一 turn 累计 50 次批量删除**后要人工确认；本门排第 58，前 57 个门早把额度用完 | 渲染页**不落盘**：`createServer` 起内存路由（`/__spellfx.html` 从字符串返回、其余静态代发 `dist`）。**重试救不了它**（跑得越多越必炸），只能从根上不删文件。已记进 `GATES.md` §五 |
| 6 | 同一次全量跑里，**无关的** `audit:bandflip` 判红（`?devtint=0` 臂与默认臂逐块差 **8940 / 8940** = 全差），单独跑两次全绿 | 那一臂抓到的是**整幅空白**的 canvas。空白帧本身"稳定" ⇒ 原「冻帧稳定」判据抓不到它；门排在第 44 位，前面积了 43 个 Chrome 门 | 量块之前加前置 `DRAWN`（抽样 ≥8 个不同色），最多等 5s，等不到判「量不到」。通则进 `GATES.md` §五：**凡"冻帧稳定"类判据都要配"帧里有东西"** |

第 3、4 条是同一类：**判据写成了"尺寸"或"绝对值"，而想要的性质是"形状"和"差值"** ——
判据会照着 bug 长成合适的样子，所以每次判红先问"我要的到底是哪个性质"。

## 六、仍欠（别记"通过"）

1. **时序没按规格做**：§11.2 要求"总 800ms（前摇 180 / 演出 420 / 结算 200）+ 可点击跳到结算"。
   现在沿用原时长（投射/爆发 460ms、链 520ms、增益/减益/复活 420ms），**没有前摇段**，
   也**没有"点击跳过但不跳过伤害"**。这是独立的一批（要动自动战斗与 AI 的节奏），不在本批。
2. **火球与冰箭的落点表现没有分开验**：火球 `burst`、冰箭 `proj`，但两者都走飞行段 ——
   只验了形状，没验"玩家能不能在飞行中认出哪个是火球"。
3. **减益与威压（`dread`）在实战同屏时没有对照**：模板层的 [C1] 只比六类，不比 `dread`。
4. **真机（手机 dpr3）目检没做**：本轮是桌面 Chrome + 裸画布。
5. **规格的"14 个法术"实际只有 12 个**：流星雨 / 群体减速未实现。覆盖闸已按表算，
   补法术时忘配模板会当场红。
