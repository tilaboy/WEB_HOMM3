## 一、做了什么

### 1. 数据只有一份（`core/data/innates.ts`）

`UnitType.innate` 只是一个**指针** `{ id: InnateId }`，效果表 `INNATES` 只有一份。
为什么不做成"每兵一个字段"：六条里有三条带次数上限、两条是光环、一条是反噬，
写成六个字段就没人说得清"哪些是每场限次的"。`perBattle > 0` 是唯一的次数来源，
`useInnate()` 是唯一的扣次入口。

| id | 兵 | 类型 | 触发 → 效果 | 每场 |
|---|---|---|---|---|
| `oath` | p1 骑士 | 光环 | 邻格友军受近战 ⇒ 该次 −1（每回合每格 1 次） | ∞ |
| `lavaArmor` | p2 熔岩巨人 | 被动 | 被近战 ⇒ 反弹 25%（**不致死**） | ∞ |
| `flameBody` | p2 恶魔 | 触发 | 被近战命中 ⇒ 攻击者受 6 点 | 2 |
| `stoneSuppress` | p3 猿人 | 触发 | 远程命中 ⇒ 目标速度 −2 | 3 |
| `dragonFear` | p3 绿龙 | 光环 | 每回合开始 ⇒ 邻格敌军攻击 −1 | ∞ |
| `stun` | p4 牛头怪 | 触发 | 近战命中 ⇒ 目标防御 −2（到战斗结束） | 2 |

**为什么是 6 条不是 8 条**：天使（自复活）与摄魂怪（威压）已经有招牌能力，再挂一条就是规则堆叠；
三头狼与吸血鬼的位置被族动词和吸血占着。分配是定稿，**只许调数值，不许换兵**。

### 2. 规则只接在三个入口上

铁律（写进 `battle.ts` 的段落头注）：所有改数值的效果只能接在
`strikeAtkBonus` / `defBonusOf` / `unitSpeed` 三个入口，**不许在 `actMelee` 里就地加减**。
就地加减 ⇒ `estimateDamage` 与实际结算立刻分裂，而且不会有任何断言响。

- 誓约 = `applyOath()` 在**伤害落账前**改数（近战专用，反击也吃）
- 熔岩护甲 / 烈焰缠身 = `innateOnMeleeHit()`，在被打之后、反击之前
- 震慑 = `target.stunDef`，由 `defBonusOf()` 读
- 龙威 = `refreshFear()` 每回合写 `feared` 标志，`strikeAtkBonus` 读
- 投石压制 / 威压 = `applySpeedDebuff()`，与缠根同一套时效（**四条 −2 只取一次**）

### 3. 四类招牌能力的演出（`BattleFxKind`）

全是 canvas 图元，**0 新图集**（§11.2 的实现口径）。形状是唯一读得懂的线索，颜色只是第二线索。

| kind | 用在 | 形状 |
|---|---|---|
| `fly` | 飞行（6 个兵） | 9px 整段弧 + 起落各一圈贴地尘环 |
| `drain` | 吸血 | 3 颗血珠**从受害者飞向攻方**（方向本身就是"吸血"的意思） |
| `revive` | 天使自复活 | 金色光柱 + 8 粒上浮颗粒 |
| `dread` | 威压 | 暗环**下沉** + 3 片碎屑下落（与缠根的"向上缠"方向相反） |
| `lava` / `flame` / `oath` | 三条自带魔法 | 外溅火星 / 三簇火舌 / 头顶护罩弧 |

飞行单独说：`move` 事件里读 `BattleUnit.canFly`（**不是兵种 id**），所以升级形态自动跟着飞。
弧高 9px vs 地面兵 2.5px —— 不靠数值、不靠文字，一眼看出"它不是走过去的"。

### 4. 规则要看得见

这十条**不占按钮、不耗蓝、没有施法动作**，界面上唯一的存在就是部队浮框那两行字。
不印 = 只有写代码的人知道骑士有誓约。文案放 `core/data/innates.ts` 的 `unitAbilityHints()`
（不是 `BattleScreen` 里就地拼）—— 就地拼的话探针断言不到，这和当年族动词搬去 core 是同一个理由。

浮框现在长这样（天使）：

```
天使 ×3
攻 10　防 10　速 8
总生命 195
飞行：可越过城墙与护城河
不屈：歼灭后重返战场
（1 次/场，20% 兵力）
```

## 二、三次返工（都是"图纸说得清、字面读不出"）

| # | 现象 | 原因 | 定稿 |
|---|---|---|---|
| 1 | 吸血一列在图纸上**几乎空白** | 珠径 2.2px ⇒ 战场 1 设备像素；`#b8324a` 压土色本来就暗；三颗又挤在起点同时出发同时变小 | 珠径 3.0 + **亮芯暗边**两层 + 起点相位错开 0 / 0.34 / 0.68 |
| 2 | 烈焰读成 **「\|\|\| 」三根竖条** | 底宽 4px、三簇等高、间距 6px ⇒ 间隔 2px 的等宽竖条，形状上就是条形码 | 底宽 5px + 中簇最高（0.78 / 1 / 0.86）+ 每簇加亮芯 |
| 3 | 浮框折行把「攻击」劈成「攻」/「击」 | 240px 宽放不下 20 个汉字，自动折行落在词中间 | 条件与效果之间**主动 `\n`**（断在 `⇒` 后）；「不屈」那行同样主动断 |

第 3 条试过两个错误方向，记下来免得再走：
· 把 `max-width` 240 → 264：**没用**（一行 22 字要 ~330px），而且改的是全局浮框宽度；
· 把文案压到 15 字以内：会丢"每场 1 次 / 20% 兵力"这类**玩家必须知道的上限**。
—— 正确解法是**控制断点**，不是压缩信息。

## 三、门与读数

```
probe:innate   53 条 ✅（A 数据口径 7 / B 飞行 6 / C 吸血 4 / D 自复活 3 /
                        E 威压 3 / F 六条魔法 21 / G 浮框可读 9）
全库           56 门 rc=0
```

**负向对照（复跑手册，写在 `tools/probes/innate.mjs` 文件头）**：

| 改一处 | 该红的断言 |
|---|---|
| `reachable()` 删掉 `if (!u.canFly)` | B1（飞行和走路一样） |
| `afterHit` 的 `Math.ceil` → `Math.floor` | D1（6 只天使只复活 1 只） |
| `applyOath` 首行直接 return | F1a / F1b |
| `lavaReflect` 去掉 `maxSafe` | F2b（反弹会把攻方打死） |
| `useInnate` 删掉次数判断 | F3c / F4c / F6c |
| `refreshFear` 首行 return | F5a / F5b |

本批**实测跑过**两条（改 `dist/core/combat/battle.js` → 跑 → 还原）：

| 注入 | 实测变红的断言 |
|---|---|
| `Math.ceil` → `Math.floor`（1 处） | `D1` 复活 2 只 → **1 只**，rc=1 |
| 上限判断置 `false` + 飞行分支置 `true` | `B1` 最远 col 10（墙 11）· `B3` 落在 col 9 · `F3c` 实际 5 次 · `F4c` 6 次 · `F6c` 4 次，rc=1 |

还原后 `probe:innate` rc=0 —— 证明这两次红的是被注入的那一处，不是别的东西碰巧红。

## 五、仍欠（不在 S4 范围，别记"通过"）

1. **能力演出没有动图验收**：图纸是静态四相位，玩家看到的是 300~520ms 的连续过程，
   "看不看得出这是吸血"目前只有静态证据。
2. `unitAbilityHints` 的浮框是**悬停 1 秒 / 右键**才出，拇指设备上没有悬停 ——
   真机上这条路径要单独走一遍（长按是否等价于右键，未验）。
3. 四条 −2 速度（减速 / 缠根 / 压制 / 威压）只取一次，是设计决定，但**没有玩家可读的提示**
   说明"为什么不叠加"。
4. `estimateDamage` / `estimateRetaliation` 漏 `au.attack`（旧账，与本批无关）。
