# S4h · 施法时序 800ms 三段（2026-11-12）

> 规格：`production/ui-redesign-2026-10-28/spec-implementation.md` §11.2「时序」表
> 门：`npm run -s probe:castbeat` → **16 条全绿**；全库 **59 门**同批全绿

S4g 只做了"形状"——法术有六种样子了，但**放出去就是一瞬间**：没有"锁定目标"的预告，
伤害数字和爆炸同帧冒出来，玩家点一下也跳不过去。这一批补的是**节拍**。

## 一、三段与唯一来源

```ts
// ui/castTimeline.ts
CAST_WINDUP_MS = 180   // 前摇：目标格描边 + 施法方抬手，伤害还没结算
CAST_SHOW_MS   = 420   // 演出：模板（弹体飞行 / 折线 / 符文…）
CAST_SETTLE_MS = 200   // 结算：伤害浮字 + 目标抖动
CAST_TOTAL_MS  = 800
```

`castFrame(ms)` 是唯一的分段函数：探针 import 它，**不在探针里重抄 180/420/200**
（抄一份就是第二真值来源，改一处另一处静默过期 —— 铁律 13 的同族病）。

时间口径是 `anim.t`（**演出毫秒**，已乘玩家的 1×/2×/3× 倍率）：
倍率只改"多快放完"，不改三段的比例与先后。探针因此对倍率免疫。

## 二、前摇画什么、为什么这样画

| 元素 | 做法 | 撞过的墙 |
|---|---|---|
| 目标格描边 | 六边形外接圆 `HEX_R=17.5`（与地砖同源，不在渲染器里另写一个数），**1px 奶白 `#ffe9a8`** 压一条 **3px 半透明墨 `#140e08`** | ① 只画奶白线：左半场深绿草上还行，右半场浅褐土 + 狼的灰身体上基本消失；加墨底后两种底都立得住（**先铺墨再压亮**，美术总纲的老账）。② 原本画在 `drawUnits` **之前**：目标格上正好站着人，躯干把 6 段里的 4 段盖掉，只剩左右两截"金虚线"，读成渲染 bug ⇒ 移到单位**之后** |
| 施法方抬手 | `lunge = {unitId: origin, dx:0, dy:0}` 一帧 ⇒ `drawUnit` 选 atk 帧 | 另画一颗 1×3 亮星被否掉：单位和描边抢注意力，看起来像"头上有个 bug"。用现成的 atk 帧更省也更像 |

> 规格写的是"施法者抬手（1 帧）"。英雄本尊不在战场上，`origin` 取的是**施法方第一支存活部队**
> —— 与 S4g 里弹体的起点同一个人，不改这条代理关系。

## 三、点击跳过：跳的是"剩下的表演"，不是伤害

```
skip() { mark; showFx(); settle(); timeline.t = CAST_TOTAL_MS; }
```

三条顺序都不能反：

1. **`settle()` 在 `t=TOTAL` 之前** —— 反了就是"点了跳过的人看不到伤害数字"（规格的括注）；
2. **`showFx()` 在 `settle()` 之前** —— 反了会出现"伤害数字先飘、爆炸后到"；
3. 点击处理里 `if (anim?.skip)` **必须排在 `busy()` 之前** —— 演出中 `busy()` 恒真，
   排后面这点代码永远走不到（首版就是这样，探针 [B4a] 直接红）。

跳过之后这一下点击**被消耗掉**（`return`），否则同一个点击会顺手下一道移动令。

## 四、门与读数（`probe:castbeat`，16 条）

```
A 组（读 castFrame，纯函数）
  [A0] 180 / 420 / 200 = 800
  [A1] 0→windup、179→windup、180→show
  [A2] 599 无 settle / 600 有 / 800 done
  [A3] 演出进度 0→1 单调
  [A4] 负数 / NaN / 超时被钳住，无 NaN 进度
  [A5] 负向对照：压成一段的假实现必红

B 组（真开一场战斗、真点施法，读 window.__castTrace）
  windup@17 → show@183 → settle@600 → fx@600 → settled@600 → done@817 → end@817
  [B0] 两臂都真点出去了
  [B1] 五段顺序一次不跳
  [B2] show@183（180±25）· settle@600（600±25）· end@817（≥800）
  [B3] 不抢跑：fx@600 ≥175 · settled@600 ≥595
  [B4a] 演出中点击 ⇒ skip@200，墙钟 **13ms** 内结束
  [B4b] **不跳过伤害**：skip 当帧就 settled@200（≤ +40ms）
  [B5] 演完 `arrow` / `cast` 都是 null
  [B6] 前摇采到 `cast` 非空 = 描边真的画了
  [B7] 前摇采到 `__battleLunge` 非空 = 施法方真的在画 atk 帧
```

**为什么 B 组要看轨迹而不是轮询画面**：`BattleScreen` 在**跨段那一帧**记
`{phase, at, ms}`（`at` = 演出毫秒、`ms` = 墙钟）。轮询画面会有 20~40ms 的 RTT，
量不出 180/600 这种边界；轨迹是同一帧写下的，边界误差只有一帧（实测 +3/+17ms）。

**边界看 `at`，"点了多快结束"看 `ms`**：`skip()` 把 `at` 直接拽到 800，
`end.at − skip.at` 恒 ≈617 —— 拿它判"跳得快不快"会得到恒定值。这一条首版写错过。

## 五、负向对照（都实测跑过，不是推演）

| 改法 | 结果 |
|---|---|
| `if (anim?.skip)` 改成 `if (false && …)`（等价于把分支放到 `busy()` 之后） | **[B4a] 红**：skip@null，end 停在 800；其余全绿 |
| `skip()` 里删掉 `settle()`（只 `showFx()` + 置 `t`） | **[B4b] 红**：settled 落到 817 而不是 183 —— 靠 `step(done)` 的兜底才补上 |
| `CAST_SHOW_MS = 0` | [A1]/[A2] 红：180 处直接 settle |
| `drawCastWindup` 挪回 `drawUnits` 之前 | 画面只剩两截碎线（×8 目检确认），[B6] 仍绿 —— **这条只能靠目检**，写在这儿当提醒 |

## 六、仍欠

- **时序只覆盖"伤害/增益/减益/复活"共用的一条时间轴**。多目标法术（群体减速未实现）没有"逐个结算"的错峰。
- **点击跳过只在触屏/鼠标的 `click` 上生效**；键盘（`Esc`/空格）没有等价入口。
- 前摇的描边会横穿单位的兵力数字（1px 线压过 `23` 的底盒）。×8 下可接受，真机未目检 ——
  如果主理人觉得碍眼，下一版把底边两段在世界坐标 `cy+6` 以下裁掉即可（代价是"开环"）。
- 规格里的"目标抖动"只对**有伤害**的法术生效（增益/减益不抖），这条是照规格做的，
  但真机上"抖动 2px"是否够看得出来，没有读数。
