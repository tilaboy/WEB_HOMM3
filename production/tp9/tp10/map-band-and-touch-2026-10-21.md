# 可达边带改形 + 触屏文案（2026-10-21）

> 两个来源：① 主理人对真机截图 `phone-01-tutorial.png` 的反馈——「英雄能走的地方跟树 / 水 / 山之间被直线切开，
> 很遮挡整体感官」；② 同一轮真机走查抓到的 **D-1**（触屏上教键鼠）与 **D-2**（`?devbattle=1` 被开局页盖住）。
> 结论：**三件都改完了，各自有门 + 反证**；另留 **1 条口径欠账**（`tintab` 的红族，见 §6.3）。

---

## 1. 先定位：那不是美术，是 ④ 的边带

| 读码结论 | 依据 |
|---|---|
| 「直线」不是地形拼接缝 | `MapRenderer.ts` 的地形是整块 blit，不做格线描边（无 `strokeRect`） |
| 是**可达染色**的边界带 | `MapRenderer.ts` 可达染色段：凡"不可走且有一侧贴可达区"的格，就在那一侧画 `红 + 亮芯 + 墨` 各 `EDGE_W`(=2) px |
| 为什么树会变成**方框** | 1×1 的树四侧全贴可达区 ⇒ 四条边带闭合成一只方框 |
| 为什么它比美术还响 | 6 世界 px；真机 `s=0.784 × DPR3` ⇒ **≈14 物理 px**，比任何一格美术的轮廓都粗 |

⇒ 这是**作用域**问题（该不该给"自带形体"的格子描边），不是配色问题。所以修法不是调色，是**收窄作用域 + 削薄色栈**。

## 2. 改动：四臂，默认 = `soft`

`?devband=full|thin|art|soft|off`（`src/render/MapRenderer.ts`）：

| 臂 | 色栈 | 作用域 | 说明 |
|---|---|---|---|
| `full` | 红 2 + 亮芯 2 + 墨 2 = **6px** | 所有贴可达区的一侧 | **旧路径，原样保留**（可逐块取回旧画面） |
| `thin` | 亮芯 1 + 墨 1 = **2px** | 同 `full` | 只削薄，不改作用域 |
| `art` | 同 `full` | **自带形体（物件精灵 / 水面）不描** | 只改作用域 |
| **`soft`（新默认）** | 亮芯 1 + 墨 1 | 自带形体不描 | 两刀同时下 |
| `off` | — | — | 只关边带，蓝色水洗保留（`?devtint=0` 是连水洗一起关） |

两条硬约束：

1. **未探索格不参与 `art` 例外** —— 贴可达区那一侧的雾界闭合段必须原样留着，否则会把 `#155` 修好的洞重新打开。
2. **旧路径必须留** —— `?devband=full` 能逐块取回旧画面；"翻默认"不是"删旧路径"（`haloflip` 那条规矩）。

图：`production/tp9/tp10/map-band-compare.png`（教学场全图）、`map-band-trees.png`（树/湖岸细节 2×）、
`phone-band-ab/band-{full,thin,art,soft}.png`（四臂原图）。

## 3. 机检：`npm run audit:bandflip`（新门）

同一构建、冻帧（`performance.now` 钉常数）、只差 `?devband=`，逐块比对 + 只读落笔量：

| 臂 | rects | 落笔面积 px | artSkip |
|---|---|---|---|
| **default** | **10** | **320** | **52** |
| `?devband=soft` | 10 | 320 | 52 |
| `?devband=full` | 120 | **7680** | 0 |
| `?devband=off` | 0 | 0 | 0 |

判据与实测：

| # | 判据 | 实测 | 结果 |
|---|---|---|---|
| ① | `default ≡ soft`（块差 ≤ 0+40） | **0** | PASS |
| ② | `default ≠ full`（块差 ≥ 200） | **745** | PASS |
| ③a | `off` 真把边带关干净 | rects **0** | PASS |
| ③b | `default ≠ off`（≥ 24 块） | **66** | PASS |
| ④a | 默认走 soft 分支 | mode=soft | PASS |
| ④b | 作用域收窄生效 | artSkip **52 > 0** | PASS |
| ④c | 落笔面积 ≤ 0.12×full | **320 ≤ 922** | PASS |

**为什么数"落笔面积"而不是数颜色**：`NOGO_EDGE_INK/GLOW` 与美术调色板的 `ink0`/`hi1` **同值**
（`#2a1a12` / `#fff3c8`）⇒ 逐像素数色会被树/兵/描边污染，量到的不是边带。落笔面积只由 `band()` 累加，是这条通道唯一干净的尺。

### 3.1 反证（三向，逐个只红该红的）

| 反证 | 施加 | 红的断言 | 判读 |
|---|---|---|---|
| A 默认回 `full` | `BAND_MODE` 默认改 `full` | ①②④a④b④c（**5 条**） | 粗控：整条特性回退 ⇒ 所有引用 default 的断言一起红，符合预期 |
| B 关掉形体豁免 | `if (false && BAND_ART_ONLY …)` | ④b（artSkip **0**）、④c（面积 **2560 > 922**） | **精确**：只有"作用域"那一刀红，① 仍绿（default 与 soft 同步失真） |
| C 删掉 `full` 旧路径 | union 里去掉 `'full'` | ②（full 臂 mode 变 soft）、④c（分母塌成 320） | **精确**：只有"旧路径还在"那两条红 |

## 4. D-1：触屏上别再教键鼠

| 位置 | 改前 | 改后（`(hover: none)` 命中时） |
|---|---|---|
| 三个按钮 | `防御 (D)` / `等待 (空格)` / `施法 (C)` | **`防御` / `等待` / `施法`** |
| 底栏提示 | 鼠标停在部队上（或右键点击）查看它的属性 | **点一下部队查看属性** |
| 速度按钮 title | 演出速度（键盘 1/2/3 直选） | **演出速度** |
| 点自己部队 | 只提示「这是自己的部队」（**纯空点**） | **弹属性牌** |
| 点够不着的敌人 | 只提示「够不着，先移动过去」 | **弹属性牌 + 提示** |
| 点空地 | 牌不消失（触屏没有 `pointerleave`） | **收掉属性牌** |

判据用**媒体查询**而不是 UA：`(hover: none)` 描述的是**输入设备能力**，带触屏的笔记本仍会命中 `hover: hover`。
老 WebView 没有 `matchMedia` ⇒ 按桌面处理（保持原文案，不静默变成触屏版）。

## 5. D-2：`?devbattle=1` 要真的看得见

`#start-screen` 是 `position:fixed; z-index:900`，`.battle` 只有 150 ⇒ 战斗层整块躺在它下面：
DOM 断言全绿、截出来却是开局页（第一轮走查就被它骗过）。修法：`devbattle` 生效时把开局页 `display:none`
（用 `display` 而不是 `remove()`，开局页的 handle 还持有这个节点）。

**新判据 = 命中测试**，不是读 `display`（被盖住时 `display` 照样是 `flex`）：
战场上 4 个采样点 `elementFromPoint` 必须都落在 `.battle` 里，**且要求开局页确实在场**（否则又变成"没有对象也算过"）。

### 6.1 为什么两臂都要测

只测 `hover:none`，"文案写死成触屏版"的回归会绿；只测 `hover:hover`，"分支没生效"的回归也会绿。

### 6.2 反证

| 反证 | 施加 | 结果 |
|---|---|---|
| ① 不收起开局页（D-2 回退） | 删 `start-screen.style.display='none'` | **只红 1 条**（第 4 条）；命中采样 `ss-line / ss-legend / ss-map / btn big` = 开局页的部件，把原始缺陷钉死 |
| ② 分支失效 | `HOVERLESS` 恒 `false` | **4 条红**（6/7/8/10），桌面臂全绿 |
| ③ 点自己人不弹牌 | 删 `if (target)` 里的 `showTip` | **只红 1 条**（第 10 条） |

> ★ 反证③ 顺手抓出本门**首版的一条假判据**：原先只有一条"点任意部队能弹牌"，它会被**敌方**那条分支兜绿
> （删掉自己人的 `showTip` 照样 PASS，实测点敌方仍弹「野狼 ×26」）⇒ 已拆成第 10、11 两条，各守一条分支。

### 6.3 两条踩过的坑（写给下一次）

1. `Emulation.setEmulatedMedia{features:[{name:'hover'}]}` **不生效**（本机 Chrome 151 实测：覆写后
   `matchMedia('(hover: none)')` 仍 `false`）⇒ 首版被这个静默无效的覆写骗成"触屏臂全红"。
   真正翻转它的是 **`Emulation.setTouchEmulationEnabled`**。
2. 没有存档时 boot 走**教学场**，`#start-screen` 压根不存在 ⇒ 命中测试当然全绿。**这是"被无对象满足的假绿"**，
   所以第 1、3 条前置断言必须存在。

### 7.1 欠账（必须交代，不许当绿）

`tintab` 的"0 命中即非零退出"曾是对的（那时默认栈里必有红）。现在**红被设计性移除**，
这个规则就变成"每次跑都红"。两条出路，**都不该由我单方面改**（该文件冻结给 `engineering-lead-2`）：

1. 给它加一条**显式声明**的口子（如 `--drop=edge` + 打印"该族按设计不在默认栈中"），而不是静默 0；
2. 或把 `#154` 的验收口径从"红 + 亮芯 + 墨 三锚"**重钉为**"亮芯 + 墨 双锚"（判据与出处一起改）。

在它落地前，`#154` 的对比数请用 `--extra=devband=full` 取（那是**旧栈**的数，可与历史读数直接比），
默认栈**不要**引用 tintab 的 WCAG 列（那两列本来就只作参考，权威在 `reachmeas`）。

## 8. 本轮没覆盖

1. **真机复看**：改完的包**没有重新装回手机**（手机当时锁屏、没有解锁方式）⇒ 图是 792×320@3 的桌面仿真实测，
   不是这台 OPPO 的实拍。下一轮上机第一件事就是补这一张。
2. **色盲下的可达边界**：红锚被移除后，边界只剩"亮芯/墨"这对亮度锚。理论上对色盲更友好（不依赖色相），
   但**没有做去色测试**（`TP-8①` 那 3 个人还没到）。
3. **触屏准度 / 长跑 / 返回键**：与第一轮走查同样的欠项，未变。
