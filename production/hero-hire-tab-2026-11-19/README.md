# 英雄招募入口归位到「招募」页（2026-11-19）

## 起因
上一批（M9 三连：矿/布景/城内一览）收口时留了一个已知边界：酒馆招英雄的按钮还躺在
「市场·工坊」页。英雄和兵一样是"招"来的，入口埋在市场页属于分类错位——玩家在
「招募」页只能招兵，要招英雄得先切到最右一页。本批把它归位。

## 改动
- `src/ui/TownDialog.ts`
  - 把酒馆招英雄那一行抽成 `heroHireRow()`，默认挂在「招募」页顶部（有酒馆才出现）。
  - 「市场·工坊」页不再有它；没有兵营但有酒馆时，招募页仍显示招英雄行（不再被
    `尚未建成任何兵营` 的空态抢先 return 掉）。
  - 新增 `?devhiretab=market` 查询参数 = 闸门负向对照臂：把入口退回旧的市场页。
    没有它，"入口在招募页"这条判据无法证明自己测的是页签位置而不是面板上恰好有这段字。
- `tools/probes/townview.mjs`：接线层新增
  - **[U7]** 默认构建：切「招募」有 `.hero-hire`（含"招募英雄"字样）、切「市场·工坊」没有；
  - **[N2]** `devhiretab=market`：两页结果必须互换。
- `tools/GATES.md`：`probe:townview` 行补 U7 / N2 说明。闸门总数不变（54 道）。

零规则改动：`canHireHero` / `hireHero` / 造价 / 每周一位的限制原样复用，只是换了 DOM 父节点。

## 验收
- `probe:townview --gate`：T0–T4 + N0 + U0–U7 + N1/N2 **全过**，包含 844×390 真 Chrome。
  实拍读数：`招募=true 市场=false`；负向臂 `招募=false 市场=true`。
- `probe:uip0`、`audit:touch`：绿（招募页那一行沿用既有 `.ex-row` / `.town-extra` 样式，
  触摸目标与字号判据未变）。
- `tp6-townpanel`：A/B 段 5/0（与上一批记录一致）。
  ⚠️ 带 `--negctrl` 时 C2 的 `reload 后回不到教学局` 会异常退出——**已用 pristine 构建
  对照确认是探针自身既有问题，与本批无关**：暂存本批改动、 checkout 回 HEAD、重建后
  同一命令同样在第 C2 段挂掉。该探针非门控，不在 54 道里。
