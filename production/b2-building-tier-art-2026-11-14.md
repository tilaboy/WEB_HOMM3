## 2. 画法只有一条：升级只加不拆

`[B6]` 用**未描边帧**逐像素验：Lv.1 的每个不透明像素都必须在 Lv.2 里，Lv.2 的每个都在 Lv.3 里。

```
onlyIn(L1, L2) === 0 && onlyIn(L2, L3) === 0     // 5 座 × 2 组 = 10 组
```

这条约束是**故意选严的**，它一次挡掉三类错：

- **"重画一遍更好看的"**：只要新图挪了窗、改了门，包含关系当场红 —— 玩家会觉得"我的房子被换掉了"。
- **"升级只是换个配色"**：掩码不变 ⇒ 包含关系全过，但 `[B5]` 的 IoU 会顶到 1.000。
- **"新体块盖住了旧件"**：盖住不算拆，所以这条允许"长出来的东西压住一部分旧像素"。

配套的口径：**包含关系用未描边帧**（`outline()` 会把外沿 1px 和内缝一起改写，描边后再比会把"画对了但描边差异"记成违规），
**面积与 IoU 用已描边帧**（玩家实际看到的就是这一层，与 B1 `[B3]` 同口径）。
两套读数不可互换 —— 例如 `dwell2` 的 L1/L2，未描边 **0.898**、已描边 **0.857**。
本批的判据一律读已描边帧，`[B5]` 报的也是后者。

### 0.88 为什么不是 S5 的 0.70

S5 的 `[G1]` 量的是**同一座塔的三阶**（每一阶是整层重画，必须一眼看出"换了一座塔"），
所以 0.70 是"必须不同"。本批量的是**同一座房子加了一间披屋 / 一层阁楼**：
它的门窗、台基、柱廊、识别件**原地不动**（§2 强制），掩码天然共享大部分 —— 拿 0.70 会把合法升级判红。

0.88 也不是"宽松"：实测最大值 **0.857**，只高 0.023。再紧一点，`dwell2` 的雨棚就会红 ——
而那 40 帧里最难的 `dwell5` L2 曾经做到 **0.942**（等于没升级）、L3 **0.925**，都是这条抓出来的。

### `[B7]` 为什么必须单独有

结构和材质是两件事：`[B6]` 只量 p1，`[B7]` 再验**四族的三档掩码逐像素相同**（45 组）。
少了这条，某一族"顺手把塔往右挪了 2px"不会被任何门发现。

## 9b. 全库跑门：66/66（同批修掉 `probe:dayflow` 的一处偶发红）

第一轮 66 门跑出 **65 绿 + `probe:dayflow` 红 1 条**（`devreport` 臂 `模态=false · 标题「」`），
单跑又全绿。查下来与 B2 无关，是那道门自己的对照臂设计问题：

世界是随机开的（URL 不钉 seed），某一天 AI 可能**一条事件都没产生** ⇒
`showAiDayReport()` 里 `if (!evs.length) { finish(); return; }` 本来就该不弹。
旧判据"只过一天，没弹就红"把**「这天没有事件」**读成了**「弹窗坏了」**——
与 2026-11-12 那次「点没点成 / 没弹窗」是同一族病（铁律 2 的第三次结账）。

改法（`tools/dayflowprobe.mjs` + `src/main.ts` 各一处）：

- 对照臂最多连过 **3 天**，任一天弹出即通过；
- `?devprobe=1` 下暴露 `__aiDayEvents()`，读数写成
  `第1天：事件 0 · 第2天：事件 1 → 弹出` —— **0 事件与"有事件没弹"当场分开**。

实测四种世界：`事件1→弹出` / `事件0 · 事件1→弹出` / `事件1→弹出` / `事件2→弹出`，全部绿；
其中第二种正是原来必红的那种。

最终 dist 上的全库读数：**64 门 rc=0 / 462 s**，另两道 `probe:uip0` / `probe:mapshadow` 报 **rc=2**（`dev server 没在 127.0.0.1:5199 上跑`）—— 前置缺失，不是判据红。起 `PORT=5199 node tools/serve.mjs` 后
两道补跑 **rc=0**（`按压 9/9` · `落点 66/66，差值 −11.6/−11.5`）。合计 **66/66 全绿**。

⚠️ 5199 的服务要起成**常驻后台任务**：用 `(node tools/serve.mjs &)` 起的那种会随调用它的 shell 一起死，
下一批门再跑又是 rc=2。
