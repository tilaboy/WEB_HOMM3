#### ⚠️ D-17 的口径冲突：用户要「地图也搞笑」，但美术圣经把环境层冻结了

用户 2026-09-18 的要求原文：「希望游戏里的人物**和地图**会有点搞笑风格」。

**查证结果（实读 `design/art-bible/cartoon-style.md`）—— 两条腿一条已就位、一条是反的：**

| 侧 | 现状 | 与要求 |
|---|---|---|
| **人物 / 单位** | §1.3「比例夸张」**本就以搞笑感为目标**：每个单位**只有一处**比例失调；§1.3 注释原文「卡通 = 一整套写实规则 + 一个打破点……处处都失调，**搞笑感就塌成乱码**」。这也正是 §1.1 警告别加粗描边的原因（会把单位糊成一团墨） | ✅ **已对齐** |
| **地图 / 环境** | §3.1 明确把环境层（地形砖 `g_*`、岸线 `sh_*`、小装饰 `deco_*`）列为 **「✅ 不动（容差 ≤10%）」**，理由是「地形已经读起来像有笔触的像素画，重写成本极高、观感收益极低」，并断言「卡通与否的判据在**主体**身上」 | ❌ **方向相反** —— 按现设计，**地图不会变搞笑** |

**结论：不能把 D-17 当成「已在 A1 里覆盖」。** 三个可选口径：

1. **只做单位，地图保持写实底座**（= 维持现状）—— 零成本，但不满足用户的字面要求。
2. **新增「喜剧布景层」，不动地形砖**（**推荐**）—— 地形与岸线继续冻结，在**其之上**叠一层可关的布景道具（歪斜路牌、乱跑的鸡、晾衣绳、堆歪的木桶、滑稽雕像）。理由：这恰好避开 §3.1 冻结地形的核心理由（重写地形贵），把「搞笑」放在成本最低的那一层；且新层天然可做成**画质档位的降级开关**（低端档关掉即回退性能，与已有 `QualitySettings` 三档体系一致）。
3. **解冻环境层，重画地形砖** —— 最彻底也最贵，与 §3.1 的成本判断直接冲突，需 A1 重新评估。

**待用户选定口径后再派工；在此之前不要动 A1 的已有产出。**

## 4. 当前优先级

### ✅ 已验收 —— E2：AI 会发展（玩家实测反馈，曾为全项目第一优先）
**玩家观察**：电脑对手「都不建设」「啥也不会干」。

**根因（`tools/aidiagnose.mjs` 逐日时间序列取证，非猜测）**：
AI 一直在建设 / 占矿 / 募兵，但**没有任何"驻军 → 英雄"的回补通道**。
`aiRecruit` 把募来的兵全部灌进驻军，出门的英雄永远是开局那 20 个弓手。
3 种子 × 60 天：9 局里 5 局英雄一次都没补到兵、3 局终局 0 兵，而驻军兵数涨了 23~40 次。
**玩家看到的是「建了也打不出来」，误读成「不建设」。**

**修复（`1943d05`，6 文件 / +692，全部为机制缺失，未改任何数值与 `BUILD_ORDER`）**：
1. `ai.ts` 新增 `refillFromGarrison` —— 英雄在自家城时带走超出守城下限的驻军
2. `ai.ts` `pickTarget` —— 把「驻军有富余」也算作回城理由（否则通道成死代码）
3. `town.ts` `marketBuy/marketSell` 加 `actor` 参数 —— 顺带修掉真 bug：`aiTrade` 曾硬编码 1000/5 汇率，AI 与玩家市场规则不一致
4. `ai.ts` 新增 `aiBuyRare` —— 买宝石/水晶解开 `guild2/guild3` 建筑死结

**量化效果**：建筑数 17.5 → **22.9**（+31%）· 英雄兵峰值 38.8 → **63.1**（+63%）· 终局金 6591 → 2629（金币终于有出口）

**主理人独立验收**：`tools/smoke.mjs` **471/471 全绿**；`aidiagnose` 输出显示 AI 英雄确实带兵机动、攻城、占矿。

**残留 → 已派第二轮**：无城 AI 变僵尸（→ D-8 七天出局）、矿优先级静态权重（→ D-10）。

#### ⚠️ 推翻规格数字的三条（规格是按 Capacitor 6 写的）
1. **Capacitor 8 ≠ 6**：规格写 `34/23 + JDK 17`，实际 **`36/36/24` + JDK 21**。
2. **零打包器 ⇒ 不能 `import '@capacitor/x'` 裸模块名**（WebView 解析不到）。正解是原生注入的

3. **Android 15+ 强制 edge-to-edge** → 旧 `@capacitor/status-bar` 在 API 35+ 失效，
   inset 只能走 core 内建 `SystemBars { insetsHandling:'css' }`（注入 `--safe-area-inset-*`）。

#### 🕳️ 本轮抓到的两个「各自都对、拼起来错」接缝
- **安全区**：eng-package 配 `SystemBars` 注入 `--safe-area-inset-*`，eng-mobile 却用**裸 `env()`**
  → Android 上安全区会**静默失效**（那正是首发平台）。已改 `var(..., env(..., 0px))`。
- **M-08 横屏**：web 侧（`orientationchange`+竖屏提示）与原生侧（manifest `sensorLandscape`）
  分属两人，需两半都在才算完成。
**教训：跨模块接缝（原生注入 ↔ CSS 消费）无人负责，必须由主理人对接口做交叉核对。**

### G-9 详解：没有真正的「简单模式」
`DIFFICULTIES` 的三个参数**全部只作用于电脑对手**：
- `startMul` → `generator.ts:1093` 写的是 `isHuman ? 1 : diff.startMul` —— **玩家永远拿 1.0**
- `growthBonus` → `town.ts:328` 是 `aiBonus` —— 只加给 AI
- `aggression` → 只改 AI 出击门槛

而玩家能感受到的三个来源**全都不受难度影响**：开局资源写死 `{2500, 10, 10}`、**野怪完全不随难度缩放**（弱 20–28 狼 / 中 11–15 猪 / 强 10–13 食人魔）、移动力与周增长也不变。

> 且默认 `opponents: 0` —— **默认设置下难度选择器完全不生效**。
> 结论：现在没有「简单模式」，只有「电脑比较笨」模式。

⚠️ **但优先级已下调**：玩家澄清真正的痛点是**对手太弱**而非自己太难。所以 G-9 的处理顺序在 G-4 之后 —— 先让 AI 像个玩家，再谈难度分层。若届时仍需要，方案是给 `DifficultyDef` 增加**玩家侧字段**（`playerStartMul` / `monsterScale` / `playerMoveMul`），使每档同时调节双方。
