## 1. 改了什么

### 1.1 规则（决策 61）

`src/core/combat/siege.ts`

```ts
export function isInsideCity(h: Hex): boolean { return h.col > WALL_COL; }

export function blocksLine(siege, from, to) {
  if (!siege) return false;
  if (isInsideCity(from)) return false;   // 城里 → 城外：恒通
  if (!isInsideCity(to)) return false;    // 同侧连线：不判墙
  // 只有「城外 → 城内」才逐格找立着的结构
}
```

三条边界（都进了 [G1]）：

| 情形 | 结果 | 为什么 |
|---|---|---|
| 城外(9,5) → 城内(14,5) | **断线** | 攻方破墙前打不到守军 |
| 城内(14,5) → 城外(9,5) | **通** | 守方弓手在墙后能输出（决策 61 的全部要求） |
| 城外 → 主楼(13,5) | **断线** | 主楼在墙后：破墙前打不到，与 L2 的塔值不值有关 |
| 打城墙列本身(col=11) | **通** | 端点不算遮挡 ⇒ 攻方可以隔着一列砸墙/塔 |

### 1.2 连带改动

- `battle.ts::shootTargets` 的注释改成单向（行为由 `blocksLine` 决定，没有第二处判断）。
- `siege.ts` 文件头补上"为什么必须单向"：双向 + 塔数 0/1/3 ⇒ **L1 建墙反而更弱**。
- `probe:wallgate` 新增（`tools/probes/wallgate.mjs`），`package.json` 与 `GATES.md` 已登记。

**没有改**：塔数曲线（0/1/3）、墙的血量、护城河、`UNIT_SIEGE_RESIST`、AI、价格。

## 2. 读数（120 种子/格，守方 = 3 周产量 × 5 队，攻方带投石车）

### 2.1 破城门槛（攻方要带多少倍于守军的兵力才能 50% 拿下）

| 族 | 不建墙 | wall1 | wall2 | wall3 | L1 所需优势 | L3 所需优势 |
|---|---|---|---|---|---|---|
| 晨曦 | ×0.94 | ×0.94 | ×1.09 | ×1.50 | **+0%** | +60% |
| 赤焰 | ×1.04 | ×1.09 | ×1.30 | ×1.58 | **+5%** | +52% |
| 翠林 | ×0.92 | ×1.04 | ×1.13 | ×1.42 | **+13%** | +54% |
| 紫晶 | ×1.04 | ×1.25 | ×1.70 | ×1.92 | **+20%** | +85% |

读法：
- "不建墙 ×0.94" = 攻方带 0.94 倍守军兵力就五五开（**攻方先手 + 守方要分兵守城**，所以不到 1.0）。
- `wall1` 把门槛抬高 **0%~20%**，`wall2` 再抬 **10%~43%**，`wall3` 再抬 **21%~44%**。
- **四族差得很大**：紫晶的墙最值钱（+20% / +43% / +21%），晨曦最不值（+0%）。
  原因是守军的远程构成：晨曦只有 T2 一支弓手，紫晶的弓手多、且 T3/T4 更能拖回合。

### 2.2 守方胜率（攻方固定在"不建墙五五开"的兵力）

| 族 | L0 | L1 | L2 | L3 | L1 提升 |
|---|---|---|---|---|---|
| 晨曦 | 55.0% | 68.3% | 100% | 100% | **+13.3pt** |
| 赤焰 | 61.7% | 94.2% | 100% | 100% | **+32.5pt** |
| 翠林 | 49.2% | 100% | 100% | 100% | **+50.8pt** |
| 紫晶 | 55.0% | 100% | 100% | 100% | **+45.0pt** |

> 这一列有**天花板**：守方到 100% 就再量不出更多，所以定价用的是 §2.1 的门槛，不是这一列。
> 晨曦 +13pt 是全表最小的一个 —— 它就是双向挡线受害最重的那一族（§4）。

### 2.3 攻城回合数与护城河

| 族 | L1 中位回合 | L1 破墙回合（中位） | L2 中位回合 | L3 中位回合 | 护城河卡住（120 局） |
|---|---|---|---|---|---|
| 晨曦 | 13 | 6 | 10 | 8 | 180 |
| 赤焰 | 15 | 12 | 11 | 8 | 235 |
| 翠林 | 11 | 6 | 9 | 7 | 139 |
| 紫晶 | 13 | 8 | 12 | 7 | 18 |

- **没有一次打到 `MAX_ROUNDS=40`**：L1 最长中位 15 回合，L3 反而更短（7~8）——
  因为 3 座塔 + 守军弓手在破墙前就把攻方打光了，不是"磨 40 回合"。
- 护城河"进入即停"实测每局 **0.15~2.0 次**（紫晶只有 0.15）：它不是主要节拍，
  但确实在拖攻方的推进（赤焰 235/120 ≈ 2 次/局，与它慢速近战多有关）。
- **破墙回合 6~12**：投石车 + 崩塌连带 ≈ 2~3 轮开一个 3 格宽的口子，与设计注释一致。

## 3. 规格 §14.4 的 "+0~30pt"：为什么不能成立

原文（2026-10-28）：

> **验收闸**：同一份守军 + 同一个攻方种子批，**建 `wall1` 的守方胜率必须高于不建**。
> 允许 +0% ~ +30%，超出 30% 说明墙太强（那时调价格，不调规则）。

实测 **+13.3 / +32.5 / +50.8 / +45.0pt**。这条上限的问题不在数值，而在**它想用价格解决规则问题**：

1. 门槛是**在"已经建了墙"的局里**量的 —— 价格不改变这局的胜率，只改变有多少城会建墙。
2. 真正决定"+30pt 是否可接受"的是**破城门槛**（§2.1）：+0%~20% 的兵力优势，
   在五周一局的节奏里完全打得出来；而 L3 的 +52%~85% 才叫"要么别打，要么带两倍兵"。
3. 所以本批把上限**从退出码里拿出来**，只保留 `≥0`（决策 61 的全部要求），
   并用 [G5]/[G6] 的破城门槛（L1 ≤ +30%、L3 ≤ +100%）替代它。

**这需要主理人重新登记判据**（不是我们自行放宽）：

| 选项 | 内容 | 代价 |
|---|---|---|
| A（本批默认） | 上限作废，改判"破城门槛"：L1 ≤ +30%、L3 ≤ +100% | 需要改规格 §14.4 的一句话 |
| B | 保留 +30pt：必须给城墙加一条"守方射击减伤"（如穿墙射击 ×0.5） | 与决策 61 的"不受限"直接冲突，等于再开一条决策 |
| C | 保留 +30pt 但只在"攻方带投石车 + 攻方兵力 ≥ 守军 ×1.15"的子样本里判 | 判据变成"特定条件下"，失去"同一份守军"的简洁性 |

我方倾向 **A**：它把"墙太强"翻译成一个可执行的数字（要带多少兵），而 +30pt 翻译不出来。

> **已拍板（2026-11-13）：选 A。** 落地记录见 `m7-b3c-wall-ai-2026-11-13.md` §1.1 ——
> 规格 §14.4、决策 61 行、§3 验收清单三处已改；`wallgate.mjs` 里"只报不判"的 `⚠️` 已删除。
> 本节的三个选项表保留，作为"为什么当初写了 30pt"的留档。

做法：`cp -R dist /tmp/dist-bidir`，删掉编译产物里的两行方向判定（`isInsideCity(from/to)` 早退），

| 族 | L1 守方胜率（单向 → 双向） | 变化 |
|---|---|---|
| 晨曦 | 55.0% → **1.7%** | **−53.3pt** |
| 赤焰 | 56.7% → 98.3% | +41.6pt（双向时它的 T2 弓手本来就不多） |

| 紫晶 | 51.7% → 65.0% | +13.3pt |

> 这张表最有价值的一行是晨曦：**双向挡线让"建 wall1"把守方从 55% 打到 1.7%** ——

## 5. 墙价复核（B3b 的定价结论：**不改**）

### 5.1 每档买到了多少

用 §2.1 的**边际门槛**（相对不建墙那一档）：

| 墙档 | 边际所需优势（四族） | 中位 | 名义价 | 有效价（非金按市场买入价折） | 名义金 / 每 1% | 有效金 / 每 1% |
|---|---|---|---|---|---|---|
| `wall1` | +0 / +5 / +13 / +20% | **+9%** | 1,000 + 10 木 | **3,000** | 111 | 333 |
| `wall2` | +16 / +20 / +10 / +43% | **+18%** | 2,500 + 10 矿 | 4,500（边际 1,500） | 139 | 83（边际） |
| `wall3` | +44 / +27 / +31 / +21% | **+29%** | 5,000 + 10 木 15 矿 | 10,000（边际 5,500） | 172 | 190（边际） |

- **名义口径**：111 → 139 → 172，递增但只差 1.5×，三档没有断层 ⇒ 价格梯度成立。
- **有效口径**：`wall1` 的 10 木按市场价折 2,000 金，是它名义价的两倍 ⇒
  "每 1% 优势"反而最贵（333）。这不是价格表错了，是 **B5 记过的同一个问题**：
  名义金 ≠ 实付金（T5 的稀有资源同源）。⇒ 与 B5 的 T5 稀有价一起在 B5′ 处理，
  不在 B3b 单独动 `wall1`（它一改，W2 的现金流表和 G-E5 同时失效）。

### 5.2 为什么不改

1. 三档的名义梯度与实测边际价值同向且量级一致（111/139/172）。
2. `wall3` 的 5,000 对应 **+52%~85% 的破城门槛**，它是"要不要掀桌"的选择，不是前置税。
3. 真正的旧问题（`wall1` 只买 +2 防、0 塔）在单向挡线之后**已经解决**：
   它现在买到的是"守方弓手能输出 + 攻方 2~3 轮不能还手"，而不再是"双方都闭嘴"。

> 如果一定要动价，唯一有读数支撑的是 **`wall1` 的 10 木**（不是金币）：
> 它占有效价的 2/3，而木头在 W1–W2 是最紧的资源。降到 5 木会把 `wall1` 从"W2 建得起"
> 变成"W1 就能建"，那是**放量**而不是修正价格 —— 需要 F2 采纳率（V1）才能判，B3b 没有这个读数。

## 6. AI 的墙估值：低约 30 倍（**本批不改**）

`ai.ts::pickTarget` 现在这样折墙：

```ts
const need = garrisonStrength(town.garrison) + townDefenseBonus(town) * 24;
const odds = power / Math.max(120, need * 1.15);
if (odds < 0.85) continue;
```

`townDefenseBonus` = 各建筑的 `defenseBonus` **取最大** ⇒ L1 2 / L2 4 / L3 6 ⇒ 折成 **48 / 96 / 144 战力**。

实测（§2.1）：墙相当于守军的 **+9% / +18% / +29%**（中位）。用游戏内 `armyValue` 把 3 周驻军折成战力
（12,072~13,250），墙值就是 **0~2,675 / 2,064~8,408 / 6,268~11,211 战力**：

| 族 | L1 实测 / 模型 48 | L2 实测 / 模型 96 | L3 实测 / 模型 144 |
|---|---|---|---|
| 晨曦 | 0（+0%） | 2,064 / 96 = **21×** | 7,705 / 144 = **54×** |
| 赤焰 | 580 / 48 = **12×** | 3,018 / 96 = **31×** | 6,268 / 144 = **44×** |
| 翠林 | 1,691 / 48 = **35×** | 2,960 / 96 = **31×** | 7,048 / 144 = **49×** |
| 紫晶 | 2,675 / 48 = **56×** | 8,408 / 96 = **88×** | 11,211 / 144 = **78×** |

⇒ **低估 12~88 倍（L1 中位 35 倍）**。晨曦 L1 是 0× —— 它的墙只改变胜率、不抬高破城门槛，
所以按"所需兵力"折是 0；这正是"胜率"和"门槛"两个读数必须分开的理由。

**为什么本批不改**：改了 AI 的出击门槛，A1–A6 的读数就不再只归因于"规则变了"。
本批的 aiscale 是**同一批 AI + 只改规则**，所以 A1–A6 的变化可以干净地归因：

```
A2 丢城 0/8 · A3 D35 8/8 · A5 5 局全达标 · A6 8/8
A1: 首攻 D1（持平）· 战斗 40.9 vs 39.4（+3.8%）· D28 兵力 795 vs 795（0.0%）· 每金 0.552 vs 0.549（+0.5%）
```

⇒ **规则改动没有拖垮宏观节奏**（占领 26.4 vs 25.6、丢城 0/8），但也没有体现出墙的强度 ——
因为 AI 之间的攻城通常带着远大于 1.2 倍的兵力，墙的影响被稀释在 8 局 × 35 天里。

**下一批（B5′ 之后 / V1 之前）建议的常数**（可直接照抄，来源就是本批读数）：

```ts
/** 攻城所需的兵力优势（累计）：不建墙 1.00 / 木栅 1.09 / 石墙 1.24 / 堡垒 1.57（四族中位，B3b 实测）。 */
const WALL_NEED = [1.0, 1.09, 1.24, 1.57];
```

`need = garrisonStrength(town.garrison) * WALL_NEED[wallLevelOf(town)]`，删掉 `defenseBonus × 24`。
并按 §2.1 的族差（晨曦 +0%、紫晶 +20%）决定要不要**按防守方族**分档 —— 那需要一张 4×3 表，
不是 4 个数。

## 7. 仍欠（不记作通过）

- **F2 城防线采纳率 40%~70%**：需要真人试玩，B3b 只有"墙值多少"，没有"玩家会不会建"。
- **真人攻城手感**：AI 对 AI 的读数不能证明"玩家愿意带投石车"（§2.1 全部假设带投石车）。
- **不带投石车那一列没有定价**：实测 1.5~3 倍守军才打得下 L1，但那是"没造工坊"的代价，
  不是墙的价格 —— 如果 V1 玩家普遍不造工坊，这条会变成"攻城不可玩"。
- **紫晶 L3 的 +85%**：四族最高，已经贴着 [G6] 的 100% 上限。它是"设计上限"还是"该降塔伤"，
  要等玩家真的去打一次紫晶堡垒。
- **H3 原版对照**：单向挡线不是 H3 的规则（H3 是"隔墙可射、伤害 −50%"），本批**没有**做对照。
